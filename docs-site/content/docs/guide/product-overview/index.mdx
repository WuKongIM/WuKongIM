WuKongIM 是开源、自托管的实时消息基础设施，让应用能够在自己的基础设施上提供聊天、通知和多设备消息同步，并面向大规模连接与消息负载设计。

<Callout type="warn" title="v3 Beta">
  WuKongIM v3 仍处于 Beta 阶段，API、配置和持久化格式在稳定版前可能变化。生产使用前请阅读[升级与迁移](/zh/server/operations/upgrade-and-migration)和[生产检查清单](/zh/server/deployment/production-checklist)。
</Callout>

## 它解决什么问题

实时消息产品不只需要“把数据发出去”，还要管理大量长连接、频道内消息顺序、持久化、断线补偿和多设备状态。WuKongIM 把这些能力放进一个可自托管的集群，让应用团队专注于自己的产品和业务规则。

应用或业务服务把消息发到一个频道。这个频道可以代表个人、群组或业务自定义主题；WuKongIM 负责保存并同步消息，在线设备实时接收，离线或重连设备随后补齐。

## 职责边界

| 参与方 | 主要负责 |
| --- | --- |
| WuKongIM | 客户端连接、频道内消息顺序、持久化与复制、在线投递、离线与多设备同步 |
| 业务系统 | 账号、身份凭据、好友或群关系、产品权限、内容治理、移动推送和业务数据 |
| 客户端 SDK | 连接生命周期、本地消息状态、界面展示和用户交互 |

## 它不是什么

- 它不是带界面和完整业务流程的聊天应用。
- 它不替代业务后端，也不决定谁可以发送什么消息。
- 它不是为离线任务、全局事务队列或长期分析设计的通用消息队列。

## 是否适合你的产品

如果产品需要大量在线用户或设备、频道内有序消息、断线恢复、持久记录或多设备同步，WuKongIM 值得评估。聊天、通知和客服是最直接的场景；直播互动、IoT 和 AI 消息工作流也可以建立在同一套消息能力上。

如果需求只是低频后台任务、离线批处理或分析查询，任务队列、流处理或分析数据库通常更合适。

## 统一部署模型

每个 WuKongIM 部署都是集群。只有一个节点时，它是**单节点集群**，仍使用与多节点相同的集群路径；不存在绕过集群语义的独立模式。实际容量取决于硬件、存储、副本、频道分布和业务负载，必须使用真实场景验证。
