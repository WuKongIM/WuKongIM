## 1. Sign in as Alice

With Docker, open [Chat Demo](http://127.0.0.1:5001/demo/?lang=en). With the source launcher, choose Chat from the opened catalog. Enter this test identity:

| Field | Value |
| --- | --- |
| API base URL | Keep the automatic address; Docker defaults to `http://127.0.0.1:5001` |
| Account | `quickstart-alice` |
| Token | `alice-local-token` |

<TutorialScreenshot src="/tutorials/first-message/login-en.jpg" alt="Sign-in form: 1 local API URL, 2 test UID and token, 3 create demo credentials only for a new test account. Open the full-size image." width={420} height={420} marks={[{ x: 3, y: 14 }, { x: 3, y: 36 }, { x: 3, y: 79 }]}>
  **① Keep the local API URL. ② Enter the UID and token. ③ Select the demo-credentials checkbox for this new test account, then choose Log in.**
</TutorialScreenshot>

<Callout type="warn" title="Create credentials only for dedicated test accounts">
  The checkbox writes this UID's Web token. For existing accounts or migration acceptance, leave it off and enter the existing Web token. The default sign-in mode does not modify credentials.
</Callout>

## 2. Sign in as Bob and choose direct chat

Open the Demo in another browser profile, private window, or browser. Use `quickstart-bob` / `bob-local-token`, selecting demo credential creation only for this new test account.

Wait until **both headers show Connected**. In Alice's page, click **＋** above the chat list (or Start a chat), choose Direct chat, enter `quickstart-bob`, and click OK.

## 3. Exchange messages

1. Alice sends `hello from alice`. Wait for the sending indicator to clear; in Bob's page, open a direct chat with `quickstart-alice` and confirm the same text appears.
2. Bob replies with `hello from bob`. Confirm Alice receives it.

## Success checklist

- Both UIDs are connected.
- Alice's send succeeds and Bob sees the original text.
- Bob's reply also appears on Alice's page.

<details>
<summary>Troubleshoot by symptom</summary>

| Symptom | Check first |
| --- | --- |
| Disconnected | `/readyz`, WebSocket port `5200`, and `docker logs --tail 100 wukongim` |
| Recipient sees no message | Both peers online, exact recipient UID, and direct-chat selection |
| Sessions replace each other | Different UIDs and independent browser sessions |

For Linux packages, check logs with `sudo journalctl -u wukongim -n 100 --no-pager`.

</details>

<details>
<summary>What does this verify?</summary>

The path covers demo token registration, exact-match CONNECT token checks, route discovery, WebSocket connection, channel message commit, and online delivery. Send success and recipient delivery are separate results; check both.

It verifies the development path. Production still needs account authentication, token expiry and replay policy, TLS, capacity, recovery, and durability validation. See [Chat Demo boundaries](/en/guide/quick-start/chat-demo).

</details>
