Conversation 是服务端为某个 UID 临时构建的视图。WuKongIM 不持久化
conversation 行，也不会在发送消息时更新每一个接收者。Channel 日志持有消息与
sequence 顺序；UID-owned membership 持有目录发现和个人可见性状态。

## 持久状态

普通频道使用 `user_channel_membership`：

| 字段 | 含义 |
| --- | --- |
| `join_seq` | 当前入群周期内第一条可见 sequence |
| `read_seq` | 只由清除/设置未读命令单调推进的红点 floor |
| `deleted_to_seq` | 单调隐藏边界 |
| `activated_at` | 用户显式进入频道后用于目录同步的优先级 |
| tombstone 字段 | 成员移除证据 |
| `source_version` | 拒绝陈旧订阅者派生写的 fence |

`activated_at` 不是最后消息时间。SEND、接收、在线投递和消息拉取都不更新它。
置顶和最终 UI 排序由客户端决定。

CMD 发现使用独立的 `user_cmd_channel_membership`，字段包含
`start_seq`、`ack_seq` 和 tombstone。CMD/SyncOnce 消息使用独立命令
Channel 日志，不占用普通 sequence，也不改变普通红点。

## 目录同步

```text
按 (activated_at desc, channel_id, channel_type) 分页扫描 membership
  -> tombstone 直接返回 delete
  -> live Channel 按 exact Channel Leader 分组
  -> 批量读取 committed head、retention floor、最近展示消息、
     当前 UID 最后一条已提交普通 SEND
  -> 返回 conversations + deletes + unresolved + cursor + done
```

limit 限制扫描的 membership 候选数，而不是返回的 conversation 数。因此空页也可能
尚未完成；只有 `done=true` 表示一次遍历结束。cursor 是不透明的，扫描采用最终一致
语义。客户端按 Channel key 去重，先同步活跃页，再后台补齐不活跃页，并独立重试
`unresolved`。

## 红点与可见性

对一条有效 membership：

```text
visibility_floor = max(join_seq - 1, deleted_to_seq, retention_through_seq)
effective_read   = max(visibility_floor, read_seq, current_user_last_send_seq)
unread           = max(0, last_committed_seq - effective_read)
```

发送者 sequence 来自与普通消息同批原子写入的 Channel-local 索引。这样 SEND
无需写 membership，同时用户自己的消息不会产生自己的红点。

未激活且没有入群后消息的 membership 不返回；显式激活的空频道可以返回且没有
last message。隐藏会推进 `deleted_to_seq` 并清零 activation，但不会退出频道；
更高 sequence 的新消息可以让它再次可见。真正移除会写 tombstone，重新加入会建立
新的 join 边界。

## 消息拉取

普通消息拉取要求 membership 有效，不再次查询 subscriber。服务端把客户端 cursor
钳制到 join、hide 和 retention 边界。批量拉取会先验证全部 membership，再执行一次
按 Leader 分组的 Channel 批量读取。目录 cursor 与各 Channel 的消息 cursor 相互独立。

<Callout type="info" title="SEND 成本">
  普通 SEND 只追加 Channel 消息和 sender index，再执行在线投递；它不写接收者
  membership，也不写 conversation 行，因此持久写成本不随群成员数增长。
</Callout>
