## 业务与连接

| 概念 | 含义 |
| --- | --- |
| 用户（User） | 由业务系统定义的稳定身份，使用 UID 标识 |
| 设备（Device） | 用户的一类客户端身份，由设备标记和设备级别区分 |
| 连接（Connection） | 一个客户端到某个节点的在线传输会话 |
| 频道（Channel） | 消息路由、顺序和存储的核心单位，由频道 ID 与频道类型共同标识 |
| 消息（Message） | 发布到频道的有序记录，包含客户端编号、内容和消息设置 |
| 会话（Conversation） | 面向用户的最近交互视图，包含最近消息、已读位置和未读状态 |

一个用户可以有多个设备，每个设备可以经历多次连接。不要把连接 ID 当作业务用户身份，也不要假设用户只会在一个节点上在线。

## 集群与存储

| 概念 | 含义 |
| --- | --- |
| 集群（Cluster） | 所有 WuKongIM 部署的统一运行模型；一个节点时称为单节点集群 |
| 节点（Node） | 运行接入、运行时、存储和节点间通信能力的进程实例 |
| Controller | 维护集群成员、节点健康、Hash Slot 表、物理 Slot 分配和运维任务的控制面 |
| Hash Slot | 把用户和频道键稳定路由到逻辑 Slot 的固定分区；默认数量是 256 |
| Slot | 持有用户、频道、成员、会话等元数据的分布式 Raft 分组 |
| Channel | 维护一个频道的有序消息日志、Leader/Replica 和提交进度 |

## 一条消息经过什么

1. 客户端用 UID、设备信息和 Token 建立连接。
2. 发送请求指定频道 ID、频道类型和客户端消息编号。
3. Hash Slot 与集群元数据把请求路由到正确的 Channel Leader。
4. Channel 按顺序追加消息，并等待持久化提交。
5. 提交成功后，发送者得到确认；在线接收者获得投递。
6. 离线或重连设备从已提交位置同步缺失消息，会话状态随之更新。

<Callout type="info" title="顺序边界">
  WuKongIM 的消息顺序以频道为核心理解。不同频道之间不应假设存在全局顺序。
</Callout>

## 设计时应保留的边界

- 业务账号和权限属于业务服务，连接和消息传输属于 WuKongIM。
- 消息提交与在线投递是不同阶段；接收者暂时离线不应改变已提交消息。
- 单节点集群与多节点集群使用同一套路径，接入代码不应为单节点集群增加旁路。
- 面向十万成员群、大量在线用户和高消息速率时，要同时考虑 Fan-out、队列边界、背压、内存和存储延迟。
