title: Conversations
description: Understand the membership-backed directory, server-built badges, pagination, visibility floors, and CMD isolation.

A Conversation is a transient server-built view for one UID. WuKongIM does not
persist a conversation row and does not update every recipient when a message
is sent. The Channel log owns messages and sequence order; UID-owned membership
owns discovery and personal visibility state.

## Durable state

Ordinary channels use `user_channel_membership`:

| Field | Meaning |
| --- | --- |
| `join_seq` | First sequence visible in the current membership period |
| `read_seq` | Monotonic badge floor changed only by clear/set-unread |
| `deleted_to_seq` | Monotonic hide floor |
| `activated_at` | Explicit navigation priority for directory sync |
| tombstone fields | Removal evidence |
| `source_version` | Fence against stale subscriber-derived writes |

`activated_at` is not last-message time. SEND, receive, online delivery, and
message pull do not update it. The client owns pinning and final UI order.

CMD discovery uses a separate `user_cmd_channel_membership` table with
`start_seq`, `ack_seq`, and tombstone state. CMD/SyncOnce messages use a
separate command Channel log, so they never consume ordinary sequence space or
change ordinary badges.

## Directory synchronization

```text
page memberships by (activated_at desc, channel_id, channel_type)
  -> emit tombstones as deletes
  -> group live channels by exact Channel Leader
  -> batch-read committed head, retention floor, last display message,
     and this UID's latest committed ordinary SEND
  -> return conversations + deletes + unresolved + cursor + done
```

The page limit bounds membership candidates scanned, not conversations
returned. A page can therefore contain no conversations while the pass is still
incomplete; only `done=true` completes a pass. The cursor is opaque and the
scan is eventually consistent. Clients deduplicate by Channel key, synchronize
active pages first, complete inactive pages in the background, and retry
`unresolved` keys separately.

## Badge and visibility

For a live membership:

```text
visibility_floor = max(join_seq - 1, deleted_to_seq, retention_through_seq)
effective_read   = max(visibility_floor, read_seq, current_user_last_send_seq)
unread           = max(0, last_committed_seq - effective_read)
```

The sender sequence comes from a Channel-local index written atomically with
the ordinary message. It avoids a membership write on SEND while preventing
the user's own sent message from creating a badge.

An inactive empty membership is omitted. An explicitly activated empty Channel
may appear without a last message. Hiding advances `deleted_to_seq` and clears
activation without leaving the Channel; a later message above the floor can
make it visible again. Remove writes a tombstone, and a true rejoin establishes
a new join boundary.

## Message pull

Ordinary message pull requires a live membership and does not recheck the
subscriber table. The server clamps the requested cursor to the join, hide, and
retention boundaries. Batch pull validates every membership before issuing one
Leader-grouped Channel read batch. Directory cursors and per-Channel message
cursors are independent.

<Callout type="info" title="SEND cost">
  Ordinary SEND appends the Channel message and sender index, then performs
  online delivery. It writes no recipient membership or conversation rows, so
  durable write cost does not grow with group membership.
</Callout>
