API pages describe contracts for the current build. An unchanged URL does not make different server, SDK, or contract versions automatically compatible.

The snapshot's verification status covers only this basic integration flow:

| Operation | Verified behavior |
| --- | --- |
| `POST /user/token` | Create a development identity |
| `GET /route` | Discover WebSocket ingress |
| `POST /channel/messagesync` | Recover committed messages after reconnect |

Channel/Conversation management and message sending have separate OpenAPI contracts and contract checks, but are outside the end-to-end status above. The client-protocol pages are source-aligned and do not extend that status.

## Version rules

- Revalidate the application flow after changing the server, SDK, or contract.
- Treat an unverified combination as unknown, not compatible by default.
- Use only fields and operations listed on the current pages and in the OpenAPI contracts.

Compatibility does not make an API safe for public exposure. Keep Product HTTP behind a trusted network or authenticated proxy. See [Product HTTP API](/en/api/product-http) for the published scope.
