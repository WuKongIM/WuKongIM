本区域发布面向应用集成开发者的可执行合同。Product HTTP 仍只承诺黄金样例需要的 Beta 子集；Phase 13 另补充了与当前 Go 权威定义校准的 Channel Type、Device Flag / Level 和 Message Flags。

## 目标与完成标准

开发者应能从受信后端创建开发身份、发现 Gateway 地址、恢复离线消息，并准确处理 HTTP、协议结果与共享 Wire 值；不会把源码中其他路由或枚举自动当作已发布平台能力。

<Callout type="warn" title="不是完整 v3 API">
  当前发布的是 Beta 黄金路径子集。仓库旧 OpenAPI 仍包含 v2 内容，完整 OpenAPI、客户端协议、Webhook、运维 API 和其他领域参考仍在规划中。
</Callout>

## 规范呈现边界

- 三个已发布 Product HTTP operation 由同一份 OpenAPI 3.1 合同生成 Fumadocs 请求、响应、Schema、示例和类型参考；
- TCP/WKProto 生命周期、JSON-RPC 与共享 Wire 字典不是 HTTP operation，继续采用协议专用正文和源码校准表，不能伪造为 OpenAPI path。

## 兼容目标

服务端 revision、SDK、Node.js、Chromium 与合同摘要记录在[API 兼容性](/zh/api/compatibility)和 `/compatibility.json`。URL 保持无版本路径，但快照不承诺任意 revision 都兼容。

## 前置条件

- Product HTTP 只对 localhost BFF 或受信业务后端开放；
- 默认 Gateway stored-token 校验缺口已经被明确接受为本地开发限制；
- 单节点集群通过 `/readyz`；
- 调用方按端点解析兼容响应。

## 预期结果

Golden BFF 是三个 HTTP 入口的唯一浏览器侧边界；实时消息通过 SDK；错误分类保留 HTTP 阶段与 CONNACK/SENDACK 阶段；共享协议字典与 Go 权威值自动校准。

## 失败诊断

- **需要的接口不在 Product HTTP 子集中**：它仍未发布；不要根据旧 OpenAPI 或源码位置推断支持。
- **浏览器直接调用服务端**：转为同源 BFF 调用并收紧网络。
- **字段与文档不一致**：让共享合同校验失败，统一修复运行时、样例和双语页面。

## 安全与责任边界

Product HTTP 没有通用业务鉴权中间件；默认 Gateway 没有 stored-token CONNECT 校验。Phase 12 不把本地开发闭环描述为生产安全方案。
