Product HTTP 当前发布两份彼此独立、均非穷举的 OpenAPI 3.1 合同：Phase 12 的三入口黄金路径合同，以及 Phase 16 的 16 入口受信管理合同。页面“已发布”只表示其**声明子集**完整且经过合同校验，不表示仓库中的全部 HTTP 路由已经成为公共 API。

黄金路径的操作白名单与 receipt tuple 继续固定。Phase 16 只把共享恢复维护 `503` Schema 修正为当前运行时的 `{error,message}` 响应；该修正不会扩大 receipt 场景。

## 目标与完成标准

完成后，你应能为已发布操作指出方法、路径、信任级别、请求、响应和失败处理，区分场景 receipt 与源码校准证据，并确保浏览器或移动端没有直接调用 Product HTTP。

## 两份合同的证据边界

## 前置条件

- Product HTTP 位于可信网络或已鉴权代理之后；
- 业务后端验证服务身份、租户、UID、Channel 与请求意图；
- 单节点集群或多节点集群的 `/readyz` 成功；
- 调用方理解[通用约定](/zh/api/conventions)和[认证边界](/zh/api/authentication)。

## 典型调用流

```text
黄金路径
  POST /user/token -> GET /route -> SDK CONNECT
  SDK reconnect -> POST /channel/messagesync

受信管理
  POST /channel -> subscriber / allowlist / denylist mutations
  POST /conversation/list -> retry unresolved -> continue until done=true
  clearUnread / setUnread / delete / activate
```

消息发送本身仍走 JavaScript SDK。`/message/send`、用户退出、在线状态、批量同步、弱校验 Channel 路由、legacy `/conversation/sync` 和其他兼容入口不属于本次发布承诺。

## 失败诊断

- **接口不在任一合同中**：它仍未发布；不要从源码存在或旧 `resources/api/openapi.json` 推断公共支持。
- **浏览器出现 Product HTTP 请求**：这是架构违规，应改为调用同源 BFF 或业务后端。
- **管理操作返回 400**：按 HTTP 状态处理，并仅记录脱敏后的 `msg`；精确错误文本不是稳定机器合同。
- **维护栅栏返回 503**：响应使用 `{error,message}`；有界退避并观察 `/readyz`。
- **会话空页提前结束**：只以 `done=true` 为完成条件，并原样传递 `next_cursor`。

## 安全与责任边界

Product HTTP 没有通用业务鉴权中间件，`security: []` 只是当前事实而非匿名访问授权。必须限制网络可达性，并由业务后端实现认证、授权、限流、审计与输入上限。Golden BFF 只是本地开发工具。
