## List synchronization

1. Start `/conversation/list` with an empty `cursor`.
2. Apply `conversations`, remove `deletes`, and send `unresolved` to `/conversation/retry`.
3. While `done=false`, return `next_cursor` unchanged even when the page is empty.
4. Save `coverage` only after `done=true`.
5. When `reset_required=true`, clear the local Conversation projection and resynchronize.

## Key points

- `read_seq` is a monotonic unread floor, not a message cursor or read receipt.
- `setUnread` can only reduce unread.
- `delete` hides the current projection; it deletes neither the Channel nor membership.
- `message_idstr` avoids JavaScript integer precision loss.

Legacy `POST /conversation/sync` is outside this contract. New integrations use `/conversation/list` and `/conversation/retry`. See [Error Responses](/en/api/product-http/errors) for shared failures.
