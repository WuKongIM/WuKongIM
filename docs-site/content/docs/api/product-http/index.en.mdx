Product HTTP now publishes two independent, deliberately non-exhaustive OpenAPI 3.1 contracts: the Phase 12 three-entry golden path and the Phase 16 16-entry trusted-management subset. “Published” means only that the **declared subset** is complete and contract-checked; it does not promote every repository HTTP route to a public API.

The golden operation whitelist and receipt tuple remain fixed. Phase 16 only corrects the shared restore-maintenance `503` schema to the current runtime `{error,message}` body; that correction does not expand the receipted scenario.

## Goal and completion criteria

You should identify method, path, trust level, request, response, and failure handling for each published operation; distinguish scenario receipts from source-calibration evidence; and prove that browsers and mobile clients call none of Product HTTP directly.

## Prerequisites

- Product HTTP is behind a trusted network or authenticated proxy;
- the product backend validates service identity, tenant, UID, Channel, and request intent;
- `/readyz` succeeds for the single-node or multi-node cluster;
- the caller understands [Conventions](/en/api/conventions) and the [authentication boundary](/en/api/authentication).

## Typical call flows

```text
golden path
  POST /user/token -> GET /route -> SDK CONNECT
  SDK reconnect -> POST /channel/messagesync

trusted management
  POST /channel -> subscriber / allowlist / denylist mutations
  POST /conversation/list -> retry unresolved -> continue until done=true
  clearUnread / setUnread / delete / activate
```

Message sending still uses the JavaScript SDK. `/message/send`, device quit, online status, batch sync, weakly validated Channel routes, legacy `/conversation/sync`, and other compatibility entries remain outside this publication promise.

## Troubleshooting

- **An endpoint is absent from both contracts:** it remains unpublished; do not infer public support from source existence or the old `resources/api/openapi.json`.
- **A browser issues a Product HTTP request:** this violates the architecture; replace it with a same-origin BFF or product-backend call.
- **A management operation returns 400:** branch on HTTP status and retain only a redacted `msg`; exact error text is not a stable machine contract.
- **The maintenance fence returns 503:** its response uses `{error,message}`; back off within a bound and observe `/readyz`.
- **Conversation sync stops on an empty page:** completion requires `done=true`; echo `next_cursor` unchanged.

## Security and responsibility boundary

Product HTTP has no general business-authentication middleware. `security: []` records that fact rather than authorizing anonymous access. Restrict network reachability and implement authentication, authorization, limits, audit, and input bounds in the product backend. The golden BFF remains a local development tool.
