选择 SDK 时，先看你的运行平台和真正需要的能力，再看仓库名称。WuKongIM 的旧版文档把客户端分为 EasySDK 与 WuKongIMSDK 两组；这里保留这组线索帮助你发现源码，但不再用“应用是不是 IM”作为唯一判断标准。

<Callout type="warn" title="源码存在不等于本站已验证">
  官方仓库、本站教程和可执行兼容 receipt 是三件事。Android `1.5.5` 的源码与 JitPack AAR 已校对，iOS `1.1.1` 的源码与公开头文件已校对，两套教程都没有本站运行 receipt；当前只有使用 `wukongimjssdk@1.3.5` 的 JavaScript/Web 黄金路径具有本站的可执行验证入口。
</Callout>

## 先写需求，不先选系列

系列名称只用于找到候选仓库，不能代表某个仓库或版本具备哪些能力。按下面四项准备选型信息，再到平台表中逐个检查候选仓库：

| 先回答的问题 | 需要核对的内容 |
| --- | --- |
| 应用运行在哪里？ | 浏览器、原生系统或跨端框架，以及最低系统和构建工具版本 |
| 第一版必须完成什么？ | 连接、消息收发、会话、未读、离线恢复、推送、多设备和自定义消息中的必选项 |
| 哪些能力由产品自己维护？ | 账号、联系人、权限、业务数据、推送设备、回执和 UI 状态 |
| 怎样证明可以采用？ | 候选仓库的精确 tag、安装产物、自带示例，以及你的最小验收结果 |

对每个候选仓库分别查看准备采用 tag 的 README、API、示例和变更记录，再做决定。若目标是浏览器并希望先运行本站已有样例，可以使用下面标记为已发布的 WuKongIMJSSDK 路径；这只是当前教程入口，不是对 SDK 系列的排名。

## 用六个问题完成选择

1. **运行在哪里？** 写清浏览器、原生系统、跨端框架及最低系统版本。
2. **第一版必须有什么？** 列出单聊、群聊、自定义消息、会话、未读、离线恢复、推送和多设备中的必选项。
3. **哪些状态由产品维护？** 明确账号、联系人、权限、推送设备、业务回执和 UI 状态的负责人。
4. **准备锁定哪个版本？** 同时记录服务端 revision、SDK tag 或包版本、运行时和构建工具。
5. **最小闭环怎么验收？** 至少验证连接、发送确认、在线接收、断线重连、离线恢复和去重。
6. **上线还缺什么？** 单独评审 Token 校验、TLS、网络隔离、限流、审计、容量、升级和回滚。

如果某个候选仓库无法回答其中一项，就先做一个小型验证项目，不要直接把选择扩大到生产应用。

## 选定后按这条路径接入

### EasySDK

1. 先看 [JSON-RPC 支持矩阵](/zh/api/client-protocols/json-rpc)；当前 Product Gateway 不支持 CONNECT，因此不要进入接入实施；
2. 可以查看上方官方仓库和固定 tag 做源码评估，但只有运行时补齐鉴权、请求关联与 Bridge 映射，并通过端到端测试后，本站才会发布接入教程。

### JavaScript / Web

1. 按[安装与配置](/zh/sdk/javascript/installation)运行已锁定的 TypeScript 样例；
2. 按[快速接入](/zh/sdk/javascript/quickstart)连接 Alice 与 Bob，完成在线消息和离线恢复；
3. 用[公共指南](/zh/sdk/common-guides)补齐身份、连接、会话、推送和多设备设计；
4. 对照[能力边界](/zh/sdk/javascript/platform-capabilities)和[上线验收](/zh/guide/integration/acceptance)关闭发布门禁。

### iOS

1. 按[iOS 安装与配置](/zh/sdk/ios/installation)精确锁定 CocoaPods `1.1.1`，先核对部署目标与模拟器架构限制；
2. 按[iOS 快速接入](/zh/sdk/ios/quickstart)在两个独立进程中完成 Alice/Bob 连接、发送确认与在线接收；
3. 在自己的 Xcode、设备和服务端 revision 上保存运行证据，不把源码/头文件校对当作本站 receipt；
4. 在发布前关闭原始 TCP、TLS、RECV Payload 日志和生产鉴权阻断，再单独验证离线、会话、推送与后台能力。

### Android

1. 按[Android 安装与配置](/zh/sdk/android/installation)精确锁定 JitPack `1.5.5`、revision `662a559a50d181540a0448454beb57e939b0c50e` 和 AAR 校验和；
2. 按[Android 快速接入](/zh/sdk/android/quickstart)在两个独立进程中完成会话同步门禁、本地入库、SENDACK 与在线接收；
3. 在自己的 AGP、JDK、设备、系统和服务端 revision 上保存运行 receipt，不把源码/AAR 校对当作 Android 执行证据；
4. 发布前关闭原始 TCP/TLS、SharedPreferences Token、UID SQLCipher key 和 Payload 日志阻断，再单独验证离线、推送、后台与多设备。

### 其他 WuKongIMSDK 平台

1. 从上面的官方仓库选择一个精确 tag，并先运行仓库自带示例；
2. 把[身份与 Token](/zh/sdk/common-guides/identity-and-token)、[初始化与连接](/zh/sdk/common-guides/initialization-and-connection)和[消息收发](/zh/sdk/common-guides/messaging)映射到该版本 API；
3. 自己保留连接、发送确认、在线接收和离线恢复的执行证据；
4. 在本站发布平台教程前，以仓库和你的验证结果作为平台 API 的事实源。

## 常见误区

- **按“聊天应用 / 非聊天应用”直接二选一**：同类应用也可能有完全不同的本地数据、会话和推送需求。
- **仓库能打开就认为已兼容**：还需要核对 tag、包版本、服务端版本和目标系统。
- **先复制 API，再设计身份**：UID、Token 和权限必须来自受信业务后端，不能由客户端自行授予。
- **浏览器直接调用 Product HTTP**：Web 客户端只能拿到连接所需材料，管理接口应留在受信后端。
