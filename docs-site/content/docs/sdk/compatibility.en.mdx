This page records the combination targeted by the **JavaScript/Web golden path**. Only the shared receipt status can attest that the exact build tuple completed the scenario. This is not a compatibility matrix for every client SDK, and it does not imply that the current source has a final v3 release.

<Callout type="info" title="EasySDK tutorials are outside this snapshot">
  The iOS, Android, Flutter, and Web pages under [WuKongEasySDK](/en/sdk/easy) are aligned to official release-tag source, but they are not recorded by this receipt and have no site runtime verification. Publishing a tutorial does not expand the compatibility snapshot.
</Callout>

## Goal and completion criteria

Before integration, confirm that your server revision, `wukongimjssdk`, Node.js, and browser belong to one compatibility snapshot. When finished, you should be able to classify the combination as verified, unverified, or drifted instead of guessing from `latest`.

## Prerequisites

- Access to the current build's `/compatibility.json`;
- ability to check out the server revision recorded by the manifest;
- the sample's committed npm lockfile instead of rolling dependencies;
- a policy that marks only combinations carrying complete smoke evidence as verified.

## Use the snapshot

1. Read the server revision and exact SDK version from `compatibility.json`.
2. Check out that server source instead of a moving `main` or SDK `latest`.
3. Run `npm ci` in the golden-sample directory and preserve its lockfile.
4. Run the sample checks, then complete the real single-node cluster smoke scenario in the [Quickstart](/en/sdk/javascript/quickstart).
5. After any component changes, rerun the entire scenario and let the integration gate emit a new exact receipt; do not mark the combination manually.

## Expected result

The same snapshot should repeatedly complete connection, persistent two-way messages between Alice and Bob, Bob's disconnect, reconnect, and offline synchronization. This page promises only that narrow scenario—not the complete SDK API, background behavior, push, custom messages, or every browser.

## Troubleshooting

- **The SDK is not `1.3.5`:** remove the manual upgrade and rerun `npm ci`.
- **The server revision differs:** treat the combination as unverified; a successful CONNECT does not prove every behavior is compatible.
- **Only one browser fails:** record the exact engine and version. Chromium evidence cannot be projected onto Firefox or WebKit/Safari.
- **The JSON and page disagree:** this is a publication error that compatibility validation should reject; do not choose one manually.

## Security and responsibility boundary

Compatibility verification does not complete production authentication. The default v3 Beta Gateway does not automatically validate CONNECT against stored tokens, and Product HTTP has no general business-authentication middleware. Matching versions do not replace product identity, TLS, access-control, capacity, or failure-recovery validation.
