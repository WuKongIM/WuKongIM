## 1. 冻结升级前基线

在独立分支记录工具链和已解析依赖：

```bash
flutter --version
dart --version
flutter pub deps --style=compact
git status --short
```

保存当前 `pubspec.yaml`、`pubspec.lock`、Release 产物摘要、每个目标平台的签名配置，以及至少一份真实 Alice/Bob 场景。基线要分别记录连接、同步完成、本地插入、SENDACK、在线接收、离线恢复和断线重连；“应用能启动”不是消息兼容证据。

搜索全部调用点和 package 子路径：

```bash
rg -n "wukongimfluttersdk|WKIM\.shared|Options|sendMessage|sendWithOption|addOn|remove|clientMsgNO|clientSeq" lib test integration_test
```

按项目实际目录调整命令。特别标记：

- `lib/main.dart` 不是 SDK barrel，所有 `package:wukongimfluttersdk/...` 子路径都可能是升级编译点；
- 无 remove API 的 provider/插入回调由谁拥有；
- listener key 是否稳定且成对移除；
- 是否依赖可变 `WKMsg` / `WKUIConversationMsg` 的惰性字段；
- 是否把 `sendMessage` 或本地 Future 返回误判为 SENDACK。

## 2. 精确安装并锁定归档

在应用 `pubspec.yaml` 中写精确版本：

```yaml
dependencies:
  wukongimfluttersdk: 1.7.9
```

不要写 `^1.7.9`、`any`、Git `master` 或仓库旧 `v1.0.0` tag。重新解析并提交 lockfile：

```bash
flutter pub get
git diff -- pubspec.yaml pubspec.lock
flutter pub get --enforce-lockfile
```

确认 `pubspec.lock` 中 hosted content hash 是：

```text
b6191a86cd1e4caacaa4652e95709310eb1493f159fee65e1dd53c2a3ff9e80a
```

CI 必须运行 `flutter pub get --enforce-lockfile`。直接依赖带有多个 caret 约束；只有提交应用的完整 lockfile，才能固定 `sqflite`、`shared_preferences`、`connectivity_plus`、`dio`、加密和其他传递包的真实组合。

## 3. 审计精确的 `1.7.7 → 1.7.9` 源码区间

本次迁移的起点固定为 `1.7.7` 源码 revision [`d99990f41ecb31166af82b9d20c121f33ff8385d`](https://github.com/WuKongIM/WuKongIMFlutterSDK/tree/d99990f41ecb31166af82b9d20c121f33ff8385d)，终点是上文的 `1.7.9` 匹配 revision。不要用分支头或只比较版本字符串；以 [`d99990f...de102427` 的精确 diff](https://github.com/WuKongIM/WuKongIMFlutterSDK/compare/d99990f41ecb31166af82b9d20c121f33ff8385d...de1024276523119e38305c49a3a873caae4d5c59) 为迁移边界。

固定 [`CHANGELOG.md`](https://github.com/WuKongIM/WuKongIMFlutterSDK/blob/de1024276523119e38305c49a3a873caae4d5c59/CHANGELOG.md) 记录 `1.7.8` 新增频道最大 reaction sequence 查询，`1.7.9` 补全 `queryAll` 会话结果中的最后消息、消息扩展和发送者资料。精确源码 diff 还证明：

- `WKMsg` 新增异步 `getFromAsync()` 和 `getMemberOfFromAsync()`，分别按需读取发送者频道与群成员；
- reaction 列表写入改为 `await ReactionDB.shared.insertOrUpdateReactionList(...)`，随后才查询并刷新消息；
- `WKMessageManager` 新增 `getMaxReactionSeqWithChannel(...)`；
- `queryAll` 会批量读取 `clientMsgNO`、message extra 和发送者频道，再填入 `WKUIConversationMsg`。

因此从 `1.7.7` 升级至少要回归：

- 会话列表首次加载与大量会话的延迟、内存和 SQL 参数分批；
- 最后一条消息缺失、已删除或未知正文时的 UI；
- 编辑、撤回、置顶等 message extra 是否与最后消息匹配；
- 单聊/群聊发送者资料、`getFromAsync()` / `getMemberOfFromAsync()` 的缓存命中、缺失、失败和头像刷新；
- reaction 写入完成后再刷新消息的顺序、最大 sequence、重复同步和同用户唯一性；
- 数据变化后 `getAll()` / 底层 `queryAll` 的刷新时序。

如果起始版本更旧，还要按真实起点逐段审计，而不是把下表当成完整兼容保证：

## 4. 把数据库 migration 当作不可逆边界

`WKDBHelper` 为每个 UID 打开 `wk_<uid>.db`，再根据 `SharedPreferences` 中的 `wk_max_sql_version_<uid>` 顺序执行 archive 内 SQL。固定 archive 没有反向 migration，也没有旧版本读取新 schema 的**降级契约**。

更具体地说，固定 [`assets/202604271625.sql`](https://github.com/WuKongIM/WuKongIMFlutterSDK/blob/de1024276523119e38305c49a3a873caae4d5c59/assets/202604271625.sql) 会删除 `message_reaction` 的全部行，再重建包含 message、UID、channel 的唯一索引。任何会跨过这条 migration 的升级都要把 reaction 重同步视为产品动作，不能假定本地 reaction 保留。

升级前：

1. 对每个测试 UID 保存脱敏的数据库与关联 `SharedPreferences` 快照；
2. 在副本上运行目标 SDK，检查消息、会话、未读、频道、成员、提醒、reaction 和搜索；
3. 验证 migration 失败、应用被杀和磁盘不足；当前 helper 没有公开事务化降级方案；
4. 回滚演练恢复**升级前数据库快照**或使用隔离的新安装，不让旧 SDK 盲目打开已迁移数据。

## 6. 重新验收生命周期与安全

- 接受序列为 `fail(null) → connecting → success → syncMsg → syncCompleted`，没有额外的最终 `success`；
- timeout、非空 CONNACK 失败、kick、`noNetwork`、二次 `connecting`、provider 失败和 SENDACK 超时都终止本轮；
- Alice 本地插入、终止 SENDACK 与 Bob 在线接收分开记录；
- 原始 `Socket.connect`、明文 sqflite/SharedPreferences、Payload 日志、不可取消重连与 `_sendingMsgMap` 残留仍是生产阻断项；
- 成功、失败、超时与 UID 切换后都执行进程重启，直到 SDK 提供并验证安全的同进程重置合同。

Android、iOS、macOS 的权限、后台、通知、存储、签名和设备行为要各自产生 receipt。Windows、Linux 和 Web 不在当前 package/证据范围。

## 7. 灰度与回滚

把版本、archive SHA、`pubspec.lock` digest、Flutter/Dart/native 工具链、设备/系统、服务端 revision 与 Alice/Bob 结果绑定成一个发布单元。灰度前必须在发布记录中填写基线、**量化观察阈值**、观察窗口和 owner；留空就不允许开始 cohort：

| 信号 | 必填阈值与停止条件 |
| --- | --- |
| 连接接受率、同步耗时、终止 SENDACK 成功率/延迟 | 写入旧版本基线、允许的最大回退/增长和最小样本；任一越界立即停止扩量 |
| 重复、丢失、顺序与 reaction/extra 错配 | 任何已确认的持久消息丢失、重复投递或错误关联都停止 rollout 并保留证据 |
| `queryAll` 完整性与延迟 | 写入大会话集的最小完整率和最大 p95/p99；last message、extra 或 sender 缺失/错配即停止 |
| migration、数据库与回滚 | 任一不可打开/损坏数据库、migration 失败或无法恢复升级前快照立即停止 |
| crash/ANR 与日志 | 写入允许的 crash/ANR 增量；任何 token、明文 Payload 或密钥泄漏立即停止 |

阈值来自应用自己的旧版本基线和风险预算，本文不提供通用数值。先在内部或小 cohort 灰度，观察窗口结束且所有阈值内才扩大范围；停止后冻结 cohort、保留数据库/日志/版本证据并执行预演过的恢复流程。

回滚同时恢复 `pubspec.yaml`、`pubspec.lock` 和升级前数据库/Preferences 快照，再运行旧基线场景。若没有验证旧 SDK 能读取新状态，就没有原地回滚依据。
