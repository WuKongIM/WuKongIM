## `WKIM` 与 `Options`

`WKIM.shared` 是进程单例。`setup(Options opts)` 保存配置、注册内置正文，并在 app mode 打开 UID 数据库。数据库打开成功后，它会发起一次 `updateSendingMsgFail()`，但两层调用都没有等待底层 sqflite update；这是 **best-effort、未等待**的状态修正，`setup` 返回成功不证明旧 sending 行已经落盘为失败。

```dart
final options = Options.newDefault(uid, token, addr: hostPort)
  ..debug = false
  ..deviceFlag = 0;

final opened = await WKIM.shared.setup(options);
```

| `Options` 字段 | `1.7.9` 语义 |
| --- | --- |
| `uid` / `token` | CONNECT 身份；必须由受信业务后端发放 |
| `addr` | 一个 DNS/IPv4 `host:port`；不是 URI |
| `getAddr` | 回调式动态路由：接收 `complete(addr)`；必须由应用设置超时 |
| `protoVersion` | 默认 `0x04`；不要在无跨端证据时覆盖 |
| `deviceFlag` | Android/iOS 使用 `0=APP`；已校对的 macOS wrapper 使用 `2=PC` |
| `debug` | 默认 `true`；生产设为 `false`，但仍需审计最终日志 |
| `proto` | 可替换协议对象；一般保留默认 `Proto()` |

`setup` 返回数据库打开结果；成功不等于连接、同步或运行兼容。`WKIM.shared` 公开 `runMode`、`options`、`deviceFlagApp`，以及 `connectionManager`、`messageManager`、`conversationManager`、`channelManager`、`channelMemberManager`、`reminderManager` 和 `cmdManager`。`isApp()` 读取运行模式；`setDeviceFlag(...)` 已 deprecated，改用 `Options.deviceFlag`。

## `WKConnectionManager`

| API | 契约 |
| --- | --- |
| `addOnConnectionStatus(String key, callback)` | 以稳定 key 监听 `(status, reasonCode, ConnectionInfo?)` |
| `removeOnConnectionStatus(String key)` | 用**相同 key**移除 |
| `connect()` | 先 `disconnect(false)`，再取路由并连接；不返回 ready Future |
| `disconnect(bool isLogout)` | `false` 保留身份；`true` 清 UID/Token，发起未等待的 best-effort sending→failed 更新后立即请求关闭数据库；不能据此证明更新已落盘 |
| `sendMessage(WKMsg)` | manager 内部低层发送入口；应用通常使用 `WKMessageManager.sendWithOption` |

`setConnectionStatus(...)` 和 `testCutData(...)` 也因 Dart 命名而公开，但分别是 SDK 状态推进和拆包测试入口；应用不得用它们伪造连接状态或生产流量。`_WKSocket` 以 `_` 开头，属于 library-private，不是公开合同。

首次连接可观察到 `fail(null) → connecting → success → syncMsg → syncCompleted`。`success` 是 CONNACK 成功，应用完成会话 provider 且收到 `WKConnectStatus.syncCompleted` 后才能发送。

| `WKConnectStatus` | 值 | 处理 |
| --- | ---: | --- |
| `fail` | `0` | 失败；首次 `connect()` 之前还会有合成的 null reason |
| `success` | `1` | CONNACK 成功，不是最终 ready |
| `kicked` | `2` | 终止并要求进程重启 |
| `syncMsg` | `3` | 同步中 |
| `connecting` | `4` | 新连接尝试 |
| `noNetwork` | `5` | 无网络；终止当前有界尝试 |
| `syncCompleted` | `6` | provider 交付后允许发送的门禁 |

## `WKMessageManager`

### 正文与发送

| API | 作用 |
| --- | --- |
| `registerMsgContent(type, factory)` | 注册自定义正文解码器 |
| `getMessageModel(type, json)` | 解码正文；未知类型回退 `WKUnknownContent` |
| `sendMessage(content, channel)` | 便利 wrapper；源码没有等待内部 `sendWithOption` |
| `sendWithOption(content, channel, options)` | 持久化、可选媒体上传并提交发送；调用方应直接 `await` |
| `getOrSyncHistoryMessages(...)` | 本地查询并按需触发频道历史 provider |
| `search(...)` / `searchWithChannel(...)` | 本地全文或频道搜索 |
| `searchMsgWithChannelAndContentTypes(...)` | 按频道、游标、上限和正文类型查询 |
| `getWithClientMsgNo(...)` | 按客户端编号查询 |
| `getMessageOrderSeq(...)` / `getOrNearbyMsgSeq(...)` / `getMaxMessageSeq(...)` | 在 message sequence 与本地 order sequence 之间定位 |
| `updateViewedAt(...)` | 更新本地已查看时间 |
| `getMaxExtraVersionWithChannel(...)` / `getMaxReactionSeqWithChannel(...)` | 读取消息扩展/reaction 增量游标 |
| `updateContent(...)` / `updateLocalExtraWithClientMsgNo(...)` / `updateMsgEdit(...)` | 更新本地正文、local extra 或待上传编辑 extra |
| `clearWithChannel(...)` / `deleteWithClientMsgNo(...)` | 本地清空频道或删除一条消息 |
| `sendMessageWithSetting(...)` / `sendMessageWithSettingAndHeader(...)` | deprecated；迁移到 `sendWithOption(...)` |

`WKSendOptions` 包含 `header`、`setting`、`expire` 与 `topicID`。`MessageHeader` 的 `noPersist=true` 会跳过本地入库；这时不能声称有持久化 `clientSeq`。媒体正文需先安装 `addOnUploadAttachmentListener`。

### Provider 与事件

| 注册 API | 所有权/移除 |
| --- | --- |
| `addOnMsgInsertedListener(callback)` | 应用级**单槽位**，无 remove API；后注册会覆盖 |
| `addOnUploadAttachmentListener(callback)` | 应用级单槽位，业务层上传媒体 |
| `addOnSyncChannelMsgListener(callback)` | 应用级单槽位，业务层同步频道消息 |
| `addOnUploadMsgExtra(callback)` | 应用级单槽位，上传消息扩展 |
| `addOnNewMsgListener(key, callback)` | keyed；`removeNewMsgListener(key)` |
| `addOnRefreshMsgListener(key, callback)` | keyed；`removeOnRefreshMsgListener(key)` |
| `addOnDeleteMsgListener(key, callback)` | keyed；`removeDeleteMsgListener(key)` |
| `addOnClearChannelMsgListener(key, callback)` | keyed；`removeClearChannelMsgListener(key)` |

发送关联使用 `clientMsgNO` 与正数 `clientSeq`。本地插入不是服务端结果；终止刷新只有 `WKSendMsgResult.sendSuccess` 是成功。

固定源码还公开了一组实现流程方法：`parsingMsg`、`saveMsg`、`generateClientMsgNo`、`saveRemoteExtraMsg`、`setSyncChannelMsgListener`、`wkSyncExtraMsg2WKMsgExtra`、`saveMessageReactions`、`getMsgReactionsAndRefreshMsg`、`pushNewMsg`、`setRefreshMsg`、`setOnMsgInserted`、`updateSendResult`、`updateMsgStatusFail` 和 `updateSendingMsgFail`。它们由收包、同步、数据库或 SENDACK 流程驱动，名称没有 `_` 只代表 Dart 可访问；业务层应包裹稳定用例入口，不要直接推进 SDK 内部状态。

| `WKSendMsgResult` | 值 |
| --- | ---: |
| `sendLoading` | `0` |
| `sendSuccess` | `1` |
| `sendFail` | `2` |
| `noRelation` | `3` |
| `blackList` | `4` |
| `notOnWhiteList` | `13` |

## 会话、频道、成员、提醒与 CMD 的公开面

下表列出固定 manager 源码的公开方法组；`set...` 通知/同步入口是 SDK 内部会调用的 public 实现面，应用通常只注册对应 listener/provider。

| Manager | 公开 API | 数据源/清理重点 |
| --- | --- | --- |
| `WKConversationManager` | `getAll`、`getWithChannel`、`saveWithLiMMsg`、`deleteMsg`、`clearAll`、`getAllUnreadCount`、`getExtraMaxVersion`、`updateRedDot`、`clearAllRedDot`、`addOnSyncConversationListener`、`setSyncConversation`、`addOnRefreshMsgListListener` / `removeOnRefreshMsgListListener`、`addOnClearAllRedDotListener` / `removeClearAllRedDotListener`、`addOnDeleteMsgListener` / `removeDeleteMsgListener`、deprecated `addOnRefreshMsgListener` / `removeOnRefreshMsg`、`setRefreshUIMsgs` | sync provider 无 key、单槽位；所有 keyed listener 用相同 key 移除；`saveWithLiMMsg`、`setSyncConversation` 和 `setRefreshUIMsgs` 主要由 SDK 流程调用 |
| `WKChannelManager` | `fetchChannelInfo`、`getChannel`、`getWithFollowAndStatus`、`search`、`searchWithChannelTypeAndFollow`、`addOrUpdateChannel`、`addOrUpdateChannels`、`updateAvatarCacheKey`、`addOnGetChannelListener`、`addOnRefreshListener` / `removeOnRefreshListener`、`addOnRefreshAvatarListener` / `removeOnRefreshAvatarListener` | channel provider 无 remove API；刷新与头像 listener keyed |
| `WKChannelMemberManager` | `getMaxVersion`、`getMembers`、`getMember`、`saveOrUpdateList`、`addOnRefreshMemberListener` / `removeRefreshMemberListener`、`addOnDeleteMemberListener` / `removeDeleteMemberListener`、`addOnNewMemberListener` / `removeNewMemberListener` | archive 没有业务分页 provider；大群分页/同步由业务层在交付 `saveOrUpdateList` 前设计 |
| `WKReminderManager` | `getWithChannel`、`getWithChannelAndType`、`getMaxVersion`、`saveOrUpdateReminders`、`setNewReminder`、`addOnNewReminderListener` / `removeOnNewReminderListener` | `setNewReminder` 是内部通知入口；listener keyed |
| `WKCMDManager` | `handleCMD`、`addOnCmdListener` / `removeCmdListener` | `handleCMD` 由内部正文解析调用；listener keyed |

`addOnSyncConversationListener` 的回调参数是 `lastMsgSeqs`、`msgCount`、`version` 和 `back(WKSyncConversation)`。生产 provider 必须完整映射最近会话、消息、未读和版本，并且只完成一次；网络失败不能伪装为空成功。

## 核心模型

- `WKChannel(channelID, channelType)`；常用 `WKChannelType.personal = 1`、`WKChannelType.group = 2`；
- `WKMsg` 同时含 `messageID` / `messageSeq`、`clientMsgNO` / `clientSeq`、频道、正文、状态、扩展与 reaction；`getFrom()` / `getMemberOfFrom()` 只读当前缓存，`1.7.9` 的 `getFromAsync()` / `getMemberOfFromAsync()` 会按需查询 manager；
- `WKMessageContent` 提供 `encodeJson()`、`decodeJson()`、`displayText()` 和 `searchableWord()`；
- 内置 `WKTextContent`、`WKCardContent`、`WKImageContent`、`WKVoiceContent`、`WKVideoContent`；
- `WKSyncConversation` / `WKSyncConvMsg` 表达会话同步结果；`WKSyncChannelMsg` 表达一页频道消息。

这些对象可变且与单例数据库关联。跨 isolate、异步 attempt 或 UI 层时，复制应用自己的不可变快照，并检查当前 activation。

## 安全与生命周期底线

- 原始 `Socket.connect` 无认证 TLS；
- `sqflite` 数据与 `SharedPreferences` 状态没有独立加密证明；
- debug 日志可能包含解密 Payload；
- `_sendingMsgMap` 与延迟重连没有安全的同进程重置边界；
- provider 单槽位和 keyed listener 必须由应用级 owner 管理；
- 超时、kick、断网、同步失败、不确定发送或 UID 切换后要求进程重启。

首次接入先完成[快速接入](/zh/sdk/flutter/quickstart)。替换已有 package 前按[升级指南](/zh/sdk/flutter/upgrade)保存 lockfile、数据库和回滚证据。
