This guide fixes the target to `wukongimfluttersdk 1.7.9`, archive SHA-256 `b6191a86cd1e4caacaa4652e95709310eb1493f159fee65e1dd53c2a3ff9e80a`, and matching source revision [`de1024276523119e38305c49a3a873caae4d5c59`](https://github.com/WuKongIM/WuKongIMFlutterSDK/tree/de1024276523119e38305c49a3a873caae4d5c59). The repository has no `1.7.9` tag. Record the hosted archive, application lockfile, and revision separately.

<Callout type="warn" title="Treat every package change as a migration">
  The pinned archive passed this site's macOS Release build, not an Android, iOS, or macOS runtime receipt. An upgrade can change database queries, migrations, providers, listeners, connection behavior, and dependency resolution. Do not publish after changing only the version number.
</Callout>

## 1. Freeze the pre-upgrade baseline

Record the toolchain and resolved graph on a separate branch:

```bash
flutter --version
dart --version
flutter pub deps --style=compact
git status --short
```

Retain the current `pubspec.yaml`, `pubspec.lock`, Release artifact digests, per-target signing configuration, and at least one real Alice/Bob scenario. Record connection, sync completion, local insertion, SENDACK, online receipt, offline recovery, and reconnect independently. “The app starts” is not messaging compatibility.

Find every call and package subpath:

```bash
rg -n "wukongimfluttersdk|WKIM\.shared|Options|sendMessage|sendWithOption|addOn|remove|clientMsgNO|clientSeq" lib test integration_test
```

Adjust directories for your project. Mark in particular:

- `lib/main.dart` is not an SDK barrel, so every `package:wukongimfluttersdk/...` subpath is a compile migration point;
- the owner of every provider/insert callback with no remove API;
- whether listener keys are stable and removed in pairs;
- dependencies on lazy mutable fields in `WKMsg` / `WKUIConversationMsg`;
- code that mistakes `sendMessage` or a local Future return for SENDACK.

## 2. Install exactly and lock the archive

Use an exact application dependency:

```yaml
dependencies:
  wukongimfluttersdk: 1.7.9
```

Do not use `^1.7.9`, `any`, Git `master`, or the stale repository `v1.0.0` tag. Resolve and commit the lockfile:

```bash
flutter pub get
git diff -- pubspec.yaml pubspec.lock
flutter pub get --enforce-lockfile
```

The hosted content hash in `pubspec.lock` must be:

```text
b6191a86cd1e4caacaa4652e95709310eb1493f159fee65e1dd53c2a3ff9e80a
```

CI must run `flutter pub get --enforce-lockfile`. Direct dependencies contain several caret constraints. Only the complete application lockfile fixes the real `sqflite`, `shared_preferences`, `connectivity_plus`, `dio`, crypto, and other transitive tuple.

## 3. Audit the exact `1.7.7 → 1.7.9` source interval

This migration starts at the `1.7.7` source revision [`d99990f41ecb31166af82b9d20c121f33ff8385d`](https://github.com/WuKongIM/WuKongIMFlutterSDK/tree/d99990f41ecb31166af82b9d20c121f33ff8385d) and ends at the matching `1.7.9` revision above. Do not substitute a branch head or a version-string comparison; use the exact [`d99990f...de102427` diff](https://github.com/WuKongIM/WuKongIMFlutterSDK/compare/d99990f41ecb31166af82b9d20c121f33ff8385d...de1024276523119e38305c49a3a873caae4d5c59) as the migration boundary.

The pinned [`CHANGELOG.md`](https://github.com/WuKongIM/WuKongIMFlutterSDK/blob/de1024276523119e38305c49a3a873caae4d5c59/CHANGELOG.md) records the channel maximum-reaction-sequence query in `1.7.8` and completion of `queryAll` conversation results with last message, message extras, and sender information in `1.7.9`. The exact source diff additionally proves that:

- `WKMsg` adds asynchronous `getFromAsync()` and `getMemberOfFromAsync()` lookups for sender channels and group members;
- reaction-list persistence now `await`s `ReactionDB.shared.insertOrUpdateReactionList(...)` before querying and refreshing messages;
- `WKMessageManager` adds `getMaxReactionSeqWithChannel(...)`;
- `queryAll` batch-loads `clientMsgNO`, message extras, and sender channels into `WKUIConversationMsg`.

An upgrade from `1.7.7` therefore needs regression coverage for:

- first conversation-list load and large-list latency, memory, and batched SQL parameters;
- missing, deleted, and unknown last-message content;
- edited, revoked, or pinned message extras matching the last message;
- direct/group sender data, cache hits, misses, failures, and avatar refresh through `getFromAsync()` / `getMemberOfFromAsync()`;
- ordering after awaited reaction persistence, maximum sequence, duplicate synchronization, and per-user uniqueness;
- refresh ordering after `getAll()` / underlying `queryAll` data changes.

For an older starting point, inspect each real delta rather than treating this table as a complete compatibility promise:

| Changelog milestone | Migration check |
| --- | --- |
| `1.4.7–1.5.0` | Protocol, pinned extras, expiry, new send API, and `noPersist`; recheck server revision and SENDACK |
| `1.5.1` | CONNACK adds node ID; status listeners must not assume the old callback shape |
| `1.5.5–1.5.6` | Channel-sync callback and reconnect/resend work; rerun outage, duplicate, and generation tests |
| `1.5.8–1.6.4` | Total unread, followed channels, and avatar events; recheck UI cache and listener removal |
| `1.7.3–1.7.6` | JSON-extra persistence, reaction, batched-extra, and local-extra fixes; use real database copies |
| `1.7.7 → 1.7.9` | Async sender/member lookup, awaited reaction persistence, maximum reaction sequence, and `queryAll` last-message/extra/sender population; verify ordering, failures, performance, and display |

The changelog records upstream intent, not your migration test. When the start version is outside the table, diff the actual locked archive/source against the target revision.

## 4. Treat database migration as irreversible

`WKDBHelper` opens `wk_<uid>.db`, then executes archive SQL by the UID-specific `wk_max_sql_version_<uid>` in `SharedPreferences`. The pinned archive has no reverse migration and no **downgrade contract** that an older SDK can read upgraded state.

In particular, pinned [`assets/202604271625.sql`](https://github.com/WuKongIM/WuKongIMFlutterSDK/blob/de1024276523119e38305c49a3a873caae4d5c59/assets/202604271625.sql) deletes every `message_reaction` row before creating a unique message/UID/channel index. Any upgrade crossing this migration must treat reaction resynchronization as a product step; local reactions are not preserved.

Before upgrading:

1. retain a redacted database and matching `SharedPreferences` snapshot for each test UID;
2. run the target SDK against copies and inspect messages, conversations, unread, channels, members, reminders, reactions, and search;
3. exercise migration failure, process kill, and low disk; the helper exposes no transactional downgrade procedure;
4. restore the **pre-upgrade database snapshot** or use an isolated fresh install for rollback instead of opening migrated data blindly with the old SDK.

## 5. Recompile and test the real call surface

Run static checks and project tests first:

```bash
flutter pub get --enforce-lockfile
flutter analyze
flutter test
flutter build macos --release
```

`flutter build macos --release` is the equivalent entry for the tuple this site exercised. Your application still needs build, signing, installation, and runtime work on its real Android/iOS/macOS toolchains. The pinned package itself still reports 93 analyze warning/info findings and a `RangeError` in `wksdk_test.dart`; successful dependency resolution is not a green package suite.

Add or update contracts for:

- compilation of every package subpath import;
- one `WKIM.shared.setup` per process and the correct device flag;
- deterministic terminal handling for provider success, rejection, timeout, and stale completion;
- same-key removal for keyed listeners and no page-level overwrite of single-slot providers;
- waiting for the same `clientMsgNO` / `clientSeq` terminal ACK after `await sendWithOption`;
- custom/unknown content, media upload, message extras, and reaction round trips;
- `getAll()` completeness and performance with a large conversation set.

## 6. Re-accept lifecycle and security

- Accept `fail(null) → connecting → success → syncMsg → syncCompleted`; there is no extra final `success`.
- Timeout, non-null CONNACK failure, kick, `noNetwork`, second `connecting`, provider failure, and SENDACK timeout terminate the run.
- Record Alice local insertion, terminal SENDACK, and Bob online receipt separately.
- Raw `Socket.connect`, plaintext sqflite/SharedPreferences, Payload logging, uncancellable reconnect, and retained `_sendingMsgMap` remain production blockers.
- Require process restart after success, failure, timeout, or UID change until the SDK exposes and proves a safe same-process reset contract.

Android, iOS, and macOS permissions, background behavior, notifications, storage, signing, and devices each need a separate receipt. Windows, Linux, and Web are outside this package/evidence boundary.

## 7. Roll out and roll back

Bind the version, archive SHA, `pubspec.lock` digest, Flutter/Dart/native toolchain, device/system, server revision, and Alice/Bob result as one release unit. Before rollout, fill in the release record with baselines, **quantified observation thresholds**, an observation window, and an owner. An empty field means the cohort may not start:

| Signal | Required threshold and stop condition |
| --- | --- |
| Connection acceptance, sync duration, terminal SENDACK success/latency | Record the old-version baseline, maximum allowed regression/increase, and minimum sample; stop expansion on any breach |
| Duplicate, lost, ordered, reaction, and extra behavior | Any confirmed durable-message loss, duplicate delivery, or incorrect association stops rollout and preserves evidence |
| `queryAll` completeness and latency | Record minimum completeness and maximum p95/p99 for a large conversation set; stop on missing/mismatched last message, extra, or sender |
| Migration, database, and rollback | Any unopenable/corrupt database, migration failure, or inability to restore the pre-upgrade snapshot stops rollout immediately |
| Crash/ANR and logs | Record the allowed crash/ANR delta; any Token, plaintext Payload, or key exposure stops rollout immediately |

Thresholds come from the application's old-version baseline and risk budget; this guide supplies no universal values. Start with internal users or a small cohort, expand only after the observation window remains within every threshold, and on stop freeze the cohort, preserve database/log/version evidence, and run the rehearsed recovery path.

Rollback restores `pubspec.yaml`, `pubspec.lock`, and the pre-upgrade database/Preferences snapshot together, then reruns the old baseline. Without proof that the old SDK reads new state, there is no basis for an in-place downgrade.

## Completion checklist

- `wukongimfluttersdk: 1.7.9`, archive SHA, and revision are recorded.
- `pubspec.lock` is committed and CI passes `--enforce-lockfile`.
- Deep imports, providers, listeners, send, async sender/member, reaction, and conversation `queryAll` calls are audited.
- Database snapshot, reaction migration, per-platform Release, and Alice/Bob evidence are reproducible.
- Quantified observation thresholds, window, owner, and stop conditions are filled and rehearsed.
- Rollback restores the dependency graph and local state, not only the package version.
