This page fixes the application dependency to the actual `wukongimfluttersdk 1.7.9` release. Repository `master`, the stale `v1.0.0` tag, and `^1.7.9` are different build identities.

## 1. Confirm the toolchain and target

The package declares only a Dart range:

```yaml
environment:
  sdk: ">=2.17.0 <4.0.0"
```

It declares no exact Flutter minimum. pub.dev currently labels Android, iOS, and macOS. The source imports `dart:io`, calls `Socket.connect`, and depends on sqflite, so this tutorial does not publish Web, Windows, or Linux runtime support.

The site's temporary consumer used Flutter `3.41.4`, Dart `3.11.1`, and macOS `15.1` arm64. `flutter analyze` and a macOS Release build passed. The host lacked Android command-line tools; the temporary iOS target lacked a Development Team/provisioning profile; no platform has a site Alice/Bob runtime receipt.

Record your own tuple first:

```bash
flutter --version
dart --version
flutter doctor -v
```

## 2. Pin the package without a range

Use an exact version in the application's `pubspec.yaml`:

```yaml
dependencies:
  flutter:
    sdk: flutter
  wukongimfluttersdk: 1.7.9
```

Resolve it:

```bash
flutter pub get
```

Do not use `wukongimfluttersdk: ^1.7.9`, `any`, or Git `master`. The `1.7.9` pub.dev archive is:

```text
https://pub.dev/api/archives/wukongimfluttersdk-1.7.9.tar.gz
SHA-256 b6191a86cd1e4caacaa4652e95709310eb1493f159fee65e1dd53c2a3ff9e80a
```

Its `lib`, `assets`, `pubspec.yaml`, and `CHANGELOG.md` match official repository revision `de1024276523119e38305c49a3a873caae4d5c59`. The repository has no `1.7.9` tag, and the pub.dev uploader is not a verified publisher. Retain both the archive content hash and matching revision.

## 3. Commit and enforce the lockfile

Application projects must commit `pubspec.lock`. Check the direct entry:

```yaml
wukongimfluttersdk:
  dependency: "direct main"
  description:
    name: wukongimfluttersdk
    sha256: b6191a86cd1e4caacaa4652e95709310eb1493f159fee65e1dd53c2a3ff9e80a
    url: "https://pub.dev"
  source: hosted
  version: "1.7.9"
```

Start CI and Release builds with:

```bash
flutter pub get --enforce-lockfile
flutter analyze
flutter build <your-target> --release
```

`--enforce-lockfile` rejects a resolution that no longer satisfies `pubspec.yaml` or a hosted-package content-hash drift. Do not run `flutter pub upgrade` first in a Release job.

## 5. Configure platform networking

The Android Release main manifest needs network permission:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

For macOS App Sandbox, enable client networking in Debug/Profile and Release entitlements:

```xml
<key>com.apple.security.network.client</key>
<true/>
```

iOS, macOS, and Android also need product-specific local-network permission, background policy, and network security configuration. These entries only let the raw TCP socket attempt a connection; they do not add TLS, certificate verification, background survival, or push.

## 6. Configure identity, route, and logs

Identity and route come from a trusted application backend. Source parses `addr` with `split(":")`, so provide exactly one DNS/IPv4 `host:port`, not `tcp://`, `https://`, or an IPv6 literal.

```dart
const deviceFlag = 0; // Android/iOS; use 2 for a macOS desktop build.

final options = Options.newDefault(
  uidFromBackend,
  tokenFromBackend,
  addr: 'im.example.internal:5100',
)
  ..debug = false
  ..deviceFlag = deviceFlag;

final initialized = await WKIM.shared.setup(options);
if (!initialized) throw StateError('WKIM setup failed');
```

The device dictionary is `0=APP`, `1=WEB`, and `2=PC`: native Android/iOS applications use `0`, while macOS uses `2`. A Windows/Linux port may adopt the same protocol value only after separate implementation and compatibility testing; this package snapshot and site receipt claim support for neither platform. Browser targets must use the Web/JSSDK instead of setting this value to `1`. `Options.debug` defaults to `true`, so disable it before setup. Debug decode logs emit `RecvPacket.toString()` with plaintext **Payload**. `ConnectPacket.toString()` also contains UID and Token and must not enter application logs.

## 7. Understand local data

`setup` opens a normal **sqflite** database named `wk_<uid>.db` and calls `updateSendingMsgFail()` to mark prior sending rows failed; it does not recover the send. The SDK provides no at-rest database encryption. **SharedPreferences** also stores a UID-scoped device ID and SQL migration version.

Before adoption, decide:

- whether the database and backups satisfy device encryption, enterprise control, and deletion requirements;
- where the application retains and revokes Token;
- how account logout clears product caches;
- how to wait for terminal SENDACK before logout, because `disconnect(true)` does not clear `_sendingMsgMap` and account switching belongs in a new process.

## Release blockers

- `Socket.connect` is raw **TCP** without authenticated TLS.
- Normal sqflite, SharedPreferences, and **Payload** logging do not close production data protection.
- `_sendingMsgMap`, non-cancellable delayed reconnect, and unremovable singleton providers make terminal recovery require a **process restart**.
- The parser test failure and offline/push/background/multi-device paths still lack complete evidence.

After exact installation, continue to the [Quickstart](/en/sdk/flutter/quickstart).
