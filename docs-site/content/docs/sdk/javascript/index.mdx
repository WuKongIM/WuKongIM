这套教程面向第一次把 WuKongIM 接入浏览器应用的开发者。它不依赖 React 或 Vue，而是用框架无关的 TypeScript、一个仅限本机的 BFF，以及 Alice/Bob 两个会话展示完整的客户端生命周期。

<Callout type="warn" title="先明确当前覆盖范围">
  教程固定使用 `wukongimjssdk@1.3.5` 和兼容快照中的 Chromium。它能证明这套样例里的安装、连接、双向持久消息、重连与离线恢复；不能自动证明其他浏览器、JavaScript SDK、运行时或平台版本兼容。
</Callout>

## 适合谁

- 你正在开发浏览器端聊天、客服、协作或实时通知界面；
- 你可以在受信后端中准备 UID、Token 和连接地址；
- 你希望先跑通一个可观察的消息闭环，再接入自己的框架和状态管理。

如果你还没决定使用 EasySDK 还是 WuKongIMSDK，先看[选择 SDK](/zh/sdk/choose-sdk)。本教程使用 WuKongIMJSSDK，不应把其中的方法名复制到其他 SDK。

## 你将搭建什么

```text
Alice 浏览器 ─┐                         ┌─ Gateway WebSocket
              ├─ localhost BFF ────────┤
Bob 浏览器 ───┘   身份、路由、离线同步    └─ WuKongIM 单节点集群
```

- 浏览器中的 SDK 管理连接、发送、接收和重连状态；
- BFF 代表受信业务后端调用 Product HTTP，并且只绑定 loopback；
- WuKongIM 集群负责持久消息的顺序、提交、路由和在线投递。

浏览器不会获得 Product HTTP 管理能力。迁移到真实产品时，你的业务后端要替换样例 BFF，接入自己的登录、授权和 Token 生命周期。

## 第一次运行前准备

- 一个已经通过 `/readyz` 的 WuKongIM 单节点集群；
- Node.js `>=20.11` 与 npm；
- 端口 `5001`、`5200` 和样例使用的 loopback 端口可用；
- 当前仓库源码，用于运行 `docs-site/examples/javascript-web-quickstart`。

## 第一条消息会经过什么

| 阶段 | 你做什么 | 你应该看到什么 |
| --- | --- | --- |
| 安装 | 使用 lockfile 安装固定 SDK | 测试、TypeScript 与构建检查通过 |
| 身份 | Alice 与 Bob 分别向 BFF 请求开发身份 | 浏览器得到 UID、临时 Token 和 WebSocket 地址 |
| 连接 | SDK 注册监听并发起连接 | 两边状态分别变为 `connected` |
| 发送 | Alice 给 Bob 发送持久文本消息 | Alice 收到 SENDACK，Bob 收到 `realtime` 事件 |
| 断线 | Bob 断开，Alice 再发送 | Alice 仍收到 SENDACK，Bob 没有实时事件 |
| 恢复 | Bob 重连并同步 | Bob 看到一次 `recovered` 结果 |

SENDACK、在线接收和离线恢复是三个独立结果。教程会让你分别观察它们，而不是只显示一个模糊的“发送成功”。

## 完成标志

- 你能解释 Token 和连接地址为什么来自后端，而不是写死在浏览器；
- 你能在代码中找到连接状态、消息和发送确认的监听器；
- 你能区分持久提交、在线投递和同步恢复；
- 你知道样例通过后还需要哪些生产门禁。

## 常见故障

- **安装阶段失败**：回到 lockfile 和 Node.js 版本，不要改用 `latest` 绕过。
- **身份创建失败**：确认集群 `/readyz`、BFF 输出和 Product HTTP 地址。
- **一直连接中**：检查 `/route` 返回地址和 Gateway WebSocket 端口。
- **对方没收到**：分别检查 SENDACK、在线事件和离线同步，不要把三条路径混在一起。
