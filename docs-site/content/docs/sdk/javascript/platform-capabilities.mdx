## “已验证”的精确含义

当前 protected scenario 使用两个隔离 Chromium browsing context 和一个 loopback-only BFF，证明单聊中的路由、连接、双向持久发送、SENDACK、实时接收、断线恢复和去重。它绑定：

- 当前服务端完整 revision；
- 样例 `package-lock.json` SHA-256；
- `wukongimjssdk@1.3.5`；
- Node.js、Playwright 与 Chromium 精确运行时身份；
- `javascript-web-quickstart/alice-bob-reconnect-sync/v1` 场景。

任一成员变化都会形成新的未验证组合，直到真实场景再次通过。样例最低 Node.js 要求不等于所有 Node/浏览器组合都获得同一 receipt。

## 当前安全边界

### 连接身份

`POST /user/token` 写入开发设备 Token 元数据，但默认 v3 Beta Gateway 没有已存 Token verifier。开发 CONNECT 成功不能证明无效、过期或撤销凭据会被拒绝。生产必须接入可信 verifier，并执行端到端拒绝测试。

### Product HTTP

浏览器只调用 same-origin BFF。`/user/token`、`/route` 和 `/channel/messagesync` 只由受信 Node.js 进程访问；BFF 只允许 loopback Host 与 Origin。这个实验边界不是可部署的账号服务。

### 浏览器范围

只有固定 Chromium 目标可以进入当前 verification receipt。Firefox、Safari/WebKit、移动 WebView、扩展环境、Service Worker 和后台休眠行为均未进入可执行矩阵。

## 未验证不等于不存在

群聊、自定义消息、会话、推送、多设备、`NoPersist` 或其他 SDK 导出可能存在于某个版本，但本页不会仅凭源码符号声明兼容。采用这些能力前，至少补齐：

1. 精确 SDK 与服务端版本；
2. 最小可运行样例；
3. 正常、拒绝、断线和恢复断言；
4. 安全与数据所有权边界；
5. CI 中的真实环境证据。

完整 JavaScript API Reference 和升级指南仍处于规划状态。跨平台行为可先阅读 [SDK 公共指南](/zh/sdk/common-guides)，但其中的建议不能替代 JavaScript 方法签名或运行时证明。

## 生成本地验收报告

按[上线验收](/zh/guide/integration/acceptance)运行：

```bash
npm run verify:acceptance
```

该命令生成兼容性 Smoke 报告，但明确保留 `production_readiness.result=not_assessed`。它不会签发文档发布 receipt，也不会证明生产鉴权、TLS、Webhook、容量或回滚。
