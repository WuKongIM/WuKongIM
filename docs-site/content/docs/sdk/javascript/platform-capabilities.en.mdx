## Exact meaning of verified

The protected scenario uses two isolated Chromium browsing contexts and one loopback-only BFF. It proves person-chat routing, connection, bidirectional persistent send, SENDACK, realtime receipt, disconnect recovery, and deduplication. Evidence binds:

- the complete current server revision;
- the sample `package-lock.json` SHA-256;
- `wukongimjssdk@1.3.5`;
- exact Node.js, Playwright, and Chromium runtime identities; and
- scenario `javascript-web-quickstart/alice-bob-reconnect-sync/v1`.

Changing any member creates a new unverified combination until the real scenario passes again. The sample's minimum Node.js requirement does not grant the same receipt to every Node or browser combination.

## Current security boundaries

### Connection identity

`POST /user/token` stores development device-token metadata, but the default v3 Beta Gateway has no stored-token verifier. A successful development CONNECT does not prove that invalid, expired, or revoked credentials are rejected. Production must wire a trusted verifier and execute end-to-end rejection tests.

### Product HTTP

The browser calls only the same-origin BFF. Only the trusted Node.js process accesses `/user/token`, `/route`, and `/channel/messagesync`, and the BFF accepts loopback Host and Origin values only. This laboratory boundary is not a deployable account service.

### Browser scope

Only the pinned Chromium target is eligible for the current verification receipt. Firefox, Safari/WebKit, mobile WebViews, extension contexts, Service Workers, and background suspension behavior are outside the executable matrix.

## Unverified does not mean absent

Groups, custom messages, conversations, push, multi-device behavior, `NoPersist`, or other exports may exist in a version, but this page does not infer compatibility from symbols. Before adopting one, add:

1. exact SDK and server versions;
2. a minimal runnable sample;
3. success, rejection, disconnect, and recovery assertions;
4. security and data-ownership boundaries; and
5. real-environment CI evidence.

The complete JavaScript API Reference and upgrade guide remain planned. [SDK Common Guides](/en/sdk/common-guides) can establish cross-platform behavior, but cannot substitute for JavaScript signatures or runtime evidence.

## Generate a local acceptance report

Follow [Integration Acceptance](/en/guide/integration/acceptance) and run:

```bash
npm run verify:acceptance
```

The command produces a compatibility-smoke report while retaining `production_readiness.result=not_assessed`. It does not issue the documentation publication receipt or prove production authentication, TLS, webhooks, capacity, or rollback.
