---

官方 `WuKongIMUniappSDK` 已明确弃用，并要求改用 `WuKongIMJSSDK`。这不是一次普通升级：旧 npm 包仍能安装，注册表也没有 deprecated 标记，但它不再是新项目候选。

<Callout type="warn" title="不要继续安装 wukongimuniappsdk">
  官方仓库在 2023-07-13 加入弃用声明；npm `wukongimuniappsdk@1.0.3` 发布于更早的 2023-06-26，包内 README 没有弃用文字。能安装不代表仍受维护。
</Callout>

## 你应该怎么做

| 当前情况 | 建议 |
| --- | --- |
| 新 UniApp 项目 | 不安装 `wukongimuniappsdk`；从[JSSDK 迁移评估](/zh/sdk/uniapp/migrate-to-jssdk)开始 |
| 已使用旧包 | 先固定现状和回归用例，再移除旧包、精确安装 `wukongimjssdk@1.3.5` |
| 只需要 H5 | 可以复用 JSSDK 的 Web API，但仍需在自己的 UniApp H5 构建中独立验收 |
| 同时发布 App、H5、小程序 | 把每个目标当成独立运行时，分别验证 socket adapter、Device Flag、WSS、后台和恢复行为 |

## 当前能证明什么

- 已核对官方弃用仓库、旧 npm `1.0.3` 产物和当前 `wukongimjssdk@1.3.5` 源码/产物；
- `1.3.5` 源码依次检测全局 `uni`、全局 `wx`，分别使用 `uni.connectSocket`、`wx.connectSocket`，否则回退到原生 `WebSocket`；
- `config.debug = false` 不能关闭所有控制台输出，未修改版本会记录解密后的接收包与重试发送包；
- 本站的 Chromium 黄金路径只证明浏览器样例，不证明 UniApp adapter；
- 本站没有 HBuilderX、App、H5 或小程序运行 receipt，也没有设备上的 UniApp Alice/Bob 结果。

因此，这组内容是迁移和独立验收指南，不是“UniApp 已兼容”的声明。

## 迁移前先回答四个问题

1. 目标是 App、H5 还是哪个小程序平台？
2. 业务后端如何返回 UID、短期 Token 与 WSS 路由？
3. 当前代码用了哪些旧包导入、provider、自定义消息和 listener？
4. 你将用什么 HBuilderX/CLI、uni-app/Vue、设备/OS 与服务端 revision 保存独立验收证据？

客户端不能持有 Product HTTP 管理凭据。身份、Token、路由和权限必须来自受信业务后端；旧仓库 demo 直接调用演示接口的方式不是生产信任架构。

## 下一步

进入[迁移到 JSSDK](/zh/sdk/uniapp/migrate-to-jssdk)，按“盘点 → 移除旧包 → 固定新包 → 配置运行时 → Alice/Bob 验收 → 保存证据”的顺序执行。若某个目标不能通过，就保持旧版本可回滚，不要用另一个目标或 Chromium 的结果代替。
