本页面向仍在使用 `wukongimuniappsdk` 的项目。目标不是把包名替换后直接上线，而是把旧集成迁移到精确的 `wukongimjssdk@1.3.5`，并为 App、H5、小程序分别建立独立验收结果。

<Callout type="warn" title="本站没有 UniApp 运行 receipt">
  本站核对了源码和 npm 产物，但没有用 HBuilderX 构建 App、H5 或小程序，也没有在设备上调用 `uni.connectSocket` 或 `wx.connectSocket`。已有 Chromium receipt 只属于浏览器黄金路径，不能证明本页迁移后的目标运行时。
</Callout>

## 2. 迁移前保存基线

先记录并截图当前可重复结果：

- `package.json` 与锁文件中的旧包版本；
- 所有 `wukongimuniappsdk`、`wukongimjssdk/lib/*` 深路径导入；
- UID、Token、路由获取流程，但不要保存真实凭据；
- provider、自定义消息注册、连接/消息/SENDACK listener；
- App、H5、小程序各自的连接、在线消息、断线恢复结果；
- 当前 HBuilderX/CLI、uni-app/Vue、目标设备/OS 与服务端 revision。

基线用于比较和回滚，不是继续采用已弃用包的理由。

## 3. 移除旧包并固定新包

只选择与现有锁文件匹配的一组命令；不要在 Yarn/pnpm 项目中运行 npm，从而生成第二份锁文件。

### npm（`package-lock.json`）

```bash
npm uninstall wukongimuniappsdk
npm install --save-exact wukongimjssdk@1.3.5
npm ls wukongimuniappsdk
npm ls wukongimjssdk
```

`npm ls wukongimuniappsdk` 显示 `(empty)` 时通常以退出码 `1` 结束，这是这里预期的否定检查；`npm ls wukongimjssdk` 应显示精确 `1.3.5` 并以 `0` 结束。CI 中应分别判断输出与退出码，不要用 `|| true` 隐藏真实依赖错误。

### Yarn（`yarn.lock`）

```bash
yarn remove wukongimuniappsdk
yarn add --exact wukongimjssdk@1.3.5
yarn why wukongimuniappsdk
yarn why wukongimjssdk
```

### pnpm（`pnpm-lock.yaml`）

```bash
pnpm remove wukongimuniappsdk
pnpm add --save-exact wukongimjssdk@1.3.5
pnpm why wukongimuniappsdk
pnpm why wukongimjssdk
```

三种路径的共同结果是：旧包不在依赖树中，新包精确为 `1.3.5`。只审查并提交原有 lockfile 的完整 diff；若旧包仍被传递依赖引用，先找出来源，不要忽略错误继续。

`1.3.5` 的 export map 只公开包根与 `package.json`。统一改成根导入：

```typescript
import WKSDK, {
  Channel,
  ChannelTypePerson,
  ConnectStatus,
  MessageText,
  SendackPacket
} from 'wukongimjssdk'
```

不要保留 `wukongimjssdk/lib/*` 深路径；它既不在当前 export map 中，也不是稳定 API 合同。对照精确 `1.3.5` 类型声明逐项迁移，不假设旧 wrapper 能无差异替换。

## 4. 先确认 UniApp socket adapter

`1.3.5` 的真实检测顺序是：全局 `uni` → `uni.connectSocket`，否则全局 `wx` → `wx.connectSocket`，两者都没有时回退到原生 `WebSocket`。平台分支会把选中的方法保存到模块变量 `wkconnectSocket`。先在每个目标的启动阶段验证实际分支：

```typescript
const runtime = globalThis as typeof globalThis & {
  uni?: { connectSocket?: unknown }
  wx?: { connectSocket?: unknown }
}

let transport: 'uni.connectSocket' | 'wx.connectSocket' | 'WebSocket'
if (runtime.uni !== undefined) {
  if (typeof runtime.uni.connectSocket !== 'function') {
    throw new Error('global uni exists but uni.connectSocket is not callable')
  }
  transport = 'uni.connectSocket'
} else if (runtime.wx !== undefined) {
  if (typeof runtime.wx.connectSocket !== 'function') {
    throw new Error('global wx exists but wx.connectSocket is not callable')
  }
  transport = 'wx.connectSocket'
} else {
  if (typeof WebSocket !== 'function') {
    throw new Error('This target exposes no supported socket transport')
  }
  transport = 'WebSocket'
}
```

<Callout type="warn" title="不要把 config.platform = uni / wx 当成修复">
  当前源码虽然暴露 `config.platform`，但显式传入 `uni` 或 `wx` 时不会初始化或刷新 `wkconnectSocket`。第一次使用时可能创建原生 `WebSocket`，后续却按平台 socket 调用 `onOpen` / `onMessage`；之前自动检测过时还可能复用陈旧 adapter。在未修 SDK 前，不要推荐或依赖这两条路径。
</Callout>

H5 没有全局 `uni` / `wx` 时可以进入原生 `WebSocket` 分支；必须在该 H5 构建中直接验证。只有目标需要平台 socket、却没有暴露全局 `uni` 或 `wx` 时，才应维护一个评审过的 adapter fork，使“创建 socket”和“事件 API”来自同一个平台对象，并为该 fork 保存源码 revision、补丁和目标运行 receipt。不能从 H5 通过推断 App 或小程序也会通过。

## 5. 明确 Device Flag 与 WSS

`wukongimjssdk@1.3.5` 默认 `deviceFlag = 1`。连接前按协议类别显式设置，并让受信业务后端签发/保存的设备元数据一致：

| 设备类别 | 值 | 常见目标 |
| --- | --- | --- |
| `0 = APP` | `0` | 原生 App 容器 |
| `1 = WEB` | `1` | H5 / 浏览器 |
| `2 = PC` | `2` | 桌面客户端 |

小程序不应仅凭“也是 JavaScript”猜类别；先明确产品设备策略，再让客户端、Token 元数据与服务端一致并单独验收。

```typescript
const sdk = WKSDK.shared()
sdk.config.uid = bootstrap.uid
sdk.config.token = bootstrap.shortLivedToken
sdk.config.addr = bootstrap.wssAddress
sdk.config.deviceFlag = targetDeviceFlag // 0 = APP, 1 = WEB, 2 = PC
// 1.3.5 下不要设置 sdk.config.platform；让 uni → wx → WebSocket 自动检测运行。
```

App 和小程序的域名白名单、证书链及网络策略不同。生产环境使用受信业务后端返回的 WSS 地址，并在每个目标验证域名、证书、代理、弱网和切换网络；不要在客户端保存 Product HTTP 管理凭据或自行签发 Token。

## 6. 按正确顺序接回业务

1. 由受信业务后端返回 UID、短期 Token 与 WSS 路由；
2. 设置 `uid`、`token`、`addr`、`deviceFlag`；
3. 安装消息同步等 provider，失败时显式抛错；
4. 自定义正文先用 `WKSDK.shared().register(contentType, factory)` 注册 factory；否则接收时会变成 `UnknownContent`；
5. 分别通过 `connectManager.addConnectStatusListener`、`chatManager.addMessageListener` 和 `chatManager.addMessageStatusListener` 注册连接、消息与 SENDACK listener；
6. 调用 `WKSDK.shared().connect()`；
7. 连接成功后发送一条个人文本，分别记录 SENDACK 与对端在线接收；
8. 断开 Bob，再发送一条持久消息，重连后从同步路径恢复并去重；
9. 退出时调用对应的 `removeConnectStatusListener`、`removeMessageListener`、`removeMessageStatusListener`，并为下一账号使用新进程或已验证的生命周期隔离。

可参考 [JavaScript/Web 快速接入](/zh/sdk/javascript/quickstart)理解 JSSDK 的消息语义，但只能复用 API 思路，不能复用 Chromium 的验证结论。

## 7. 每个目标单独验收

| 目标 | 至少保存的结果 |
| --- | --- |
| App | HBuilderX/CLI、App 基座/签名、设备与 OS、`0 = APP`、WSS、前后台/网络切换、Alice/Bob 闭环 |
| H5 | 构建模式、浏览器/WebView、`1 = WEB`、WSS、SENDACK、在线接收与离线恢复 |
| 小程序 | 平台与基础库、域名白名单、Device Flag 决策、实际 `uni.connectSocket` / `wx.connectSocket` 分支、前后台与恢复 |

一次可评审 receipt 至少包含：

```text
wukongimjssdk 1.3.5 + lockfile digest + tarball integrity
JSSDK source revision + any adapter fork revision
HBuilderX/CLI + uni-app/Vue + exact target
build/signing + device/OS or browser/WebView
server revision + WSS route class (not credentials)
Alice/Bob redacted connection timestamps
local send correlation + SENDACK + online receive
disconnect + offline send + reconnect recovery + dedup result
```

本站没有这组 UniApp 运行 receipt。App、H5、小程序任一目标通过，都不能自动替代其他目标的独立验收。

## 8. 发布与回滚门禁

<Callout type="warn" title="1.3.5 的明文 Payload 日志是发布阻断项">
  接收路径会先解密 `RecvPacket.payload`，再无条件 `console.log` 整个接收包；重连队列也会记录包含明文 Payload 的 `SendPacket`。这些路径不检查 `config.debug`，所以 `config.debug = false` 不能关闭它们。未修改的 `1.3.5` 不能通过生产发布门禁；必须采用评审过的删除/脱敏补丁或已验证的构建期移除，并检查最终发布产物与日志采集链路。
</Callout>

只有以下条件同时满足才扩大灰度：旧包已从依赖树消失；精确版本和锁文件已审查；每个目标的最小闭环通过；Token 与 WSS 来自受信后端；明文日志补丁和最终产物已验证；日志无 Token/完整 Payload；失败、断网、后台、恢复和回滚已演练。

迁移失败时回滚应用版本和对应 lockfile，不要在同一构建中同时保留两套 SDK 争用单例、provider 或 socket。记录失败目标、工具链和日志，再修 adapter 或业务映射。
