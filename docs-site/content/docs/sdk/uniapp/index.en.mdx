---

The official `WuKongIMUniappSDK` is deprecated and directs users to `WuKongIMJSSDK`. This is not a normal upgrade. The old npm package still installs and the registry has no deprecated marker, but it is no longer a candidate for a new project.

<Callout type="warn" title="Do not keep installing wukongimuniappsdk">
  The official repository added its deprecation notice on 2023-07-13. npm `wukongimuniappsdk@1.0.3` was published earlier, on 2023-06-26, and its packaged README has no retirement notice. Installability is not maintenance.
</Callout>

## What to do

| Current situation | Recommendation |
| --- | --- |
| New UniApp project | Do not install `wukongimuniappsdk`; begin with the [JSSDK migration evaluation](/en/sdk/uniapp/migrate-to-jssdk) |
| Existing old-package integration | Freeze the baseline and regression cases, then remove the old package and pin `wukongimjssdk@1.3.5` |
| H5 only | You can reuse the JSSDK Web API, but must still run a separate acceptance in your own UniApp H5 build |
| App, H5, and mini-program targets | Treat every target as a separate runtime and verify its socket adapter, Device Flag, WSS, background, and recovery behavior |

## What is actually proven

- The official retired repository, old npm `1.0.3` artifact, and current `wukongimjssdk@1.3.5` source/artifact were inspected.
- Exact `1.3.5` source checks global `uni` and then global `wx`, uses `uni.connectSocket` or `wx.connectSocket`, and otherwise falls back to native `WebSocket`.
- `config.debug = false` does not disable every console path; unmodified source logs decrypted receive packets and retried send packets.
- This site's Chromium golden path proves only its browser sample, not the UniApp adapter.
- This site has no HBuilderX, App, H5, or mini-program runtime receipt and no device-side UniApp Alice/Bob result.

This content is therefore a migration and separate acceptance guide, not a statement that “UniApp is compatible.”

## Answer four questions first

1. Is the target App, H5, or a specific mini-program platform?
2. How does the trusted backend return UID, short-lived Token, and a WSS route?
3. Which old-package imports, providers, custom messages, and listeners exist today?
4. Which HBuilderX/CLI, uni-app/Vue, device/OS, and server revision will identify the separate acceptance evidence?

The client must not hold Product HTTP administrative credentials. Identity, Token, route, and policy come from a trusted backend. The old repository demo's direct calls to demonstration endpoints are not a production trust architecture.

## Next step

Open [Migrate to JSSDK](/en/sdk/uniapp/migrate-to-jssdk) and follow inventory → remove old package → pin new package → configure runtime → Alice/Bob acceptance → retain evidence. If one target fails, keep a reviewed rollback path; do not substitute another target or the Chromium result.
