Conversation 不是另一份消息真相。当前服务端根据某个 UID 的成员目录与 Channel 已提交状态临时构建会话；消息仍以 Channel 日志为权威。

<Callout type="info" title="跨 SDK 行为指南">
  本页是**跨 SDK 行为指南**，不会声明某个平台已有相同的会话 API。只有 [JavaScript/Web 兼容快照](/zh/sdk/compatibility)中的窄消息恢复场景经过验证；完整会话 API 仍需按所选 SDK 版本确认。
</Callout>

## 目标与完成标准

客户端应能分别维护：会话列表分页游标、每个 Channel 的消息拉取游标、展示 Badge 的 floor、本地已显示位置和最终用户已读业务状态。它们不能共用一个整数。

## 当前会话模型

```text
UID 成员目录
  + Channel committed head / last message
  + join / delete / retention visibility floors
  + UID-owned read_seq 与 activated_at
  -> 临时构建 Conversation
```

- `activated_at` 参与活动会话顺序；
- `read_seq` 是 Badge floor，不是消息拉取游标或对端已读回执；
- `deleted_to_seq` 隐藏当前 UID 在某个 sequence 之前的内容，不删除 Channel 对其他成员的日志；
- Channel 解散会产生删除投影；临时 hydration 失败应报告 unresolved，而不是静默丢会话；
- SEND、在线接收、消息拉取本身不会自动改变 `read_seq` 或 `activated_at`。

## 客户端本地模型

每个会话至少分开保存：

| 状态 | 用途 |
| --- | --- |
| `channel_id + channel_type` | 稳定会话键；单聊 UI 可使用对端 UID，但不要暴露内部 canonical person ID |
| `last_committed_seq` | 已知 Channel head，用于判断是否缺消息 |
| `last_local_seq` | 本地原子提交完成的位置，用于继续拉取 |
| `displayed_seq` | UI 已展示到的位置，可用于产品策略但不自动等于服务端 `read_seq` |
| `read_seq` / Badge floor | 当前 UID 的服务端未读基线 |
| conversation cursor | 会话目录分页，不可替代 Channel 消息游标 |

## 同步与分页

1. 用 opaque conversation cursor 分页，不解析或拼接其中字段。
2. 空页不必然表示完成；只有响应的 `done=true` 才完成一次遍历。
3. 对 `unresolved` 键做有界重试，不要推进为永久删除。
4. 每个返回会话再按自己的 Channel sequence 恢复消息。
5. 消息同步与实时接收可能重叠，按消息身份去重并保持 Channel 内顺序。
6. 把会话 cursor、消息和本地 sequence 在可恢复事务中提交。

旧兼容 `/conversation/sync` 使用不同分页和响应语义，并在临时 hydration 失败时让整个请求失败。不要把旧数组响应与 canonical list 的 `unresolved` / `done` 模型混用。

## 未读与已读

未读数是投影，不是跨设备瞬时强一致计数。更新 Badge floor 时使用单调 sequence，重复请求必须幂等。若产品需要“对方已读”，发送独立的业务回执，明确读到的 Channel 与 sequence；不要用 RECVACK 代替。

多设备通常共享 UID-owned 会话与 `read_seq`。一个设备清未读可能改变其他设备下一次同步看到的 Badge，因此 UI 要接受服务端较新状态覆盖旧本地值。

## 失败诊断

- **会话存在但最近消息为空**：检查 Channel hydration、可见性 floor 和临时 unresolved。
- **未读数回退**：确认更新是否单调、是否把拉取游标误写成 `read_seq`。
- **翻页后漏会话**：不要把“返回数量小于 limit”当作 done；按 opaque cursor 继续。
- **单聊出现两个会话**：检查是否混用了对端 UID 与内部 canonical person Channel ID。

## 安全边界

会话列表可能暴露关系和行为时间。只返回当前 UID 有权观察的成员目录与消息，日志中不记录完整 UID/Channel 样本。当前默认 v3 Beta 组合未启用已存 Token 的 CONNECT 校验；生产环境必须接入可信 verifier，并证明无效、过期和撤销凭据都会被拒绝。
