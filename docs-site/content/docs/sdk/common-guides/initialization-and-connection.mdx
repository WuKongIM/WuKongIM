可靠的客户端不会把“创建 SDK 对象”和“业务可以发送消息”视为同一时刻。初始化需要先绑定环境与身份，连接成功后还要恢复缺失状态，最后才向 UI 发布 ready。

<Callout type="info" title="跨 SDK 行为指南">
  本页是**跨 SDK 行为指南**，状态名是应用侧建议，不是对每个平台 API 的承诺。当前唯一经过可执行场景验证的实现见 [JavaScript/Web 兼容快照](/zh/sdk/compatibility)。
</Callout>

## 目标与完成标准

应用应只有一个明确的连接所有者，能够串行化 connect、disconnect、身份切换与恢复。页面或组件可以观察状态，但不能各自创建互相竞争的 SDK 会话。

## 建议状态机

```text
idle
  -> preparing      读取环境、登录态和本地游标
  -> discovering    从受信后端取得 Gateway 入口
  -> connecting     建立传输并发送 CONNECT
  -> connected      CONNACK 成功，但尚未完成恢复
  -> recovering     同步缺失消息并合并本地状态
  -> ready          允许普通业务发送

任意活动状态
  -> degraded       网络或部分恢复暂不可用
  -> reconnecting   有界退避、必要时刷新路由
  -> logging-out    停止发送、关闭会话、清理本地身份状态
  -> idle
```

`connected` 与 `ready` 必须分开：CONNECT 只建立协议 Session；它不证明业务授权、离线数据已恢复或本地会话列表已收敛。

## 初始化顺序

1. 选择明确的服务端环境与 SDK 精确版本，不使用漂移的 `latest`。
2. 从业务登录取得 UID、设备材料和短生命周期 Token。
3. 注册连接、消息、错误和生命周期观察器，再发起连接，避免漏掉早期事件。
4. 通过受信后端调用路由发现；当前 `/route` 返回配置的 `tcp_addr`、`ws_addr`、`wss_addr`，不是按 UID 的业务授权。
5. 浏览器优先使用可达的 `wss_addr`，其他平台按其版本文档选择受 TLS 保护的入口。
6. SDK 发送 CONNECT 并单独检查 CONNACK Reason Code。
7. 连接成功后执行离线同步和本地去重，最后发布 `ready`。

WKProto 连接必须以 CONNECT 作为第一个数据包。认证等待期间发送第二个包会被视为协议错误。不要在并发页面初始化时重复调用连接。

## 路由与环境

- 路由结果只是当前配置的入口地址，不证明用户属于某个 owner node；
- 断线后可以刷新路由，不要永久缓存已失败节点；
- 开发、预发和生产必须使用独立 UID/Token、存储命名空间和入口配置；
- 所有部署都是集群，单节点集群也必须走相同路由与 Channel authority；
- 负载均衡与反向代理的空闲超时要长于有效心跳策略，且支持 WebSocket 升级。

## 生命周期所有权

| 事件 | 应用动作 |
| --- | --- |
| 前台进入 | 确认身份未过期；必要时连接或结束恢复 |
| 网络切换 | 标记 degraded，取消旧拨号，刷新路由后有界重连 |
| 后台或休眠 | 遵守平台限制；不要承诺 Socket 永久在线 |
| UID 切换 | 先停止旧身份发送并完整退出，再清理本地状态和创建新会话 |
| 显式退出 | 撤销凭据、关闭 Session、清除游标/缓存/推送绑定 |

## 完成信号

只有以下条件同时满足时才向业务层发布 ready：

- CONNACK 成功且当前 Session 没有被更新的连接尝试替代；
- 当前 UID、设备与环境仍匹配；
- 必需的持久消息恢复已经完成或明确进入可见的降级模式；
- 事件监听与本地持久层能够接收后续消息；
- 没有待处理的 logout、身份轮换或应用终止操作。

## 失败诊断

- **Socket 打开但无 CONNACK**：检查协议选择、CONNECT 首包、客户端密钥和认证队列压力。
- **能连接但不能发送**：分别检查业务权限、SENDACK Reason Code 与恢复 gate。
- **反复连到不可达地址**：停止使用旧缓存并重新发现路由。
- **同一页面出现两个会话**：收敛为一个连接所有者，并序列化 lifecycle 命令。

## 安全边界

CONNECT 协商的会话 Payload 加密不替代 TLS。路由地址、Token 和设备材料只能来自受信配置；不要接受页面参数注入任意 Gateway。
