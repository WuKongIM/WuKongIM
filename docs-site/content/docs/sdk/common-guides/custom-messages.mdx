WuKongIM 运输 Payload 字节，不定义你的订单、客服卡片、位置、通知或 AI 消息模型。自定义消息首先是业务协议设计问题，其次才是某个平台 SDK 的注册或解码 API。

<Callout type="info" title="跨 SDK 行为指南">
  本页是**跨 SDK 行为指南**，不会假设所有 SDK 都有相同的消息注册 API。当前可执行 Payload 示例仍以 [JavaScript/Web 兼容快照](/zh/sdk/compatibility)为准。
</Callout>

## 目标与完成标准

发送端和接收端即使版本不同，也能识别消息类型、验证结构、忽略未知字段，并对未知类型给出安全降级，而不是崩溃、丢失游标或显示原始敏感内容。

## 推荐信封

```json
{
  "version": 2,
  "type": "order.status.changed",
  "id": "evt_01J...",
  "occurred_at": "2026-08-27T08:30:00Z",
  "body": {
    "order_id": "o_10001",
    "status": "shipped"
  }
}
```

| 字段 | 规则 |
| --- | --- |
| `version` | 对同一 `type` 单调演进；不要用客户端版本隐式推断 Payload 结构 |
| `type` | 稳定、命名空间化；重命名视为兼容变更 |
| `id` | 业务事件幂等键，不替代 `client_msg_no` 或服务端 `message_id` |
| `occurred_at` | 业务发生时间；消息 sequence 仍决定 Channel 内顺序 |
| `body` | 只包含消费方所需字段，限制深度、数组数量和字符串长度 |

## 兼容策略

- 新增可选字段，旧客户端忽略未知字段；
- 改变字段含义或类型时升级 `version`，必要时使用新 `type`；
- 接收端为未知 `type` 显示安全占位，例如“此消息需要更新客户端”，仍保存消息身份和 sequence；
- 不要把未知消息从本地游标中跳过，否则会反复同步同一条消息；
- 灰度发布先让接收端兼容新版本，再让发送端产生新版本；
- 回滚前确认旧接收端仍能处理已提交的新 Payload。

## 编码边界

Gateway SDK 发送的是字节 Payload；Product HTTP JSON 中的 `payload` 是 Base64。不要二次 Base64 后再交给 SDK，也不要把 HTTP 示例直接复制为客户端方法参数。

对二进制协议或压缩数据，在信封中声明内容类型、版本和解压上限。解压前检查压缩后大小，解压时设置最大输出，避免压缩炸弹。

## 大消息与附件

不要把附件二进制直接塞进消息。业务服务先把文件写入受控对象存储，消息只携带短生命周期、最小权限的对象定位信息、大小、媒体类型和完整性摘要。下载仍需业务鉴权。

## 安全与隐私

- 不发送密码、Token、私钥或管理凭据；
- 对个人数据做最小化，定义保留和删除策略；
- 文本、Markdown、HTML 和富媒体都按不可信输入渲染；
- URL 使用允许列表和安全跳转，不允许 Payload 注入任意脚本或本地文件；
- 业务签名若需要端到端真实性，必须有独立密钥、版本和轮换设计，不能把 TLS 当作 Payload 签名。

## 失败诊断

- **只有某个平台解码失败**：比较实际 Payload 字节、字符集和该 SDK 版本，不要先修改服务端 Channel。
- **旧客户端崩溃**：缺少未知类型降级或发送端发布顺序错误。
- **HTTP 与 SDK 内容不同**：检查 Product HTTP Base64 边界和是否发生二次编码。
- **重试产生重复业务动作**：让业务消费者按 `id` 幂等，同时保留消息级 `client_msg_no`。
