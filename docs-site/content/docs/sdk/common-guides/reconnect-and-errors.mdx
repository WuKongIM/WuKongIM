“自动重连”不是无限循环调用 connect。可靠恢复先判断失败发生在哪个阶段，再决定刷新路由、轮换身份、复用幂等键、退避或停止。

<Callout type="info" title="跨 SDK 行为指南">
  本页是**跨 SDK 行为指南**，不假设平台 SDK 使用相同的错误类。已验证的重连与离线恢复基线见 [JavaScript/Web 兼容快照](/zh/sdk/compatibility)。
</Callout>

## 目标与完成标准

每次故障都记录低敏的阶段、当前应用状态、Reason Code 或 HTTP 状态、尝试次数和最终动作。客户端有最大退避、总恢复截止时间和用户可见降级，不会形成重连风暴。

## 先定位阶段

| 阶段 | 典型证据 | 权威动作 |
| --- | --- | --- |
| 网络 / DNS / TLS | 拨号、证书、代理或 WebSocket 升级错误 | 修复网络；有界退避，不发送业务重试 |
| 路由发现 | HTTP 状态与 endpoint-specific error | 重新登录或换受信入口；不要解析成 Reason Code |
| CONNECT | CONNACK Reason Code 或认证超时 | 认证失败停止；节点漂移刷新路由；临时压力退避 |
| SEND admission | 本地队列满、会话未 ready | 等待容量或恢复完成；尚未进入服务端提交 |
| SENDACK | Reason Code + `client_msg_no` | 按 Reason Code 分类；幂等重试复用键 |
| 消息同步 | HTTP 状态、页内 error、范围与 `more` | 保留已提交游标，只重试失败页或 unresolved |
| 业务处理 | Payload 校验、数据库或下游失败 | 使用业务幂等和队列；不要回滚 Channel 提交 |

HTTP 状态、Product HTTP JSON、CONNACK 与 SENDACK 没有一个通用 `{data,error}` 信封。先识别协议阶段，再解析该端点或数据包。

## 重连算法

1. 原子地把 Session 标为不可发送，冻结新的普通 SEND。
2. 允许当前接收处理完成或安全取消，保存最后本地提交游标。
3. 根据关闭原因判断凭据是否仍有效；认证拒绝不自动重试。
4. 对网络、route stale 或 node mismatch，重新发现入口。
5. 使用带抖动的指数退避，并设置单次拨号超时、最大间隔、最大次数和总截止时间。
6. CONNECT 成功后进入 recovering，而不是直接 ready。
7. 同步缺失的持久消息、去重并原子提交游标。
8. 只有当前重连代次仍是最新时才发布 ready，避免旧尝试覆盖新 Session。

## 建议重试分类

- `ReasonAuthFail`、成员不存在、黑白名单、封禁、解散：修复身份或业务状态后由用户/业务重新触发；
- `ReasonNodeNotMatch`：刷新路由并复用 `client_msg_no`；
- `ReasonSystemError` 或明确暂时压力：有界退避；
- 协议升级要求：停止重试并升级兼容客户端；
- 未知 Reason Code：保留原始数字，fail closed，不默认成功。

完整分类见 [Reason Code](/zh/api/dictionaries/reason-codes)。枚举中存在不代表当前每条路径都能发出该值。

## 幂等与不确定结果

如果连接在 SEND 后、SENDACK 前断开，结果是不确定，不等于失败。先在恢复同步中查找相同业务消息；确需重试时复用 `client_msg_no`。并发协议尝试使用不同非零 `client_seq`，避免迟到 ACK 完成错误 future。

SENDACK 已成功但接收端实时未见时，不发送新 `client_msg_no` 制造重复业务消息。接收端应从持久 Channel 同步恢复。

## 防止重连风暴

- 网络变化事件只触发一个连接所有者；
- 前后台切换与系统网络回调合并；
- 使用 full jitter，并限制每个进程与账号的并发拨号；
- 服务器 maintenance 或持续 503 时扩大间隔；
- UI 提供“离线 / 正在恢复 / 需要重新登录”，不要隐藏无限 spinner；
- 应用退出和显式 logout 必须取消定时器并禁止后续自动连接。

## 可观测性

记录阶段、Reason Code、SDK/服务端兼容快照、退避桶和最终状态。不要把 UID、Channel ID、`client_msg_no`、地址、Token 或完整错误 Payload 放入指标标签。详细身份只在受控、脱敏的请求日志中按需关联。

## 上线演练

至少覆盖：Wi-Fi/蜂窝切换、DNS 失败、TLS 错误、Gateway 重启、路由变更、无效/撤销 Token、同类 Master 冲突、SENDACK 丢失、同步空页、同步重叠和服务端背压。

## 安全边界

认证失败后的无限重试既是安全风险也是容量风险。Token 过期或撤销时回到业务登录，不把旧凭据发送到多个入口探测。
