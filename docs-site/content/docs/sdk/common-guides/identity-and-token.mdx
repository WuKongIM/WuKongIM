接入 WuKongIM 前，先把业务账号、协议身份和具体设备分开。业务账号仍由你的系统认证；WuKongIM 使用稳定 UID 路由用户，用 `device_flag` 表示设备类别，用 `device_id` 区分具体端点。

<Callout type="info" title="跨 SDK 行为指南">
  本页是**跨 SDK 行为指南**，不声明任何平台 SDK 的方法名。先核对 [JavaScript/Web 兼容快照](/zh/sdk/compatibility)，再把这里的行为映射到所选 SDK 的版本文档。
</Callout>

## 目标与完成标准

完成后，你应拥有一份后端控制的会话材料合同：客户端只能取得自己的 UID、设备参数、短生命周期 Token 和可用入口；不能创建任意身份、选择特权设备等级或获得 Product HTTP 管理能力。

## 身份模型

| 字段 | 集成者规则 |
| --- | --- |
| `uid` | 稳定、不可回收的业务用户 ID；不要使用昵称、手机号或可变邮箱 |
| `device_flag` | 从当前 [Device Flag](/zh/api/dictionaries/device-flags) 选择 APP、WEB 或 PC；终端不能使用 SYSTEM |
| `device_id` | 表示一次具体安装或端点；明确重装、清缓存和设备迁移后的生成策略 |
| `device_level` | 由服务端策略选择同类设备多活或单活；客户端不能自行升级为 Master |
| `token` | 高熵、短生命周期、可撤销；只通过受 TLS 保护的业务登录返回 |

## 推荐签发流程

1. 客户端先登录业务服务，业务服务检查账号、租户、设备、风险和权限。
2. 后端将业务用户映射到稳定 UID，并从自己的设备登记表选择 `device_flag`、`device_id` 与冲突策略。
3. 后端生成独立于密码、OAuth access token 和 Manager 凭据的 WuKongIM 会话 Token。
4. 只有受信服务调用用户 Token 管理入口；浏览器和移动端不直接访问 Product HTTP。
5. 客户端只获得当前会话所需材料，并把 Token 保存在平台安全存储中。
6. Gateway 完成 CONNECT 后仍需检查 CONNACK；“拿到 Token”不是“已建立会话”。

## 当前 v3 Beta 限制

`POST /user/token` 会把设备 Token 元数据写入用户用例，但默认应用组合创建 Gateway Authenticator 时没有启用 `TokenAuthOn`，也没有注入已存 Token verifier。因此：

- Token 写入成功不证明后续 CONNECT 会校验它；
- `/user/device_quit` 清空元数据并关闭匹配的本地会话，也不能单独证明攻击者无法再次 CONNECT；
- 会话加密不替代身份认证、TLS 或 Product HTTP 访问控制。

<Callout type="error" title="生产阻断项">
  如果部署仍使用默认鉴权组合，就不能把它声明为完整生产身份边界。上线前必须接入同一可信凭据来源的 Gateway 校验，并用无效、过期、撤销和跨设备 Token 做端到端拒绝测试。
</Callout>

## 轮换与撤销

- 轮换时让新 Token 与旧 Token 有明确的短暂重叠或立即失效策略；
- 先持久化撤销，再关闭现有会话，最后证明重连被拒绝；
- 按 UID、设备类别和具体设备记录审计，但不要记录明文 Token；
- 业务封禁、租户冻结和风险控制必须在可信后端或已接入的 Gateway verifier 中生效；
- 退出登录还要清除客户端本地消息、游标和推送 Token，不能只断开 Socket。

## 失败诊断

| 现象 | 先检查 |
| --- | --- |
| Token API 成功但任意 Token 都能连接 | 默认 stored-token verifier 是否仍未接入 |
| 同类设备意外互踢或共存 | `device_flag`、`device_id`、`device_level` 是否由同一后端策略产生 |
| 撤销后旧连接仍可用 | 撤销持久化、 owner-local close 与重连拒绝是否都完成 |
| 日志出现凭据 | 立即清理并轮换；Token、CONNECT Payload 和 Header 不应进入日志 |

## 安全边界

Product HTTP 必须位于私网、服务网格或有服务身份认证的反向代理之后。CORS 只是浏览器兼容行为，不是业务鉴权。
