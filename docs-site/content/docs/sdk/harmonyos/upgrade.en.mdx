## 1. Freeze the pre-upgrade baseline

Record the real toolchain and artifacts on a separate branch:

```bash
ohpm --version
ohpm list @wukong/wkim
git status --short
```

Also record DevEco Studio, HarmonyOS SDK, hvigor, build mode, signing/HAP, and device/system versions. Commit the current `oh-package.json5` and `oh-package-lock.json5`, and hash the Release HAP and lockfile.

Retain a real scenario baseline:

- `connecting → success → syncing → syncCompleted` with provider delivery;
- Alice positive local `clientSeq` and terminal SENDACK;
- Bob online receipt;
- channel history, recent conversations, unread, reactions, members, and reminder sync;
- network loss, kick, failure, timeout, and cleanup.

Find all SDK calls and deep imports:

```bash
rg -n "@wukong/wkim|WKIM\.shared|src/main/ets|sendWithOption|add.*Listener|remove.*Listener|clientMsgNo|clientSeq" entry/src test
```

The root package exports only `WKIM`. Every `@wukong/wkim/src/main/ets/...` deep import is a version migration point, not a long-term stable contract.

## 3. Audit `1.1.6 → 1.1.7`

The pinned [`wkim/CHANGELOG.md`](https://github.com/WuKongIM/WuKongIMHarmonyOSSDK/blob/0c41810a1e0a5fc2936929d63ca32a50ffb11bec/wkim/CHANGELOG.md) and the exact [`a79df83… → 0c41810…` comparison](https://github.com/WuKongIM/WuKongIMHarmonyOSSDK/compare/a79df83f2794c581096850f0f77d34b95566a9ae...0c41810a1e0a5fc2936929d63ca32a50ffb11bec) show these changes for this version edge only:

| `1.1.7` change | Migration action |
| --- | --- |
| Adds `ChannelManager.getWithFollowAndStatus` | Verify follow/status filtering, empty data, and local cache refresh |
| Adds `MessageManager.getMinMessageSeqWithChannel`, `getMaxReactionSeqWithChannel`, and `getMessageOrderSeq` | Verify history bounds, channel-aware ordering, reaction delta, uniqueness, delete, and offline sync |
| Adds `ConversationManager.updateMsgExtra`, `getWithChannel`, and `getMsgExtraWithChannel` | Compile every conversation call site and verify extra writes/queries, missing conversations, last message, unread state, and refresh events |
| Initialization calls `MessageDB.shared.updateSendingToFail()` | Start from a copied database containing sending rows and verify old unresolved sends become failed without incorrect retransmission |
| Changes synchronized-message persistence | Exercise duplicate/empty `clientMsgNo`, deleted messages, message extras, and reactions |
| Changes local SENDACK update | Check missing `messageId`/`messageSeq`, rejection codes, `orderSeq`, and same-`clientSeq` correlation |
| Changes stalled connection recovery and attempt/timer handling | Verify route timeout, provider rejection, stale addresses, socket failure, outage, and duplicate reconnect |
| Changes recent-conversation extra/message queries | Check last message, extras, unread, delete, and refresh ordering |
| Adds direct `hilog.info` send traces | Scan final Release logs; `WKLogger.setShowLog(false)` does not disable these traces |

There is no source evidence that these additions remove an old call signature, so do not invent rename steps. Even applications that do not call the new queries directly should regress history paging, local order, conversation extras, and reactions because managers use related semantics internally.

## 4. Audit root exports and deep imports

`1.1.7` root `index.ets` still exports only:

```typescript
export { WKIM } from './src/main/ets/WKIM'
```

Audit individually:

- `WKChannel`, `WKConnectStatus`, `WKMsg`, and `WKSendOptions` from `entity/Bean`;
- `model/WKTextContent` and every explicitly registered image/voice/video/custom content;
- `common/WKLogger`;
- any application import into manager/db/protocol internals;
- deep-path effects on final sourcemaps, obfuscation, signing, and license handling.

If a later version moves these files, prefer a stable root export or a reviewed adapter. Do not copy HAR source into the application merely to make compilation pass and lose distribution identity.

## 5. Treat local state as irreversible

The pinned SDK opens `${uid}.db` in `RelationalStore` with `securityLevel: S1` and `encrypt: false`, and stores UID-scoped migration version in Preferences. Rawfile SQL runs forward. There is no published reverse migration or **downgrade contract** proving the old SDK can read new state.

Before upgrading:

1. retain a redacted **database snapshot** and matching Preferences for every test UID;
2. upgrade copies and inspect messages, conversations, extras, reactions, channels, members, reminders, search, and unread;
3. inject database-open, SQL, low-disk, and process-termination failures; the helper swallows some errors, so the application must detect data availability;
4. record post-upgrade schema/migration version;
5. restore pre-upgrade database and Preferences or use an isolated fresh install for rollback instead of opening upgraded state blindly with the old HAR.

## 6. Compile and accept in a real DevEco environment

Complete the pinned install first:

```bash
ohpm install
ohpm list @wukong/wkim@1.1.7
```

Then run static checks, tests, Release HAP, signing, and installation through the project's pinned DevEco/hvigor entry. Commands vary by hvigor version and must come from the consuming repository's reproducible workflow; this site cannot claim an unexecuted command passed.

Acceptance covers at least:

- API 20, `default` / `tablet`, and merged INTERNET/GET_NETWORK_INFO permissions;
- compilation of every deep import and custom content;
- provider success, rejection, timeout, and stale completion;
- same-function-object listener removal and no page overwrite of the `addInsertedListener` single slot;
- Alice positive `clientSeq`, same-sequence `WKSendMsgResult.success`, and Bob online receipt;
- `getWithFollowAndStatus`, the three new Message queries, `updateMsgExtra` / `getWithChannel` / `getMsgExtraWithChannel`, and real history/conversation synchronization;
- high concurrent traffic, outage, route failure, kick, background/foreground, and process termination;
- no Token, Payload, or disallowed high-cardinality identifier in Release logs.

## 7. Preserve security blockers

Upgrading to `1.1.7` does not automatically fix:

- raw `TCPSocket` without authenticated TLS;
- default `WKLogger` output and two direct `hilog.info` send traces;
- the `encrypt: false` local database and migration state stored separately in Preferences;
- swallowed database-open errors;
- retained `sendingMsgMap` after SENDACK/logout;
- providers, inserted callback, and some listeners without a complete reset;
- unobfuscated HAR, package hygiene, and template-only ohosTest.

Completion, failure, timeout, kick, uncertain SENDACK, or UID change requires a **process restart**. Relax that policy only after upstream fixes and independent transport, storage, device, and runtime receipts.

## 8. Roll out and roll back

Bind HAR version/hash/integrity, `oh-package-lock.json5` digest, DevEco/SDK/ohpm/hvigor, HAP/signing, device/system, server revision, and Alice/Bob result as one release unit. Start with internal users or a small cohort and observe stalled connections, reconnect, SENDACK reasons, duplicates/loss, conversation/database behavior, reactions, and logging leaks.

Rollback restores `oh-package.json5`, lockfile, old HAR, application deep-import code, and the pre-upgrade database/Preferences snapshot, then reruns the old scenarios. Changing only the dependency number is not recoverability evidence.
