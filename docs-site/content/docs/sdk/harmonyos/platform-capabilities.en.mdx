## Export boundary

Root `index.ets` **exports only `WKIM`**:

```typescript
import { WKIM } from '@wukong/wkim'
```

`WKChannel`, `WKConnectStatus`, `WKMsg`, `WKSendOptions`, `WKTextContent`, and `WKLogger` require deep imports into `src/main/ets/...` in the HAR. Legacy topics can inform learning order, but these deep imports are not a stable root API contract. Recompile and audit every deep path during an upgrade.

## Capability matrix

| Topic | Pinned `1.1.7` source surface | Application responsibility |
| --- | --- | --- |
| Initialization | `await WKIM.shared.init(uid, token, address, context)` process singleton | Trusted backend issues short-lived identity; pass explicit application `Context`; one UID per process |
| Connection | `ConnectionManager.connection()`, `disConnection(bool isLogout)`, status listeners | DNS/IPv4 `host:port`, timeout, terminal policy, and connection-generation fencing |
| Channels | `WKChannelType.personal`, `group`, plus customer-service, community, and topic constants | Server authorization, product semantics, and cross-client receipt per adopted type |
| Content | `WKTextContent` and `WKImageContent` are registered by default | Fixed content type, unknown-content handling, and cross-platform schema |
| Other media models | HAR also contains `WKVoiceContent`, `WKVideoContent`, and `WKMediaMessageContent` | They are not default-registration proof; register them, wire `uploadAttachmentCallback`, and verify permission/upload/recovery |
| Custom content | `registerMsgContent` and `WKMessageContent` | Unique type and identical encode/decode implementation on every client |
| Send | `sendWithOption`, local insertion, and send-status listeners | Separate durable insertion, terminal SENDACK, and Bob online receipt |
| History and extras | Local queries, `syncMessageCallback`, message extras, and reactions | Business-backend pagination, deduplication, authorization, idempotency, and errors |
| Conversations | `ConversationManager` and `syncConversationCallback` | Complete conversation/recent/unread/version mapping; no empty provider masquerading as production sync |
| Channels and members | `ChannelManager`, `ChannelMemberManager`, profile and member providers | Member pagination and order/dedup/capacity design for 100,000-member groups |
| Reminders and CMD | `ReminderManager`, `CMDManager` | Business data, authorization, idempotency, and product handling |
| Local state | HarmonyOS `RelationalStore` and Preferences | Encryption, backup, erasure, identity switching, migration, and recovery |

## Lifecycle and ownership

`WKIM.shared` and all managers are process singletons. `init` opens the UID database and marks old sending rows failed, but database-open errors are logged and swallowed. A fulfilled Promise does not prove storage is usable.

The connection sequence is `connecting → success → syncing → syncCompleted`. `success` is CONNACK only. The SDK can reach `syncCompleted` without `syncConversationCallback`, so the application must observe both provider delivery and matching-activation `syncCompleted` before enabling send.

- Connection, send-status, new-message, channel, member, conversation, reminder, and CMD listeners are arrays; removal requires the **same function object**.
- `MessageManager.addInsertedListener` is a **single slot** with no remove API; later registration overwrites it.
- `WKProvider` fields are shared process state and belong to one application dispatcher.
- `sendWithOption` returns `void`. Durable text writes locally and invokes insertion before send; wait separately for `WKSendMsgResult.success`.
- A positive `clientSeq` is durable-insert evidence. Pinned source can still dispatch a packet when `clientSeq === 0`; a later ACK cannot rewrite that as local durability.

## Platform integration ownership

- Pass application `Context` from `UIAbility` or an application container rather than the deprecated global `getContext()` fallback.
- Confirm `ohos.permission.INTERNET` and `ohos.permission.GET_NETWORK_INFO` in the final merged module.
- `default` / `tablet` declarations do not verify phone, foldable, tablet, multi-window, or foreground/background behavior.
- Notifications, background survival, system accounts, multi-device, file picker, camera, microphone, and media cache are not complete product flows in this HAR.
- The UniApp repository is deprecated and must not be described as a current standalone HarmonyOS SDK.

## Production blockers

- [`ConnectionManager`](https://github.com/WuKongIM/WuKongIMHarmonyOSSDK/blob/0c41810a1e0a5fc2936929d63ca32a50ffb11bec/wkim/src/main/ets/manager/ConnectionManager.ets) uses raw `TCPSocket` without authenticated TLS. WKProto Payload encryption does not replace TLS.
- Route parsing uses `split(":")`; it accepts one DNS/IPv4 `host:port`, not a URI or IPv6 literal.
- `WKLogger.showLog` defaults on and can log outbound JSON Payload. Two direct `hilog.info` traces remain even after disabling `WKLogger`.
- `WKConfig.debug` is not read by pinned source and is not an effective log gate.
- UID data is stored in `RelationalStore` with `securityLevel: S1` and `encrypt: false`; device/migration state lives in Preferences.
- Database-open and some migration failures are logged but not propagated, so execution can continue.
- `sendingMsgMap` packets are not reliably removed after SENDACK or logout; providers, the inserted callback, and some listeners also lack a complete reset contract.
- The HAR is `obfuscated: false`, contains `.DS_Store`, and the repository ohosTest is only a template assertion.

These blockers mean completion, failure, timeout, network loss, kick, uncertain send, or identity change requires a **process restart** until upstream exposes and verifies a safe reset.

## Minimum adoption acceptance

- Pin package, HAR SHA, integrity, source revision, and `oh-package-lock.json5`.
- Compile, sign, and install a Release HAP with the real DevEco/HarmonyOS SDK/ohpm/hvigor tuple.
- Verify permissions, foreground/background behavior, network switching, and listener cleanup on each real device/system.
- Record Alice provider gate, positive local `clientSeq`, terminal SENDACK, and Bob online receipt separately.
- Exercise real conversations/history, media, reminders, reactions, offline, push, multi-device, and high load.
- Fix or explicitly accept TLS, logging, `encrypt: false`, database error propagation, `sendingMsgMap`, deep-import, and package-hygiene risks.

Use the [HarmonyOS API Reference](/en/sdk/harmonyos/api-reference) for exact entry points, then follow the [Upgrade Guide](/en/sdk/harmonyos/upgrade) before replacing an existing HAR.
