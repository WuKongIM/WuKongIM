## 导出边界

包根 `index.ets` **只导出 `WKIM`**：

```typescript
import { WKIM } from '@wukong/wkim'
```

`WKChannel`、`WKConnectStatus`、`WKMsg`、`WKSendOptions`、`WKTextContent` 和 `WKLogger` 必须从 HAR 内的 `src/main/ets/...` 做 deep import。旧站的主题可以帮助安排学习顺序，但不能把这些深路径描述为稳定 root API。每次升级都必须重新编译并审计深路径。

## 生命周期与所有权

`WKIM.shared` 与所有 manager 都是进程单例。`init` 打开 UID 数据库并把早先 sending 行标为失败，但数据库打开错误被记录后吞掉；fulfilled Promise 不能证明存储已可用。

连接状态顺序是 `connecting → success → syncing → syncCompleted`。`success` 只代表 CONNACK；如果 `syncConversationCallback` 缺失，SDK 仍会进入 `syncCompleted`。应用必须同时观察本次 provider 已交付与同一 activation 的 `syncCompleted` 才开放发送。

- 连接、发送状态、新消息、频道、成员、会话、提醒和 CMD listener 是函数数组；移除时必须使用**相同函数对象**；
- `MessageManager.addInsertedListener` 是一个**单槽位**，没有 remove API，后注册覆盖前者；
- `WKProvider` 字段也是共享进程状态，应由应用级 dispatcher 一次安装；
- `sendWithOption` 返回 `void`。持久文本先写库、触发 inserted callback，再发送；网络结果必须另等 `WKSendMsgResult.success`；
- 正数 `clientSeq` 才是持久插入证据；固定源码在 `clientSeq === 0` 时仍可能发包，不能把随后 ACK 改写成本地持久成功。

## 平台集成责任

- 从 `UIAbility` 或应用容器传入 application `Context`；不要依赖已弃用的全局 `getContext()` fallback；
- 在最终 merged module 中确认 `ohos.permission.INTERNET` 与 `ohos.permission.GET_NETWORK_INFO`；
- `default` / `tablet` 是 module 声明，不是手机、折叠屏、平板、多窗口、前后台行为已经验证；
- 通知、后台保活、系统帐号、多设备、文件选择、相机、麦克风和媒体缓存都不由当前 HAR 提供完整产品流程；
- UniApp 仓库已 deprecated，不能把它描述为当前独立 HarmonyOS SDK。

## 生产阻断项

- [`ConnectionManager`](https://github.com/WuKongIM/WuKongIMHarmonyOSSDK/blob/0c41810a1e0a5fc2936929d63ca32a50ffb11bec/wkim/src/main/ets/manager/ConnectionManager.ets) 使用 `TCPSocket` 原始 TCP，没有认证 TLS；WKProto Payload 加密不能替代 TLS。
- 地址用 `split(":")` 解析，只接受一个 DNS/IPv4 `host:port`，不是 URI 或 IPv6 literal。
- `WKLogger.showLog` 默认开启，发送 JSON 可能包含 Payload；即使关闭 `WKLogger`，仍有两个直接 `hilog.info` trace。
- `WKConfig.debug` 在固定源码中没有被读取，不能当成有效日志门禁。
- UID 数据存进 `securityLevel: S1`、`encrypt: false` 的 `RelationalStore`；设备/迁移状态在 Preferences。
- 数据库打开与部分 migration 错误只记日志，调用方可能仍继续运行。
- `sendingMsgMap` 的包不会在 SENDACK 或 logout 后可靠移除，provider、inserted callback 与部分 listener 也没有完整重置合同。
- HAR `obfuscated: false`，包含 `.DS_Store`，仓库 ohosTest 只有模板断言。

这些阻断项意味着完成、失败、超时、断网、kick、不确定发送或换号后都应要求**进程重启**，直到上游提供并验证安全重置。

## 采用前最小验收

- 固定 package、HAR SHA、integrity、source revision 与 `oh-package-lock.json5`；
- 在实际 DevEco/HarmonyOS SDK/ohpm/hvigor tuple 编译、签名并安装 Release HAP；
- 在每个实际设备/系统组合验证权限、前后台、网络切换和 listener 清理；
- 分别记录 Alice provider 门禁、本地正数 `clientSeq`、终止 SENDACK 和 Bob 在线接收；
- 验证真实会话/历史、媒体、提醒、reaction、离线、推送、多设备和高负载；
- 修复或明确接受 TLS、日志、`encrypt: false`、数据库错误传播、`sendingMsgMap`、深路径与 package hygiene 风险。

用 [HarmonyOS API 参考](/zh/sdk/harmonyos/api-reference)查找精确入口；替换既有 HAR 前按[升级指南](/zh/sdk/harmonyos/upgrade)保留数据库和回滚证据。
