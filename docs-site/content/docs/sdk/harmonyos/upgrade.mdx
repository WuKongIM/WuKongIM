## 1. 冻结升级前基线

在独立分支记录实际工具链和产物：

```bash
ohpm --version
ohpm list @wukong/wkim
git status --short
```

同时保存 DevEco Studio、HarmonyOS SDK、hvigor、build mode、签名/HAP、设备/系统版本，提交当前 `oh-package.json5` 与 `oh-package-lock.json5`，并计算 Release HAP 与 lockfile digest。

保存一份真实场景基线：

- `connecting → success → syncing → syncCompleted`，且 provider 已交付；
- Alice 本地正数 `clientSeq` 与终止 SENDACK；
- Bob 当前在线接收；
- 频道历史、最近会话、未读、reaction、成员与提醒同步；
- 断网、kick、失败、超时和清理。

搜索全部 SDK 调用与 deep import：

```bash
rg -n "@wukong/wkim|WKIM\.shared|src/main/ets|sendWithOption|add.*Listener|remove.*Listener|clientMsgNo|clientSeq" entry/src test
```

根 package 只导出 `WKIM`。任何 `@wukong/wkim/src/main/ets/...` deep import 都是版本迁移点，不是长期稳定 contract。

## 2. 精确安装并核对 lockfile

在应用 `oh-package.json5` 中写精确依赖：

```json5
{
  "dependencies": {
    "@wukong/wkim": "1.1.7"
  }
}
```

不要使用 `latest`、范围或 Git `main`。重新安装并检查解析结果：

```bash
ohpm install
ohpm list @wukong/wkim@1.1.7
git diff -- oh-package.json5 oh-package-lock.json5
```

提交 `oh-package-lock.json5`，确认 resolved URL 指向：

```text
https://repo.harmonyos.com/ohpm/@wukong/wkim/-/wkim-1.1.7.har
```

lockfile 的 integrity 必须与本页固定值一致。不同 ohpm 版本的排版可能不同，因此发布门禁同时核对 version、resolved、integrity 与下载后 SHA-256，而不是只搜索字符串 `1.1.7`。

## 3. 审计 `1.1.6 → 1.1.7`

固定 [`wkim/CHANGELOG.md`](https://github.com/WuKongIM/WuKongIMHarmonyOSSDK/blob/0c41810a1e0a5fc2936929d63ca32a50ffb11bec/wkim/CHANGELOG.md) 和 [`a79df83… → 0c41810…` 精确比较](https://github.com/WuKongIM/WuKongIMHarmonyOSSDK/compare/a79df83f2794c581096850f0f77d34b95566a9ae...0c41810a1e0a5fc2936929d63ca32a50ffb11bec)给出这些目标变化；它们只适用于这条版本边：

| `1.1.7` 变化 | 迁移动作 |
| --- | --- |
| `ChannelManager.getWithFollowAndStatus` 新增 | 检查频道 follow/status 过滤、空数据和本地缓存刷新 |
| `MessageManager.getMinMessageSeqWithChannel`、`getMaxReactionSeqWithChannel`、`getMessageOrderSeq` 新增 | 验证历史上下界、带频道排序、reaction 增量、唯一性、删除与离线同步 |
| `ConversationManager.updateMsgExtra`、`getWithChannel`、`getMsgExtraWithChannel` 新增 | 编译所有会话调用点，验证 extra 写入/查询、缺失会话、最后消息、未读和刷新事件 |
| 初始化调用 `MessageDB.shared.updateSendingToFail()` | 用升级前含 sending 行的数据库副本启动，确认旧未决发送变为 failed 且不会错误重发 |
| 同步消息持久化调整 | 用重复/空 `clientMsgNo`、已删除消息、message extra 和 reaction 运行历史同步 |
| SENDACK 本地更新调整 | 检查 `messageId`/`messageSeq` 缺失、拒绝码、`orderSeq` 与同一 `clientSeq` 关联 |
| 连接停滞恢复与 attempt/timer 调整 | 验证路由超时、provider reject、陈旧地址、socket 失败、断网和重复 reconnect |
| 最近会话 extra / message 查询调整 | 检查会话最后消息、extra、未读、删除与刷新顺序 |
| 新增直接 `hilog.info` 发送 trace | 日志门禁必须扫描最终 Release；`WKLogger.setShowLog(false)` 不会关闭这些 trace |

这些新增方法没有移除旧调用签名的证据；不要发明重命名步骤。即使应用没有直接调用新查询，也要回归历史分页、本地排序、会话 extra 与 reaction，因为 manager 内部会使用相关语义。

如果起始版本早于 `1.1.6`，至少复核 changelog 中的这些边界：

| 版本 | 上游记录 | 必做检查 |
| --- | --- | --- |
| `1.0.6–1.0.7` | 修复 `clientMsgSeq` 与 SENDACK 本地状态 | 本地正数序号、ACK 关联和失败状态 |
| `1.0.9` | 大量收发稳定性与每次连接重新生成密钥 | 并发、重连与协议互操作 |
| `1.1.0–1.1.1` | 附件上传结果和正文更新 | 上传成功/失败、数据库内容与跨端解码 |
| `1.1.2` | 数据库 migration version 改为 UID 作用域 | 多账号数据库与 Preferences 一起迁移、备份和擦除 |
| `1.1.3` | 升级 SDK 6.0 并调整数据库异常 | 用实际 API 20/DevEco tuple 重编译并注入存储失败 |
| `1.1.5` | 未连接时缓存发送 | 断网队列、重发、logout 与账号隔离 |
| `1.1.6` | 查询排序修复 | 历史、会话、reaction 的升降序和分页边界 |
| `1.1.7` | 关注频道、reaction seq、持久化与连接恢复 | 按上表建立目标场景 |

Changelog 是上游意图，不是兼容性保证。从实际 lockfile 版本到固定 revision 做完整 diff；不要跨过未知版本直接套用示例。

## 4. 审计 root 导出与 deep import

`1.1.7` 的 `index.ets` 仍只导出：

```typescript
export { WKIM } from './src/main/ets/WKIM'
```

因此要逐个核对：

- `entity/Bean` 中的 `WKChannel`、`WKConnectStatus`、`WKMsg`、`WKSendOptions`；
- `model/WKTextContent` 以及任何显式注册的图片/语音/视频/自定义正文；
- `common/WKLogger`；
- 应用是否直接导入 manager/db/protocol 内部路径；
- Deep path 是否进入最终 sourcemap、混淆、签名与 license 流程。

如果新版本移动这些文件，优先等待稳定 root export 或使用受评审 adapter；不要靠复制 HAR 内源码让编译“暂时通过”而丢失版本证据。

## 5. 把本地状态当作不可逆边界

固定 SDK 为每个 UID 打开 `${uid}.db`，在 `RelationalStore` 使用 `securityLevel: S1` 与 `encrypt: false`，并把 UID 作用域 migration version 存在 Preferences。SQL 按 rawfile 列表前向执行；没有发布反向 migration 或旧 SDK 可读取新状态的**降级契约**。

升级前：

1. 保存每个测试 UID 的脱敏**数据库快照**和匹配 Preferences；
2. 在副本上升级，检查消息、会话、extra、reaction、频道、成员、提醒、搜索与未读；
3. 注入数据库打开、SQL、磁盘空间和应用终止失败；helper 会吞掉部分错误，必须从业务层检测数据可用性；
4. 记录升级后的 schema/migration version；
5. 回滚恢复升级前数据库与 Preferences，或使用隔离新安装，不让旧 HAR 盲目打开升级状态。

## 6. 在真实 DevEco 环境编译与验收

先完成锁定安装：

```bash
ohpm install
ohpm list @wukong/wkim@1.1.7
```

然后用项目固定的 DevEco/hvigor 入口运行静态检查、test、Release HAP、签名和安装。命令与 hvigor 版本有关，应以应用仓库记录的可复现命令为准；本站不能宣称某条未执行命令已通过。

验收至少覆盖：

- API 20、`default` / `tablet`、merged INTERNET/GET_NETWORK_INFO 权限；
- 所有 deep import 与自定义正文编译；
- provider 成功、reject、timeout 和陈旧 completion；
- listener 使用相同函数对象移除，`addInsertedListener` 单槽位不被页面覆盖；
- Alice 正数 `clientSeq`、同序号 `WKSendMsgResult.success`、Bob 在线接收；
- `getWithFollowAndStatus`、三个新增 Message 查询、`updateMsgExtra` / `getWithChannel` / `getMsgExtraWithChannel` 与真实历史/会话同步；
- 大量收发、断网、路由失败、kick、后台/前台和进程终止；
- Release 日志中没有 Token、Payload 或不允许的高基数标识。

## 7. 保留安全阻断

升级到 `1.1.7` 不会自动解决：

- `TCPSocket` 原始 TCP 无认证 TLS；
- `WKLogger` 默认日志和两个直接 `hilog.info` send trace；
- `encrypt: false` 本地数据库，以及另存于 Preferences 的迁移状态；
- 数据库打开错误被吞掉；
- `sendingMsgMap` 在 SENDACK/logout 后残留；
- provider、inserted callback 和部分 listener 缺少完整 reset；
- 未混淆 HAR、package hygiene 和模板级 ohosTest。

完成、失败、超时、kick、不确定 SENDACK 或 UID 切换后都要求**进程重启**。只有上游修复并取得独立 transport、storage、device 和 runtime receipt 后，才能放宽该策略。

## 8. 灰度与回滚

把 HAR version/hash/integrity、`oh-package-lock.json5` digest、DevEco/SDK/ohpm/hvigor、HAP/signing、设备/系统、服务端 revision 与 Alice/Bob 结果绑定成一个发布单元。先对内部或小 cohort 灰度，观察连接停滞、重连、SENDACK 原因、重复/丢失、会话/数据库、reaction 与日志泄漏。

回滚同时恢复 `oh-package.json5`、lockfile、旧 HAR、应用代码 deep import，以及升级前数据库/Preferences 快照，再跑旧场景。只把依赖号改回去不是可恢复性证明。
