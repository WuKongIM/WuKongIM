WuKongEasySDK 面向只需要实时通信能力、希望自己维护界面和业务状态的应用。它通过 WebSocket JSON-RPC 连接 WuKongIM Gateway，把第一次接入收敛为四件事：取得连接材料、初始化 SDK、监听事件、发送一条消息。

<Callout type="warn" title="源码校对不等于本站运行验证">
  本组教程按四个官方仓库的精确发布 tag 与源码 revision 校对，并与当前服务端 JSON-RPC 结构核对；本站没有为这些 EasySDK 版本签发可执行兼容性凭据。当前唯一具有本站完整客户端场景证据的仍是[版本与兼容性](/zh/sdk/compatibility)中记录的 WuKongIMJSSDK Web 黄金路径。
</Callout>

<Callout type="error" title="当前 v3 还不能直接运行这条路径">
  Product Gateway 当前不支持将 EasySDK 的 JSON-RPC CONNECT 用作客户端接入路径，因此这组教程继续保持“规划中”，不进入搜索、Sitemap 或兼容性凭据。下文是对固定源码的接入说明，不是当前服务端的可用性承诺。
</Callout>

“5 分钟”描述的是阅读路径：安装、初始化、监听、连接和发送。它不是完成时间承诺，也不包含业务账号、授权、群成员、离线同步、推送、容量与上线验收。

## EasySDK 负责什么

| EasySDK 当前源码提供 | 仍由你的应用负责 |
| --- | --- |
| WebSocket 建连与 JSON-RPC CONNECT | 产品登录、UID 分配、Token 签发和撤销 |
| 单聊或群聊 Channel 的消息发送 | 好友、群成员、权限、内容安全和业务回执 |
| 连接、断开、消息、错误等事件 | 页面状态、消息展示、持久化和未知消息降级 |
| 发送结果与实时消息接收 | 离线消息同步、会话与未读、推送和多设备策略 |
| 有界自动重连能力 | TLS/WSS、限流、容量、监控、升级与回滚证据 |

EasySDK 不是聊天 UI，也不是完整产品后端。`send` 返回表示服务端对本次发送给出了结果；它不等于对方已经在线收到、已经展示或已经处理。继续阅读[消息收发](/zh/sdk/common-guides/messaging)，把发送确认、实时接收和业务完成分开建模。

## 同一流程，不同的生命周期归属

| 任务 | iOS | Android | Flutter | Web |
| --- | --- | --- | --- | --- |
| 创建与初始化 | 应用级 `WuKongEasySDK` 实例 | 进程单例 `getInstance()` + `init` | 应用级单例 + `init` | 每个身份/浏览器上下文一个 `WKIM` 实例 |
| 监听器归属 | 保存 `EventListener` token | 保存同一个 listener 对象 | 保存同一个回调引用 | `on` / `off` 使用同一个函数引用 |
| 连接就绪 | `onConnect` 后才启用发送 | `CONNECT` 后才启用发送 | `connect` 事件后才启用发送 | `Connect` 事件后才启用发送 |
| 退出账号 | 移除 token 并 `disconnect` | 由进程/账号 owner 移除监听并断开 | 移除监听、`disconnect` 并 `dispose` | `off` 后 `destroy` |

页面可以订阅状态，但不应因为页面重建而创建第二个连接。各平台页面分别说明“谁创建、谁清理”，但不规定应用的 UI 架构。

## 开始前准备连接材料

客户端不应该自己授予身份。用户先登录你的产品，受信业务后端再返回本次连接所需的最小材料：

```json
{
  "uid": "alice",
  "token": "short-lived-token",
  "websocketUrl": "wss://im.example.com/ws"
}
```

- `uid` 是产品中的稳定用户标识；
- `token` 应短期、可撤销，且不能授予 Product HTTP 管理权限；
- `websocketUrl` 来自部署配置或后端调用 `/route` 后的安全选择；
- 生产环境使用 `wss://`，并让反向代理正确支持 WebSocket Upgrade。

先完成[身份与 Token](/zh/sdk/common-guides/identity-and-token)。当前默认 v3 Beta 组合不会因为 `/user/token` 保存成功就自动获得生产级 CONNECT 校验；部署必须接入可信验证器并证明无效、过期和撤销 Token 会被拒绝。

<Callout type="info" title="设备类型已经统一，业务代码仍应使用枚举">
  这四个固定版本都采用 [设备字典](/zh/api/dictionaries/device-flags)中的同一组线路值：APP `0`、WEB `1`、PC `2`。移动端使用 `.app` / `APP`，浏览器默认使用 WEB；不要在业务代码中复制整数。设备值已对齐不代表其余协议形态已兼容，iOS 与 Android 仍有各自教程列出的 Payload 或字段问题。
</Callout>

<Callout type="error" title="先关闭 SDK 敏感日志再进入生产">
  当前四个平台的固定源码都存在可能泄露 Token 或 Payload 的日志路径：Android `v1.0.3` 的部分解析错误日志不受 `debugLogging` 控制，iOS `v1.0.3` 的 JSON 日志配置开关没有真正拦截输出，Flutter `v1.0.4` 与 Web `v2.0.2` 会记录完整请求或响应。各平台教程列出了具体边界。完成修复、构建产物复核与脱敏测试前，不得通过生产门禁。
</Callout>

## 用 Alice 和 Bob 验收

每个平台都采用同一个最小闭环：

1. 为 Alice 和 Bob 分别取得 UID、短期 Token 与 WebSocket 地址；
2. 建立两个独立 SDK 实例或两个独立应用进程；
3. 两端都观察到连接成功后，Alice 向 Bob 的个人 Channel 发送文本 Payload；
4. Alice 记录发送结果中的消息 ID、序号和 Reason Code（若该 SDK 暴露）；
5. Bob 独立观察实时消息事件，并按 `messageId` 去重；
6. 反向由 Bob 向 Alice 发送，再验证一次；
7. 页面、Activity、Widget 或应用退出时移除监听器并断开连接。

这个闭环只证明当前环境的连接和在线消息。离线恢复、会话、推送、多设备、重连边界和生产安全仍要单独验收。
