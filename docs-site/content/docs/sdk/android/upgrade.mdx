本页给出“如何安全迁移到本文档固定快照”的流程，不提供未经上游证明的逐版本 changelog。目标是：升级前知道当前状态，升级后能重现依赖和验收，失败时不会拿未知数据库或未决发送做盲目降级。

<Callout type="warn" title="证据状态">
  目标快照的源码与 AAR 已校对，但**不是本站 Android 运行验证**。本站没有替你的应用执行 Gradle 构建、R8、数据库迁移、设备消息环或回滚演练；这些结果也不在 JavaScript/Web 的 `compatibility.json` 中。
</Callout>

## 目标快照

| 组成 | 固定值 |
| --- | --- |
| 依赖 | `com.github.WuKongIM:WuKongIMAndroidSDK:1.5.5` |
| tag / revision | `1.5.5` / `662a559a50d181540a0448454beb57e939b0c50e` |
| AAR SHA-256 | `5a797f1fac53c4fbcf015afca2686ecbeebd24b5e64dea598881b814b1322792` |
| Android/JVM | min 21、compile/target 34、Java/JVM 17 |

版本来源以依赖声明、`gradle.lockfile`、JitPack revision 与 `verification-metadata.xml` 为准。`WKIM.getVersion()` 仍返回 `V1.5.0`，源码的本地 Maven publication 仍写 `1.0.7`；二者都不能证明安装了 `1.5.5`。

## 版本历史能证明什么

官方[标签列表](https://github.com/WuKongIM/WuKongIMAndroidSDK/tags)显示从 `1.0.x`、`1.1.x`、`1.2.x`、`1.3.x`、`1.4.x` 到 `1.5.0`–`1.5.5` 的源码快照。目标 tag 指向固定 revision，但 `1.5.5` 仓库根目录没有一份可据此发布的完整 changelog。

### `1.5.4` → `1.5.5` 的精确源码 diff

官方 [`1.5.4...1.5.5` compare](https://github.com/WuKongIM/WuKongIMAndroidSDK/compare/1.5.4...1.5.5)固定了两个端点：`1.5.4` revision `65493fa7368636784981ff6b0ce8886769537d85` 与 `1.5.5` revision `662a559a50d181540a0448454beb57e939b0c50e`。这个 compare 只有 [`WKIMApplication.java`](https://github.com/WuKongIM/WuKongIMAndroidSDK/blob/662a559a50d181540a0448454beb57e939b0c50e/wkim/src/main/java/com/xinbida/wukongim/WKIMApplication.java) 的 7 行新增：

- `isNetworkConnected()` 在 `Build.VERSION_CODES.O`（Android 8.0）或 `Build.VERSION_CODES.O_MR1`（Android 8.1）上改走 `getActiveNetworkInfo()`，并以 `NetworkInfo.isConnected()` 的结果判断连通；源码注释把原因限定为部分 VPN 实现没有给活动网络附加 `INTERNET` capability；
- 其他 Android 6.0 及以上版本仍走 `NetworkCapabilities.NET_CAPABILITY_INTERNET`；Android 6.0 以下原有的 `NetworkInfo` 路径没有变化；
- 分支只检查系统版本，不检查 VPN transport。因此 Android 8.0/8.1 的非 VPN 活动网络也走同一 fallback，验收必须同时覆盖 VPN 和非 VPN；
- 该 compare 中**公开 Java 签名没有变化**（no public Java signature changes）：没有公开类、方法名、参数或返回类型的 diff。这个结论只描述这两个 tag 的 Java 源码 diff，不替代 AAR 编译、依赖或运行兼容性验证。

这是**源码 diff 事实，不是运行认证**，也不能外推成任意 VPN 提供方、设备或 Android 版本已经通过验证。升级 `1.5.4` 的应用应把以下定向用例加入自己的精确设备/系统/VPN/服务端 tuple：

| 维度 | 定向用例 | 保存的证据 |
| --- | --- | --- |
| VPN | 分别在 Android 8.0 与 Android 8.1 上让目标 VPN 连接、断开，再连接 | `getActiveNetworkInfo()` 是否存在及连接状态、`noNetwork`/`connecting`/最终接受状态、VPN 实现和版本 |
| 非 VPN | 在 Android 8.0/8.1 分别测试 Wi-Fi 与蜂窝网络的在线/离线 | 确认版本限定 fallback 没有把普通活动网络误判为在线或离线 |
| 网络切换 | 在已接受会话中执行 Wi-Fi ↔ 蜂窝、非 VPN ↔ VPN 切换 | 每个 attempt 的状态序列、旧回调隔离、重复连接和消息重复/丢失信号 |
| 重连 | 断网恢复、VPN 重新建立和切换后等待新的最终接受状态 | 重连耗时、超时、二次 `connecting`、`fail`/`noNetwork` 与 activation epoch |
| 消息验收 | 每种网络路径在连接接受后执行 Alice → Bob 文本消息 | Alice 本地入库、终止 `send_success` SENDACK、Bob 单次在线接收及 `clientMsgNO`/`messageID` 关联 |

这些用例应另含至少一个非 Android 8.x 控制设备，确认未修改的 capability 路径；单个 tuple 通过后，结论仍只属于该 tuple。

因此本页遵守两条规则：

1. tag 存在只证明该源码快照存在；**没有发布说明就不推断变更**；
2. 迁移判断来自旧/新应用实际使用的 API diff、构建结果、数据库副本和运行场景，不能根据版本号猜测兼容性。

旧站 [Android 集成指南](https://docs.githubim.com/zh/sdk/wukongim/android/integration)仅作为“依赖、初始化、连接、消息、频道、会话”的检查顺序参考。它的浮动 `version`、旧仓库配置和手工旧依赖不能复制进本次升级。

## 1. 冻结升级前基线

在改依赖前保存一份可审计清单：

- 当前坐标、解析后的依赖图、`gradle.lockfile` 和 `verification-metadata.xml`；
- AGP、Gradle、JDK、Kotlin、compile/target/min SDK 与 ABI；
- Debug 与 minified Release 的构建命令和结果；
- 当前用户数据库 schema/迁移索引的脱敏副本，以及数据保留/擦除要求；
- 当前注册的 route、conversation/channel sync、media provider 与 listener key；
- Alice/Bob 连接、SENDACK、在线接收、离线同步、登出/换号和失败路径结果。

不要导出 token、明文消息或 Product HTTP 管理凭据到日志或工单。

## 2. 只修改精确依赖并刷新校验

```kotlin
dependencies {
  implementation("com.github.WuKongIM:WuKongIMAndroidSDK:1.5.5")
}
```

在受控环境重新解析依赖，确认 JitPack 指向 revision `662a559a50d181540a0448454beb57e939b0c50e`。更新依赖锁后，按团队流程重新生成并审核 `verification-metadata.xml`，确保 AAR SHA-256 仍为 `5a797f1fac53c4fbcf015afca2686ecbeebd24b5e64dea598881b814b1322792`，然后以 strict 模式构建。

依赖锁定只固定版本选择；checksum verification 才约束下载 bytes。二者都要进入代码评审。

## 3. 校正 API 迁移

以固定 [`MsgManager.java`](https://github.com/WuKongIM/WuKongIMAndroidSDK/blob/662a559a50d181540a0448454beb57e939b0c50e/wkim/src/main/java/com/xinbida/wukongim/manager/MsgManager.java) 和 [`ConnectionManager.java`](https://github.com/WuKongIM/WuKongIMAndroidSDK/blob/662a559a50d181540a0448454beb57e939b0c50e/wkim/src/main/java/com/xinbida/wukongim/manager/ConnectionManager.java) 编译调用方：

| 旧/风险形态 | `1.5.5` 目标 |
| --- | --- |
| 浮动或旧 JitPack 版本 | 精确 `1.5.5` + revision + checksum |
| `sendMessage(content, channelID, channelType)` | deprecated；新代码用 `send(WKMessageContent, WKChannel)` / `sendWithOptions` |
| 需要控制本地消息的发送 | 构造 `WKMsg` 后调用 `sendMessage(WKMsg)` |
| 猜测 `removeOnSendMsgCallback` | 实际移除方法是 `removeSendMsgCallBack(key)` |
| 猜测 `WKConnectStatus.failed` | 实际常量是 `fail`、`noNetwork`、`kicked` 等 |
| 第一次 `success` 就允许发送 | READ 同步需要 `syncMsg` → `syncCompleted` → 接受后的 `success` |

每个 `addOn…(key, listener)` 都必须用相同 key 清理。Provider 回调要单次完成并由应用 activation epoch 拒绝陈旧结果。

## 4. 检查依赖与 R8

`1.5.5` AAR 已声明当前 SQLCipher、SQLite、Kotlin 和 Curve25519 依赖。删除从旧站复制的重复旧版本，重新检查依赖冲突。

固定 AAR 的 `consumer-rules.pro` / `proguard.txt` 为空，而源码仓库自身的 `proguard-rules.pro` 含 SDK、xSocket、Curve25519 和 SQLCipher 规则。应用需要维护并审核自己的规则，至少执行：

- Debug build；
- minified Release build；
- 启动、初始化、连接、正文反射/自定义消息、SQLCipher 打开、SENDACK 和接收 smoke；
- mapping 与缺类/反射告警检查。

源码中存在规则不代表 consumer 自动继承。

## 5. 把数据库升级当作不可逆边界

[`WKDBUpgrade`](https://github.com/WuKongIM/WuKongIMAndroidSDK/blob/662a559a50d181540a0448454beb57e939b0c50e/wkim/src/main/java/com/xinbida/wukongim/db/WKDBUpgrade.java) 按 `assets/wk_sql` 中的递增 SQL 索引执行迁移并记录进度。固定源码**没有公开的降级契约**，也没有说明旧版本能读取新 schema。

因此：

1. 只在脱敏数据库副本上先跑升级；
2. 验证消息、会话、频道、未读与搜索数据；
3. 回滚演练使用升级前快照或隔离的新安装，不要让旧 SDK 直接打开已升级数据库；
4. 在确认升级后 schema 与账号数据策略前，不删除唯一可恢复副本。

这不是说升级一定不可回滚，而是没有证据时不能宣称原地降级安全。

## 6. 重跑生命周期和安全验收

- `WKIM.init` 使用 application context，route/conversation providers 在连接前激活；
- 连接在 15 秒内到达最终可接受状态，超时、kick、`fail`、`noNetwork` 与二次 `connecting` 被隔离；
- Alice 的本地入库、终止 SENDACK 和 Bob 在线接收分别记录；
- 所有在途发送完成后才 `disconnect(false/true)`；同进程换号仍受 `sendingMsgHashMap` 风险约束；
- `setDebug(false)` / `setWriteLog(false)` 生效，日志链不含 token 或 Payload；
- 原始 `NonBlockingConnection` TCP、SharedPreferences token、UID SQLCipher key 仍作为生产阻断项处理。

## 7. 发布与回滚判定

先小范围发布，比较连接接受率、SENDACK 终止率、消息重复/丢失、数据库迁移失败、ANR/crash 和日志泄露信号。只有新构建和运行证据通过后才扩大范围。

回滚必须同时回答：APK/AAB 是否可恢复、服务端协议是否兼容、旧 SDK 是否会碰到新 schema、是否存在未决发送、账号数据库是否已切换。任一项未知时，停止原地回滚，使用已验证的隔离恢复方案。

## 完成清单

- 依赖、revision、checksum、锁文件和验证元数据一致；
- 代码只使用 `1.5.5` 的真实公开 API，deprecated 迁移已审计；
- Debug/minified Release、数据库副本升级和 Alice/Bob 场景有可复现 evidence；
- TCP/TLS、日志、凭据、本地 key、换号和回滚风险仍明确可见；
- 不把源码对齐或本站页面发布误写成 Android `compatibility.json` receipt。
