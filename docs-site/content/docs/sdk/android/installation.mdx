本页安装 JitPack 坐标 `com.github.WuKongIM:WuKongIMAndroidSDK:1.5.5`，并把构建事实固定到源码 revision `662a559a50d181540a0448454beb57e939b0c50e`。

<Callout type="warn" title="这不是本站 Android 运行验证">
  依赖和 AAR 公共签名已经校对，但**不是本站 Android 运行验证**。没有 Android toolchain 构建、设备消息闭环与运行 receipt。`NonBlockingConnection` 原始 TCP、普通 SharedPreferences Token、UID SQLCipher key 和 debug Payload 日志仍是**生产阻断项**。
</Callout>

## 1. 前置条件

精确 `1.5.5` 源码声明：

```kotlin
android {
  compileSdk = 34

  defaultConfig {
    minSdk = 21
    targetSdk = 34
  }

  compileOptions {
    sourceCompatibility = JavaVersion.VERSION_17
    targetCompatibility = JavaVersion.VERSION_17
  }
}
```

同时准备 JDK 17。AAR 内的 `WKIM.class` 是 Java class major version 61，不能把旧 README 中的 compile SDK 33、min SDK 19 当成 `1.5.5` 事实。以上只是 tag 的构建边界；你的 Android Gradle Plugin、Kotlin、ABI、设备和系统组合仍需自行构建与运行验收。

## 2. 添加 JitPack 仓库

在现代 Gradle 项目的 `settings.gradle.kts` 中配置：

```kotlin
dependencyResolutionManagement {
  repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
  repositories {
    google()
    mavenCentral()
    maven(url = "https://jitpack.io")
  }
}
```

Groovy DSL 对应写法：

```groovy
dependencyResolutionManagement {
  repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
  repositories {
    google()
    mavenCentral()
    maven { url 'https://jitpack.io' }
  }
}
```

不要同时在多个 project/module 重复声明 JitPack，也不要使用全局动态仓库规则掩盖依赖来源。

## 3. 精确安装 `1.5.5`

在应用 module 中添加固定坐标：

```kotlin
dependencies {
  implementation("com.github.WuKongIM:WuKongIMAndroidSDK:1.5.5")
}

dependencyLocking {
  lockAllConfigurations()
}
```

生成并提交 Gradle lock：

```bash
./gradlew dependencies --write-locks
```

依赖锁固定解析版本，不固定下载字节；还要使用下一节的 Gradle dependency verification 强制 AAR 校验和。不要使用版本占位符、`latest`、`+` 或版本范围。tag `1.5.5` 对应官方仓库 [WuKongIMAndroidSDK](https://github.com/WuKongIM/WuKongIMAndroidSDK) revision `662a559a50d181540a0448454beb57e939b0c50e`；JitPack build API 同样报告该 revision、`status: ok` 与 `isTag: true`。

## 4. 核对实际 AAR

本教程审计时下载的 AAR：

```text
https://jitpack.io/com/github/WuKongIM/WuKongIMAndroidSDK/1.5.5/WuKongIMAndroidSDK-1.5.5.aar
SHA-256 5a797f1fac53c4fbcf015afca2686ecbeebd24b5e64dea598881b814b1322792
```

可在受控下载后核对：

```bash
openssl dgst -sha256 WuKongIMAndroidSDK-1.5.5.aar
unzip -l WuKongIMAndroidSDK-1.5.5.aar
```

在受信网络与已评审构建脚本下执行 Release 构建，让 Gradle 解析应用的实际依赖并生成 `gradle/verification-metadata.xml`；评审后提交该文件：

```bash
./gradlew --write-verification-metadata sha256 :app:assembleRelease
```

如果应用 module 不叫 `app`，替换为它的实际 Release task。单独传 `--write-verification-metadata` 而不带会解析依赖的 task，不足以保证 AAR 与传递依赖进入元数据。

评审生成文件，确认该组件的 AAR 条目固定为本页 SHA，而不是只相信自动下载结果：

```xml
<component group="com.github.WuKongIM" name="WuKongIMAndroidSDK" version="1.5.5">
  <artifact name="WuKongIMAndroidSDK-1.5.5.aar">
    <sha256 value="5a797f1fac53c4fbcf015afca2686ecbeebd24b5e64dea598881b814b1322792" />
  </artifact>
</component>
```

CI 必须以 strict 模式解析并构建，例如：

```bash
./gradlew --dependency-verification strict :app:assembleRelease
```

Gradle 有 verification metadata 时默认也是 strict；CI 仍显式写出模式，避免构建脚本或调用方静默关闭验证。

AAR 应包含 `classes.jar` 和 `libs/xSocket-2.8.15.jar`。公共签名中应存在：

```text
WKIM.init(Context, String, String)
ConnectionManager.connection()
ConnectionManager.disconnect(boolean)
MsgManager.send(WKMessageContent, WKChannel)
MsgManager.sendMessage(WKMsg)
ISendACK.msgACK(WKMsg)
```

JitPack 可以重新构建 tag，校验和漂移不应被静默接受；先检查 build revision、POM 与 AAR 差异，再更新锁和文档证据。

## 5. 理解传递依赖

精确 POM 声明：

| 依赖 | 版本/位置 | 作用 |
| --- | --- | --- |
| xSocket | AAR 内嵌 `xSocket-2.8.15.jar` | 原始 TCP 连接 |
| Kotlin BOM | `org.jetbrains.kotlin:kotlin-bom:1.9.22`（dependency management import） | Kotlin 版本约束 |
| Kotlin stdlib | `org.jetbrains.kotlin:kotlin-stdlib:1.9.22` | Kotlin runtime |
| Kotlin JDK 8 stdlib | `org.jetbrains.kotlin:kotlin-stdlib-jdk8:1.9.22` | JDK 8 扩展 runtime |
| multidex | `com.android.support:multidex:1.0.3` | 历史 support 依赖；AndroidX 项目需检查冲突/Jetifier |
| SQLCipher | `net.zetetic:sqlcipher-android:4.9.0` | 本地数据库 |
| SQLite KTX | `androidx.sqlite:sqlite-ktx:2.5.1` | SQLite 支持 |
| Curve25519 | `org.whispersystems:curve25519-java:0.5.0` | WKProto 兼容加密 |

旧文档要求手工添加 `android-database-sqlcipher`、旧 `sqlite-ktx`、`curve25519-android` 和 Signal Protocol。那组版本不属于当前 POM；重复添加会制造 class/原生库冲突。先用 `./gradlew :app:dependencies` 检查解析结果，再只为明确冲突添加受审约束。

## 6. 声明文本闭环需要的权限

应用需要网络权限；AAR 自身只声明 `ACCESS_NETWORK_STATE`：

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
```

文本消息闭环不需要相机、麦克风、相册或存储运行时权限。媒体与推送功能应按真实平台 API 另行设计，不能为了“省事”预先申请全部权限。

## 7. 为 minified Release 配置 R8

tag 的 `consumer-rules.pro` 为空，AAR 中 `proguard.txt` 也是 0 字节，因此源码 `proguard-rules.pro` 不会自动传给应用。至少从精确 tag 评审并在应用规则中保留实际反射/协议类型，例如：

```text
-dontwarn org.xsocket.**
-keep class org.xsocket.** { *; }
-keep class javax.ws.rs.** { *; }

-keep class com.xinbida.wukongim.** { *; }
-keep class org.whispersystems.curve25519.** { *; }
-keep class net.zetetic.database.sqlcipher.** { *; }

-keepattributes *Annotation*,Signature,Exceptions,InnerClasses
```

这是一条保守基线，不是体积最优保证。必须在 `minifyEnabled true` 的 Release 上至少验证初始化、数据库打开、连接、文本发送、SENDACK、在线接收和退出登录；再根据 R8 mapping 与反射使用收紧规则。

## 8. 不要用运行时字符串证明版本

`1.5.5` AAR 的 `WKIM.getVersion()` 仍返回 `V1.5.0`；tag 源码的本地 Maven publication 仍写 `1.0.7`。不要把它们上报为已安装包版本。构建元数据应记录：

- Gradle lock 中的完整 JitPack 坐标；
- `gradle/verification-metadata.xml` 中受审的 AAR SHA；
- source revision `662a559a50d181540a0448454beb57e939b0c50e`；
- 下载 AAR 的 SHA-256；
- JDK、AGP、Kotlin、compile/target/min SDK；
- 最终 APK/AAB 与 R8 mapping 的构建身份。

## 9. 安装后先审安全边界

| 边界 | `1.5.5` 源码事实 | 上线前动作 |
| --- | --- | --- |
| 传输 | xSocket `NonBlockingConnection` 原始 **TCP**，无 TLS | 私网/受控入口或受审的认证 TLS 升级 |
| 凭据 | UID、Token 写入普通 **SharedPreferences** | 受审凭据存储或 SDK 修复；短期、轮换、撤销 |
| 数据库 | **SQLCipher** 密码直接等于 UID | 独立机密 key、备份与擦除策略 |
| 日志 | debug 时 `WKReceivedMsg.toString()` 包含解密 **Payload**；关闭 debug 仍有少量 warning | `setDebug(false)`、`setWriteLog(false)`，检查 Release 与采集链 |
| 账号切换 | `disconnect(true)` 不清空 `sendingMsgHashMap` | 终止 SENDACK 后再退出；生产换号需 SDK 修复或进程隔离 |
| 设备类别 | CONNECT 固定 `0`；字典为 `0=APP`、`1=WEB`、`2=PC` | 单独验收互踢、多端和设备策略 |

WKProto Payload 加密不是认证 TLS，应用沙箱也不是独立机密管理。安装成功只能证明依赖可解析，不能关闭这些生产阻断项。

## 安装完成标准

进入快速接入前应能回答：

- lockfile 是否只解析精确 `1.5.5`？
- JitPack build revision、Gradle `verification-metadata.xml` 和 AAR SHA 是否与审计记录一致？
- Debug 与 minified Release 是否都能解析依赖？
- 应用是否只声明当前场景所需权限？
- R8、传输、Token、数据库和日志阻断是否有明确负责人？
