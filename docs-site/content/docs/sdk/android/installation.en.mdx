This page installs `com.github.WuKongIM:WuKongIMAndroidSDK:1.5.5` and binds the build facts to source revision `662a559a50d181540a0448454beb57e939b0c50e`.

<Callout type="warn" title="This is not Android runtime verification">
  Dependency and AAR public signatures are aligned, but this is **not Android runtime verification**. There is no Android toolchain build, device message loop, or runtime receipt. Raw TCP through `NonBlockingConnection`, an ordinary SharedPreferences token, a UID SQLCipher key, and debug Payload logging remain **production blocker** items.
</Callout>

## 1. Prerequisites

The exact `1.5.5` source declares:

```kotlin
android {
  compileSdk = 34

  defaultConfig {
    minSdk = 21
    targetSdk = 34
  }

  compileOptions {
    sourceCompatibility = JavaVersion.VERSION_17
    targetCompatibility = JavaVersion.VERSION_17
  }
}
```

Use JDK 17 as well. `WKIM.class` in the AAR has Java class major version 61. Do not carry the old README's compile SDK 33 or minimum SDK 19 into a `1.5.5` build. These are source-tag build boundaries, not validation for every Android Gradle Plugin, Kotlin, ABI, device, or system tuple.

## 2. Add JitPack

Configure modern Gradle projects in `settings.gradle.kts`:

```kotlin
dependencyResolutionManagement {
  repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
  repositories {
    google()
    mavenCentral()
    maven(url = "https://jitpack.io")
  }
}
```

Groovy DSL:

```groovy
dependencyResolutionManagement {
  repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
  repositories {
    google()
    mavenCentral()
    maven { url 'https://jitpack.io' }
  }
}
```

Do not repeat JitPack across project/modules or use broad dynamic repository rules that hide dependency provenance.

## 3. Install exactly `1.5.5`

Add the fixed coordinate to the application module:

```kotlin
dependencies {
  implementation("com.github.WuKongIM:WuKongIMAndroidSDK:1.5.5")
}

dependencyLocking {
  lockAllConfigurations()
}
```

Generate and commit Gradle locks:

```bash
./gradlew dependencies --write-locks
```

Dependency locking pins resolved versions, not downloaded bytes. Also use Gradle dependency verification in the next section to enforce the AAR checksum. Do not use a version placeholder, `latest`, `+`, or a version range. Tag `1.5.5` in [WuKongIMAndroidSDK](https://github.com/WuKongIM/WuKongIMAndroidSDK) resolves to revision `662a559a50d181540a0448454beb57e939b0c50e`; the JitPack build API reports that revision with `status: ok` and `isTag: true`.

## 4. Inspect the actual AAR

The AAR observed for this tutorial is:

```text
https://jitpack.io/com/github/WuKongIM/WuKongIMAndroidSDK/1.5.5/WuKongIMAndroidSDK-1.5.5.aar
SHA-256 5a797f1fac53c4fbcf015afca2686ecbeebd24b5e64dea598881b814b1322792
```

Check a controlled download:

```bash
openssl dgst -sha256 WuKongIMAndroidSDK-1.5.5.aar
unzip -l WuKongIMAndroidSDK-1.5.5.aar
```

Run a Release build with a trusted network and reviewed build scripts so Gradle resolves the application's actual dependencies and generates `gradle/verification-metadata.xml`; review and commit that file:

```bash
./gradlew --write-verification-metadata sha256 :app:assembleRelease
```

If the application module is not named `app`, substitute its actual Release task. Passing `--write-verification-metadata` without a dependency-resolving task does not ensure that the AAR and transitive artifacts enter the metadata.

Review the generated file and require this exact AAR entry rather than trusting the downloaded result itself:

```xml
<component group="com.github.WuKongIM" name="WuKongIMAndroidSDK" version="1.5.5">
  <artifact name="WuKongIMAndroidSDK-1.5.5.aar">
    <sha256 value="5a797f1fac53c4fbcf015afca2686ecbeebd24b5e64dea598881b814b1322792" />
  </artifact>
</component>
```

Resolve and build in strict mode in CI, for example:

```bash
./gradlew --dependency-verification strict :app:assembleRelease
```

Gradle defaults to strict when verification metadata exists. Keeping the mode explicit in CI prevents a build script or caller from silently disabling it.

The AAR should contain `classes.jar` and `libs/xSocket-2.8.15.jar`. Its public signatures include:

```text
WKIM.init(Context, String, String)
ConnectionManager.connection()
ConnectionManager.disconnect(boolean)
MsgManager.send(WKMessageContent, WKChannel)
MsgManager.sendMessage(WKMsg)
ISendACK.msgACK(WKMsg)
```

JitPack can rebuild a tag. Never accept checksum drift silently: inspect the build revision, POM, and AAR diff before updating locks and documentation evidence.

## 5. Understand transitive dependencies

The exact POM declares:

| Dependency | Version/location | Role |
| --- | --- | --- |
| xSocket | Embedded `xSocket-2.8.15.jar` | Raw TCP connection |
| Kotlin BOM | `org.jetbrains.kotlin:kotlin-bom:1.9.22` dependency-management import | Kotlin version constraints |
| Kotlin stdlib | `org.jetbrains.kotlin:kotlin-stdlib:1.9.22` | Kotlin runtime |
| Kotlin JDK 8 stdlib | `org.jetbrains.kotlin:kotlin-stdlib-jdk8:1.9.22` | JDK 8 extension runtime |
| multidex | `com.android.support:multidex:1.0.3` | Legacy support dependency; inspect AndroidX/Jetifier conflicts |
| SQLCipher | `net.zetetic:sqlcipher-android:4.9.0` | Local database |
| SQLite KTX | `androidx.sqlite:sqlite-ktx:2.5.1` | SQLite support |
| Curve25519 | `org.whispersystems:curve25519-java:0.5.0` | WKProto compatibility encryption |

Legacy docs manually add older SQLCipher, SQLite, Curve25519 Android, and Signal Protocol artifacts. Those versions are not the current POM. Duplicating them can produce class or native-library conflicts. Inspect `./gradlew :app:dependencies` first and add reviewed constraints only for a demonstrated conflict.

## 6. Declare permissions for the text loop

The application needs internet access; the AAR itself declares only `ACCESS_NETWORK_STATE`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
```

A text-message loop needs no camera, microphone, photo-library, or storage runtime permission. Design media and push permissions against the real platform APIs instead of requesting everything up front.

## 7. Configure R8 for a minified Release

Tag `consumer-rules.pro` is empty and AAR `proguard.txt` is zero bytes, so source `proguard-rules.pro` is not inherited. Review the exact tag and keep the actual reflective/protocol types in the app, starting conservatively with:

```text
-dontwarn org.xsocket.**
-keep class org.xsocket.** { *; }
-keep class javax.ws.rs.** { *; }

-keep class com.xinbida.wukongim.** { *; }
-keep class org.whispersystems.curve25519.** { *; }
-keep class net.zetetic.database.sqlcipher.** { *; }

-keepattributes *Annotation*,Signature,Exceptions,InnerClasses
```

This is a conservative baseline, not a size optimum. With `minifyEnabled true`, exercise initialization, database open, connection, text send, SENDACK, online receipt, and logout. Tighten rules only with the R8 mapping and reflection use in hand.

## 8. Do not attest the version from runtime strings

`WKIM.getVersion()` in the `1.5.5` AAR returns `V1.5.0`; the tag source's local Maven publication says `1.0.7`. Do not report either as the installed package. Build metadata should retain:

- the complete JitPack coordinate from the Gradle lock;
- the reviewed AAR SHA in `gradle/verification-metadata.xml`;
- source revision `662a559a50d181540a0448454beb57e939b0c50e`;
- downloaded AAR SHA-256;
- JDK, AGP, Kotlin, compile/target/min SDK;
- final APK/AAB and R8 mapping build identity.

## 9. Review security before integration

| Boundary | `1.5.5` source fact | Required release action |
| --- | --- | --- |
| Transport | xSocket `NonBlockingConnection` raw **TCP**, no TLS | Private/controlled ingress or a reviewed authenticated-TLS upgrade |
| Credentials | UID/token in ordinary **SharedPreferences** | Reviewed credential store or SDK patch; short lifetime, rotation, revocation |
| Database | **SQLCipher** password equals UID | Independent secret key, backup, and erasure policy |
| Logging | Debug `WKReceivedMsg.toString()` includes decrypted **Payload**; selected warnings remain when debug is off | `setDebug(false)`, `setWriteLog(false)`, Release/log-pipeline inspection |
| Account switching | `disconnect(true)` does not clear `sendingMsgHashMap` | Wait for terminal SENDACK; production switching needs an SDK fix or process isolation |
| Device category | CONNECT fixes `0`; dictionary is `0=APP`, `1=WEB`, `2=PC` | Separately accept kicking, concurrent devices, and policy |

WKProto Payload encryption is not authenticated TLS, and an application sandbox is not independent secret management. A resolved dependency cannot close these production blockers.
