## Capability matrix

| Area | Public `1.5.5` surface | What the integrator must supply |
| --- | --- | --- |
| Initialization | `WKIM.getInstance().init(context, uid, token)` with application context | A trusted backend issues UID/token; the client never receives Product HTTP management credentials |
| Route and connection | `addOnGetIpAndPortListener`, `connection()`, `disconnect(false/true)`, and status listeners | Gateway host/port, timeouts, reconnect-generation fencing, and failure acceptance |
| Channels | `WKChannelType.PERSONAL` and `WKChannelType.GROUP`; source also declares customer-service, community, and topic constants | Server channel model, authorization, and real acceptance for each selected type |
| Text | `WKTextContent` | SENDACK rejection handling and Bob's online receipt |
| Media | `WKImageContent`, `WKVoiceContent`, and `WKVideoContent` | Product upload through `addOnUploadAttachListener`, permissions, compression, failure recovery, and large-file acceptance |
| Custom content | Extend `WKMessageContent`, implement codec methods, and call `registerContentMsg` | The same stable content type and compatibility policy on every platform |
| Sending | `sendMessage(WKMsg)`, `send(WKMessageContent, WKChannel)`, and `sendWithOptions` | Separate local insert, SENDACK, and peer receipt; correlate with `clientMsgNO` / `clientSeq` |
| Receive and status | `addOnNewMsgListener`, `addOnSendMsgCallback`, and `addOnSendMsgAckListener` | Register/remove stable keys and cross async boundaries with application-owned immutable snapshots |
| Conversations | `ConversationManager` and `addOnSyncConversationListener` | A trusted sync provider; an empty `WKSyncChat` is for fresh test accounts only, not production offline recovery |
| Channel data and members | Local query, refresh, and provider hooks on `ChannelManager` and `ChannelMembersManager` | Product APIs, authorization, and paged/capacity design for 100,000-member groups |
| Local data | UID-scoped database, SQLCipher, and message/conversation/channel managers | UID is not a secret database key; review key management, backup, account switching, and erasure |
| Reminder, CMD, robot | `ReminderManager`, `CMDManager`, and `RobotManager` | Matching server providers, signature/authorization, and product acceptance |

Verify the exposed symbols in [`WKIM.java`](https://github.com/WuKongIM/WuKongIMAndroidSDK/blob/662a559a50d181540a0448454beb57e939b0c50e/wkim/src/main/java/com/xinbida/wukongim/WKIM.java), [`MsgManager.java`](https://github.com/WuKongIM/WuKongIMAndroidSDK/blob/662a559a50d181540a0448454beb57e939b0c50e/wkim/src/main/java/com/xinbida/wukongim/manager/MsgManager.java), and [`ConnectionManager.java`](https://github.com/WuKongIM/WuKongIMAndroidSDK/blob/662a559a50d181540a0448454beb57e939b0c50e/wkim/src/main/java/com/xinbida/wukongim/manager/ConnectionManager.java).

## Message content and send options

`WKIM.init` registers text, image, video, and voice content: `WKTextContent`, `WKImageContent`, `WKVideoContent`, and `WKVoiceContent`. A custom type needs a no-argument constructor, a unique `type`, and `encodeMsg()` / `decodeMsg()`. Registration on one platform alone does not create a cross-platform protocol.

`WKSendOptions` exposes `expire`, `topicID`, `flame`, `flameSecond`, `robotID`, `setting`, and `header`. Source presence does not prove that every server/client combination supports each option; accept them against the protocol, server configuration, and other clients.

Sending has three distinct event layers:

1. `addOnSendMsgCallback` reports local insertion.
2. `addOnSendMsgAckListener` delivers SENDACK; only `WKSendMsgResult.send_success` is success.
3. Bob's `addOnNewMsgListener` proves online receipt.

The immediately created `WKMsg.messageID` / `messageSeq` may not yet be server-assigned. Correlate a pending item with `clientMsgNO` and require a positive local `clientSeq`.

## Platform and network boundaries

- Exact source opens raw TCP through xSocket `NonBlockingConnection`; it exposes no TLS socket, TLS option, or `startTLS`. WKProto Payload encryption does not authenticate the server and is not TLS.
- CONNECT uses device flag `0=APP`; `1=WEB` and `2=PC` are protocol constants. That fact does not prove multi-device behavior, system push, or background survival.
- The public SDK surface does not provide an end-to-end Firebase/Huawei push configuration or receipt. Design and accept push, notification permission, background restrictions, and vendor channels separately.
- Keep `setDebug(false)` and `setWriteLog(false)` before initialization, but selected warnings can still be emitted; with debug enabled, `WKReceivedMsg.toString()` can expose decrypted Payload.
- UID/token are stored in ordinary `MODE_PRIVATE` `SharedPreferences`, and SQLCipher uses UID as its password. Neither is independent key-management evidence.

## Minimum production acceptance

- Pin and verify `com.github.WuKongIM:WuKongIMAndroidSDK:1.5.5`, its revision, and AAR SHA-256.
- Build debug and minified Release with the actual AGP/JDK/Kotlin/device matrix.
- Exercise timeout, authentication failure, kick, network loss, reconnect generations, and listener cleanup.
- Prove Alice local insert, terminal SENDACK, Bob online receipt, and real offline/conversation synchronization.
- Verify media permission, upload, failure recovery, push, and background policy.
- Close or explicitly isolate raw TCP, Payload logging, token storage, UID database-key, and same-process account-switch risks.
- Produce platform-specific build/device/runtime evidence; do not reuse `compatibility.json`, which covers only the JavaScript/Web path.
