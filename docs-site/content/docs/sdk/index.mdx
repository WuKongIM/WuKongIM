WuKongIM SDK 负责客户端与 Gateway 之间的连接、消息收发和协议状态。你不需要先掌握底层协议；从自己的平台和目标开始，先跑通最小闭环，再补生产能力。

<Callout type="info" title="第一次接入从这里开始">
  还没决定仓库时先看[选择 SDK](/zh/sdk/choose-sdk)。Android 可从[完整版 SDK 教程](/zh/sdk/android)开始：`1.5.5` 的源码与 JitPack AAR 已校对，但没有本站 Android 运行 receipt。iOS `1.1.1` 同样只有源码/公开头文件证据。需要本站可执行场景证据的浏览器路径，请进入 [WuKongIMJSSDK 安装与配置](/zh/sdk/javascript/installation)。WuKongEasySDK 的 JSON-RPC CONNECT 当前不受 Product Gateway 支持，教程维持规划状态。
</Callout>

## 一次完整接入会经历什么

1. **选择并锁定 SDK**：确认平台、必需能力和精确版本，不从 `latest` 猜兼容性。
2. **准备业务身份**：用户先登录你的产品；受信后端再返回 UID、短期 Token 和连接所需材料。
3. **初始化并监听事件**：配置当前用户，先注册连接、消息和发送状态监听，再发起连接。
4. **连接并恢复状态**：等待 SDK 真正连接成功；重连时先同步缺失消息并去重，再把 UI 标记为可用。
5. **发送与接收消息**：分别处理发送确认、在线接收和业务处理结果，不能把它们合成一个“成功”。
6. **补齐产品体验**：根据需求加入自定义消息、会话与未读、移动推送和多设备策略。
7. **完成上线验收**：验证失败与恢复路径，并单独关闭鉴权、TLS、限流、容量、审计和回滚门禁。

这七步在不同平台上的类名和回调形式会变化，但职责和验收问题相同。[SDK 公共指南](/zh/sdk/common-guides)按这个顺序解释共享行为，平台仓库负责精确 API。

## Web 教程会带你完成什么

按照[安装与配置](/zh/sdk/javascript/installation)和[快速接入](/zh/sdk/javascript/quickstart)操作后，你将看到：

- Alice 与 Bob 各自完成连接；
- Alice 发送后收到 SENDACK，Bob 另行收到实时消息；
- Bob 断开时，Alice 的持久消息仍可提交；
- Bob 重连后从同步路径恢复消息，且不会把恢复结果误标为实时接收。

这比只看“发送成功”更接近真实应用，因为持久提交、在线投递和离线恢复本来就是三个不同结果。

## 常见问题

- **不知道选哪一个仓库**：先列出平台、最低系统版本和必需能力，再使用[选择 SDK](/zh/sdk/choose-sdk)逐项核对。
- **只需要连接和在线消息**：当前不要选择 EasySDK 作为 v3 接入路径；先看 [JSON-RPC 支持矩阵](/zh/api/client-protocols/json-rpc)，或使用已有可执行证据的 JavaScript/Web 路径。
- **iOS 需要本地消息、会话和未读**：先用 [iOS 安装与快速接入](/zh/sdk/ios)核对 `1.1.1` 的最小在线路径，再按公共指南补需求；离线与会话恢复还没有本站运行证据。
- **Android 需要本地消息、会话和未读**：先用 [Android 安装与快速接入](/zh/sdk/android)核对 `1.5.5` 的同步门禁与在线路径；源码/AAR 校对不是设备运行 receipt。
- **其他原生平台需要本地状态**：评估对应 WuKongIMSDK 仓库；Flutter、UniApp 与 HarmonyOS 教程仍在规划中。
- **Web 样例能构建但连接失败**：继续按快速接入检查集群 `/readyz`、路由地址、Gateway 端口和 BFF 输出。
- **消息发送成功但对方没显示**：先区分 SENDACK、在线接收和同步恢复，分别诊断。

## 安全与责任边界

SDK 不负责产品账号、授权或 Token 签发。客户端不能获得 WuKongIM Product HTTP 管理能力；这些接口应位于受信业务后端。默认 v3 Beta Gateway 也不会自动把已保存 Token 变成生产级身份校验。Android `1.5.5` 和 iOS `1.1.1` 都存在无 TLS 原始 TCP、本地数据/凭据或 Payload 日志阻断；上线前必须补齐鉴权、TLS、网络隔离、日志脱敏、本地数据保护、限流、审计和撤销。
