SDK 文档现在分成两层：公共指南用当前服务端和 Wire 契约解释所有集成者都要处理的身份、连接、消息、会话、离线和多设备边界；JavaScript/Web 黄金路径提供唯一可执行、可出具 receipt 的客户端样例。

## 目标与完成标准

开发者应先完成跨 SDK 行为设计，再把它映射到精确平台版本。当前构建是否附带完整执行证据，仍以 JavaScript 兼容快照的 receipt 状态为准；公共指南发布不等于 Android、iOS、Flutter、UniApp 或 HarmonyOS 已验证。

## 兼容目标

Phase 12 固定 `wukongimjssdk@1.3.5`，并把服务端 revision、Node.js 与 Chromium 写入[兼容性快照](/zh/sdk/compatibility)。Phase 13 的公共指南和协议字典与当前源码校准，但没有扩大该快照的平台支持范围。

## 前置条件

- 一个通过 `/readyz` 的 WuKongIM 单节点集群；
- Node.js `>=20.11` 与 npm，用于黄金样例；
- 业务后端拥有账号、权限和 Product HTTP 信任边界；
- 理解浏览器只能访问 localhost BFF，不能直连 Product HTTP。

## 预期结果

完成公共指南后，你应有一份可评审的客户端状态机和上线证据清单。黄金路径通过时，Alice 与 Bob 各自连接；双向消息分别显示 SENDACK 与 realtime 接收；Bob 断开期间提交的消息在重连后显示为 sync 恢复。

## 失败诊断

- **不确定从哪个 SDK 开始**：Phase 12 只验证 JavaScript/Web；其他平台不要从规划菜单推断支持。
- **有平台 SDK，但不知道如何组织生命周期**：先使用公共指南定义行为，再查该 SDK 的精确版本 API。
- **版本不一致**：回到兼容快照并使用 lockfile，不要改用 `latest`。
- **示例能连接但安全评审失败**：这是开发路径，不具备生产 Token 校验和 HTTP 业务鉴权。

## 安全与责任边界

SDK 不拥有业务账号、授权或 Token 签发。默认 v3 Beta Gateway 不自动校验已存 Token，生产系统必须自行补齐身份边界、TLS、限流、审计和撤销。
