---
title: 升级 SDK
description: 用一套简洁流程安全升级任意平台的 WuKongIMSDK。
---

不要只修改版本号就发布。SDK 还管理本地数据库、监听器和连接状态，升级时需要一起检查。

## 1. 记录当前版本

保存当前依赖版本和锁文件，并列出应用使用的连接、消息、会话、频道、Provider 和自定义消息 API。

## 2. 阅读发布说明

查看目标 SDK 仓库的 Release、Changelog 和迁移说明。重点关注：

- 方法名或参数是否变化；
- 本地数据库是否升级；
- 消息编码是否变化；
- 最低系统和构建工具要求是否变化。

## 3. 只升级 SDK 依赖

先只修改 SDK 版本并刷新锁文件，不要同时升级大量无关依赖。这样出现问题时更容易定位。

## 4. 重新验证核心流程

至少验证：

1. 登录后能够连接；
2. Alice 能给 Bob 发送文本；
3. 发送状态从发送中变为成功；
4. Bob 能收到消息；
5. 断网后能够恢复连接；
6. 历史消息、会话和未读数仍然正确；
7. 自定义消息仍能编码和解码。

## 5. 检查本地数据

使用已有账号和真实数据量测试升级，不要只测全新安装。如果 SDK 修改了数据库结构，确认旧数据能够打开，并提前决定失败时如何处理。

## 6. 小范围发布

先向少量用户发布，观察连接失败、消息发送失败、崩溃和本地数据库错误。出现异常时同时回退依赖版本和锁文件。

<Callout type="warn" title="回退不一定能恢复数据库">
  如果新版本已经修改本地数据库，安装旧版本可能无法直接打开它。发布前必须验证真实的数据升级与回退路径。
</Callout>
