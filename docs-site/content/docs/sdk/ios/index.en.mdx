This tutorial is for developers integrating the full WuKongIMSDK into a native iOS application for the first time. It uses the Objective-C public API from `WuKongIMSDK` `1.1.1` to explain the shortest lifecycle: a product backend prepares identity, the client configures the SDK, waits for connection state, then observes send state and online receipt separately.

<Callout type="warn" title="Understand the evidence boundary first">
  The tutorial is aligned with the `1.1.1` source, CocoaPods metadata, and distributed framework public headers, but this is **not runtime verification**. This site carries no Xcode build, simulator/device message loop, or compatibility receipt for this version. Raw TCP without TLS, logging, and local-data protection findings below are current **production blocker** items.
</Callout>

## Who this is for

- You need the SDK to own connection, messaging, local database, conversation, and other client state rather than calling a stateless endpoint only.
- Your trusted product backend can return UID, token, Gateway host, and port after product login.
- You want to prove an Alice/Bob online-text loop before separately validating offline sync, push, background behavior, and production security.

If you are still comparing EasySDK and the full SDK, start with [Choose an SDK](/en/sdk/choose-sdk). This tutorial uses `WuKongIMiOSSDK`; do not copy EasySDK or legacy-document method names into it.

| Binary artifact | [`WuKongIMiOSSDK-Framework` tag `1.1.1`](https://github.com/WuKongIM/WuKongIMiOSSDK-Framework/tree/1.1.1) | CocoaPods public headers and framework |
| Podspec deployment declarations | iOS `11.0` / iOS `13.0` conflict | Source and framework podspecs disagree; they do not establish one minimum supported version |

The tutorial-facing public headers match between the source and framework tags. That supports “the shown methods exist,” but it does not prove a target environment builds or runs. The source podspec says iOS `11.0`, while the framework podspec says deployment target iOS `13.0` and platform iOS `11.0`; integrators must resolve and validate this podspec conflict with their own Deployment Target, Xcode, simulator, and device tuple.

## What you will build

```text
Alice iOS ─┐                           ┌─ Gateway TCP
           ├─ trusted backend identity ┤
Bob iOS ───┘   uid/token/host/port      └─ WuKongIM single-node cluster
```

- The product backend owns product login, authorization, UID, token, routing, expiry, and revocation.
- The iOS SDK owns connection state, send queues, online receipt, and a UID-isolated local database.
- The WuKongIM cluster owns channel logs, persistent commit, routing, and online delivery.

The client receives only minimal connection material and never Product HTTP management credentials.

## Minimal loop and excluded scope

| Stage | This tutorial shows | This tutorial does not prove |
| --- | --- | --- |
| Install | `pod 'WuKongIMSDK', '1.1.1'` and public-header provenance | Compatibility with every Xcode, simulator, or device |
| Connect | Call `connect`, await the connection delegate, and enforce a 15-second acceptance timeout | Calling `connect` means the connection succeeded |
| Send | Create `WKTextContent` and a person channel, then obtain a local `WKMessage` | The returned object has a server acknowledgement |
| Ack and receive | Handle message-update and RECV callbacks separately | Peer product processing or offline recovery completed |
| Cleanup | Remove delegates and force disconnect; call `logout` for account logout | Automatic compliance with the product's data-deletion policy |

## Blockers to close before production

Exact `1.1.1` source opens a raw **TCP** connection without transport TLS through `GCDAsyncSocket`. It exposes no TLS option or `startTLS` path. WKProto compatibility Payload encryption neither authenticates the server nor replaces authenticated TLS. Production requires controlled/private ingress or a reviewed SDK or transport upgrade with authenticated TLS.

`WKOptions.isDebug` defaults to enabled, and the tutorial explicitly disables `isDebug`. That is still insufficient: the `1.1.1` receive path unconditionally logs the decoded packet, and a RECV description can contain plaintext message **Payload**. This remains a production blocker until an upstream or reviewed patch redacts it and the Release artifact plus log-collection chain are verified.

The local message database uses SQLCipher, but source supplies the UID directly as its database key. A UID scopes the database file; it is not a secret key or standalone at-rest confidentiality. Production still needs reviewed key management, iOS file protection, backup, account-switch, and erasure policy.

## Completion check

- You can identify the exact CocoaPods version and both reviewed revisions.
- You can explain the iOS `11.0` / iOS `13.0` podspec conflict and validate the application's own Deployment Target on its target environment.
- You know connection success comes from a delegate rather than the `connect` return value.
- You can distinguish a local pending message, send acknowledgement, and Bob's online receipt.
- You do not present source review as a compatibility receipt or ignore TCP/TLS and Payload logging risk.
