---
title: Docker
description: Start a WuKongIM single-node cluster with random credentials and persistent storage in one command.
---

You only need Docker and `curl`. The installer generates random credentials, creates persistent storage, starts a pinned image, and waits for the node to become ready.

<Callout type="warn" title="The default is for a quick local evaluation">
  The installer pins pre-release `3.0.0-beta.6`. It does not configure a domain, TLS, backups, or multi-node replication. Complete the [Production Checklist](/en/server/deployment/production-checklist) before serving production traffic.
</Callout>

## 1. Start with one command

```bash
curl -fsSL https://docs.githubim.com/install/docker.sh | sh
```

When installation finishes, the terminal prints the Manager URL, username, and random password. Deployment files are stored in `wukongim-docker/` under the current directory, while message data is stored in the `wukongim-data` Docker volume.

If clients connect from another machine, provide a reachable hostname or IP in the same command:

```bash
curl -fsSL https://docs.githubim.com/install/docker.sh | env WK_PUBLIC_HOST=im.example.com sh
```

## 2. Sign in and verify

Open [http://127.0.0.1:5301](http://127.0.0.1:5301) and sign in with `admin` and the random password printed by the installer. Confirm that the node is ready:

```bash
curl --fail http://127.0.0.1:5001/readyz
```

Then follow [Quick Start](/en/guide/quick-start) with two test users and complete one send-and-receive cycle.

<details>
<summary>How do I open Manager from my computer after deploying on a server?</summary>

Manager and the Product API bind only to server loopback by default. Create an SSH tunnel, then open the same Manager URL on your computer:

```bash
ssh -N \
  -L 5001:127.0.0.1:5001 \
  -L 5301:127.0.0.1:5301 \
  user@server
```

</details>

<details>
<summary>Common operations</summary>

```bash
# Inspect status and logs
docker ps --filter name=wukongim
docker logs --follow --tail 100 wukongim

# Restart or stop
docker restart wukongim
docker stop wukongim

# Start again
docker start wukongim
```

Credentials are stored in `wukongim-docker/.env` with mode `0600`. Removing the container does not remove `wukongim-data`; do not delete that volume unless its data is no longer needed.

</details>

<details>
<summary>Review the installer before running it</summary>

```bash
curl -fsSLO https://docs.githubim.com/install/docker.sh
less docker.sh
sh docker.sh
```

The installer pins an image digest, never uses `latest`, and does not overwrite an existing deployment environment file.

</details>

<details>
<summary>Remove the evaluation deployment completely</summary>

Confirm that the data is no longer needed, then run:

```bash
docker rm --force wukongim
docker volume rm wukongim-data
rm -r wukongim-docker
```

The last two commands permanently remove message data and installation credentials.

</details>

A production deployment also needs real TCP/TLS and WSS endpoints, restricted access to ports `5001` and `5301`, plus backup and rollback procedures. Continue to [Multi-node Cluster](/en/server/deployment/multi-node) when you need replication and failure recovery.
