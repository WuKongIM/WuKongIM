部署只需要先做一个决定：**是否接受单点故障？** 如果不确定运行介质，从 Docker 开始。

<Callout type="warn" title="每个部署都是集群">
  单节点部署是单节点集群，仍然经过 Controller、Slot、Channel、路由和存储路径，不存在绕过集群语义的独立模式。
</Callout>

## 选择路径

| 你的目标 | 从这里开始 |
| --- | --- |
| 先在本机运行并验证消息链路 | [快速开始](/zh/guide/quick-start) |
| 使用最短的可重复部署路径 | [Docker 部署](/zh/server/deployment/docker)（推荐） |
| 直接管理主机、文件和 systemd | [Linux 部署](/zh/server/deployment/linux) |
| 跨节点复制并规划故障恢复 | 先阅读[多节点集群](/zh/server/deployment/multi-node)，再选择 Docker 或 Linux |

单节点集群适合开发、验证，以及明确接受节点或磁盘故障会中断服务的小规模生产。需要节点故障后继续服务时，必须使用分布在独立故障域的多节点集群。

## 所有部署都要满足

- 固定制品版本或摘要，不使用浮动标签。
- 为每个节点准备唯一 ID、独立持久化目录和可达的 Transport 地址。
- 替换示例凭据，并限制 Manager、指标、Debug、Benchmark、诊断和 Transport 的网络访问。
- 设置客户端真正可达的 TCP、WS 或 WSS 外部地址；`0.0.0.0` 只能用于监听。
- 启动后验证持久化挂载、端到端消息和 `/readyz`，再接入流量。

```bash
curl --fail http://127.0.0.1:5001/readyz
```

`/healthz` 只说明进程能够响应；负载均衡、发布门禁和切流必须以 `/readyz` 为准。
