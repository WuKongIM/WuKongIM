---
title: Docker 部署
description: 使用固定版本镜像、Docker Compose 和持久卷运行可验证的 WuKongIM 单节点集群。
---

这条路径适合希望用官方镜像快速部署，同时明确管理网络、数据和容器生命周期边界的团队。完成后，你会得到一个可登录 Manager、可继续验证消息收发的单节点集群。

示例固定到预发布版本 `3.0.0-beta.5`，支持 `linux/amd64` 和 `linux/arm64`。镜像使用“版本标签 + 摘要”，不会因为标签移动而改变内容。

<Callout type="warn" title="生产使用前验证该预发布版本">
  固定镜像以 UID/GID `10001:10001` 运行，内置镜像级 `HEALTHCHECK`，使用 Alpine 3.24.1，并已通过 amd64 和 arm64 的发布时 Critical/High 漏洞门禁。但它仍是 beta 版本，扫描也只是特定时间点的证据。承载生产流量前，请结合[生产检查清单](/zh/server/deployment/production-checklist)验证配置、存储权限、网络控制、备份和回滚。
</Callout>

## 1. 准备主机和配置

主机需要 Docker Engine、Docker Compose v2、`curl` 和 `openssl`：

```bash
docker version
docker compose version
curl --version
openssl version
```

创建独立部署目录，并下载与镜像版本一致的配置模板：

```bash
mkdir -p wukongim-docker
cd wukongim-docker

curl --fail --location \
  https://raw.githubusercontent.com/WuKongIM/WuKongIM/v3.0.0-beta.5/wukongim.toml.example \
  --output node1.toml
chmod 644 node1.toml
```

配置文件保持只读挂载。容器所需的路径、监听地址和示例凭据通过 `WK_*` 环境变量覆盖，不必手工复制一份 Docker 专用 TOML。

## 2. 生成部署环境文件

先把 `WK_PUBLIC_HOST` 改成客户端能访问的主机名或 IP。首次本机验证可使用 `127.0.0.1`；远程客户端不能使用回环地址。

```bash
export WK_PUBLIC_HOST='im.example.com'

cluster_token=$(openssl rand -hex 32)
manager_secret=$(openssl rand -hex 32)
manager_password=$(openssl rand -hex 16)

(
  umask 077
  {
    printf '# Manager username: admin\n'
    printf '# Manager password: %s\n' "$manager_password"
    printf 'WK_NODE_DATA_DIR=/var/lib/wukongim\n'
    printf 'WK_CLUSTER_LISTEN_ADDR=0.0.0.0:7000\n'
    printf 'WK_CLUSTER_NODES=[{"id":1,"addr":"wukongim-node1:7000"}]\n'
    printf 'WK_CLUSTER_JOIN_TOKEN=%s\n' "$cluster_token"
    printf 'WK_API_LISTEN_ADDR=0.0.0.0:5001\n'
    printf 'WK_EXTERNAL_TCPADDR=%s:5100\n' "$WK_PUBLIC_HOST"
    printf 'WK_EXTERNAL_WSADDR=ws://%s:5200\n' "$WK_PUBLIC_HOST"
    printf 'WK_MANAGER_LISTEN_ADDR=0.0.0.0:5301\n'
    printf 'WK_MANAGER_AUTH_ON=true\n'
    printf 'WK_MANAGER_JWT_SECRET=%s\n' "$manager_secret"
    printf 'WK_MANAGER_USERS=[{"username":"admin","password":"%s","permissions":[{"resource":"*","actions":["*"]}]}]\n' "$manager_password"
    printf 'WK_BENCH_API_ENABLE=false\n'
    printf 'WK_DEBUG_API_ENABLE=false\n'
    printf 'WK_LOG_DIR=/var/lib/wukongim/logs\n'
    printf 'WK_PROMETHEUS_DATA_DIR=/var/lib/wukongim/prometheus\n'
    printf 'WK_PLUGIN_DIR=/var/lib/wukongim/plugins\n'
    printf 'WK_PLUGIN_SOCKET_PATH=/run/wukongim/plugin.sock\n'
    printf 'WK_PLUGIN_SANDBOX_DIR=/var/lib/wukongim/plugin-sandbox\n'
    printf 'WK_PLUGIN_STATE_DIR=/var/lib/wukongim/plugin-state\n'
  } > .env
)

unset cluster_token manager_secret manager_password WK_PUBLIC_HOST
```

`.env` 包含明文凭据，不能提交到版本库。这个文件让首次部署可复现，但环境变量仍可能出现在容器检查和平台控制面；生产环境应改用部署平台的 Secret 能力，并收紧 Manager 权限。

`WK_EXTERNAL_TCPADDR` 和 `WK_EXTERNAL_WSADDR` 是客户端广告地址，不是监听地址。生产 TLS 通常在受控代理或负载均衡器终止，此时应改为真实的 TCP/TLS 与 WSS 入口；不要把 `0.0.0.0` 写进广告地址。

## 3. 创建 Compose 文件

将下面内容保存为 `compose.yaml`：

```yaml
name: wukongim

services:
  node1:
    image: ghcr.io/wukongim/wukongim:3.0.0-beta.5@sha256:7112c059dc5517ee6370b340b4a3180c10244553e8e946f44640014c67890516
    container_name: wukongim-node1
    restart: unless-stopped
    stop_grace_period: 30s
    env_file:
      - ./.env
    volumes:
      - ./node1.toml:/etc/wukongim/wukongim.toml:ro
      - wukongim-node1-data:/var/lib/wukongim
    tmpfs:
      - /run/wukongim:rw,noexec,nosuid,uid=10001,gid=10001,mode=0750,size=16m
    ports:
      - "127.0.0.1:5001:5001"
      - "0.0.0.0:5100:5100"
      - "0.0.0.0:5200:5200"
      - "127.0.0.1:5301:5301"
    healthcheck:
      test: ["CMD", "wget", "-q", "--spider", "-T", "5", "http://127.0.0.1:5001/readyz"]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 20s

volumes:
  wukongim-node1-data:
```

这里的网络边界是有意设置的：

- `5100`（TCP）和 `5200`（WebSocket）是客户端 Gateway，发布到宿主机；防火墙仍应只允许预期流量。
- `5001` 同时承载 Product HTTP API、就绪、Metrics 和 Top，默认只绑定宿主机回环。远程可信后端需要访问时，应改绑受保护的内网地址或放在外部鉴权代理之后。
- Manager `5301` 默认只绑定回环；节点 Transport `7000` 不发布到宿主机。
- 配置只读，数据、日志和 Plugin 持久状态进入 named volume；Unix Socket 留在临时的 `/run/wukongim`。

GHCR 不可用时，可以把 `image` 替换为以下任一已验证的同摘要镜像：

```text
wukongim/wukongim:3.0.0-beta.5@sha256:7112c059dc5517ee6370b340b4a3180c10244553e8e946f44640014c67890516
registry.cn-shanghai.aliyuncs.com/wukongim/wukongim:3.0.0-beta.5@sha256:7112c059dc5517ee6370b340b4a3180c10244553e8e946f44640014c67890516
```

升级版本时，标签、摘要和配置模板版本必须成对更新并重新验证。

## 4. 启动并验证

先检查 Compose 语法和必需文件，再拉取并启动：

```bash
docker compose config --quiet
docker compose pull
docker compose up -d
docker compose ps
```

等待 `/readyz` 成功，并检查最近日志与实际挂载：

```bash
curl --retry 30 --retry-delay 2 --retry-all-errors --fail \
  http://127.0.0.1:5001/readyz

docker compose logs --tail 100 node1
docker inspect wukongim-node1 \
  --format '{{range .Mounts}}{{println .Destination .Type .RW}}{{end}}'
```

检查结果应满足：

- `docker compose ps` 显示容器为 `healthy`；
- `/etc/wukongim/wukongim.toml` 是只读 bind mount；
- `/var/lib/wukongim` 是可写 volume；
- `/readyz` 返回成功后才接入业务流量。

在部署主机浏览器打开 `http://127.0.0.1:5301`。远程部署时，从本地为 Product API 和 Manager 建立 SSH 隧道，再打开相同地址：

```bash
ssh -N \
  -L 5001:127.0.0.1:5001 \
  -L 5301:127.0.0.1:5301 \
  user@server
```

用户名为 `admin`，密码可以在部署主机查看：

```bash
sed -n 's/^# Manager password: //p' .env
```

Manager 登录和 `/readyz` 只证明管理面与节点已启动。继续按照[快速开始](/zh/guide/quick-start)连接两个测试用户，完成一次发送与接收，才算验证真实消息链路。

## 5. 日常操作与数据边界

```bash
# 跟踪日志
docker compose logs --follow --tail 100 node1

# 优雅重启；Compose 最多等待 stop_grace_period
docker compose restart node1

# 停止或重新启动同一容器
docker compose stop node1
docker compose start node1

# 删除容器和默认网络，但保留 named volume
docker compose down
```

不要对需要保留的数据运行 `docker compose down -v`。更换或重建容器前，应确认仍使用同一 `wukongim-node1-data` volume。升级和回滚按[升级与迁移](/zh/server/operations/upgrade-and-migration)执行，不要只移动镜像标签。

| 现象 | 优先检查 |
| --- | --- |
| 容器反复重启或保持 `unhealthy` | `docker compose logs --tail 200 node1`；确认 `.env` JSON、配置文件和 volume 可用 |
| `/readyz` 返回 `503` | 节点尚未满足流量门槛；检查日志中的 Controller、Slot、存储与配置错误，不要改用 `/healthz` 接流量 |
| 客户端无法连接 | 检查 `WK_EXTERNAL_*`、防火墙、代理和目标网络；广告地址不能是 `0.0.0.0` 或远程客户端的 `127.0.0.1` |
| 远程无法打开 Manager 或 Product API | 默认回环绑定是预期行为；使用 SSH 隧道，或只绑定到受保护内网并增加访问控制 |
| 重建后数据为空 | 立即停止写入，检查实际挂载；不要创建新 volume，也不要运行 `down -v` |

<details>
<summary>没有 Compose 时使用 docker run</summary>

下面的命令复用同一 `.env`、配置和数据边界：

```bash
export WK_IMAGE='ghcr.io/wukongim/wukongim:3.0.0-beta.5@sha256:7112c059dc5517ee6370b340b4a3180c10244553e8e946f44640014c67890516'

docker network inspect wukongim >/dev/null 2>&1 || docker network create wukongim
docker volume inspect wukongim-node1-data >/dev/null 2>&1 || docker volume create wukongim-node1-data

docker run -d \
  --name wukongim-node1 \
  --network wukongim \
  --restart unless-stopped \
  --stop-timeout 30 \
  --env-file .env \
  --mount type=bind,src="$PWD/node1.toml",dst=/etc/wukongim/wukongim.toml,readonly \
  --mount type=volume,src=wukongim-node1-data,dst=/var/lib/wukongim \
  --tmpfs /run/wukongim:rw,noexec,nosuid,uid=10001,gid=10001,mode=0750,size=16m \
  --health-cmd='wget -q --spider -T 5 http://127.0.0.1:5001/readyz' \
  --health-interval=10s \
  --health-timeout=5s \
  --health-retries=12 \
  --health-start-period=20s \
  -p 127.0.0.1:5001:5001 \
  -p 0.0.0.0:5100:5100 \
  -p 0.0.0.0:5200:5200 \
  -p 127.0.0.1:5301:5301 \
  "$WK_IMAGE"
```

</details>
