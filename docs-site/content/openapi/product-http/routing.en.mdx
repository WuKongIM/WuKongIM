`GET /route` returns the configured client Gateway addresses.

## Key points

- On HTTPS pages, prefer a non-empty `wss_addr`; otherwise use `ws_addr`.
- The browser sample does not use `tcp_addr`.
- Rediscover after disconnect instead of caching an old address forever.

<Callout type="warn" title="Discovery is not authentication">
  A successful `/route` call proves neither UID authorization nor CONNECT success.
</Callout>

If addresses are empty, check the external Gateway configuration. If the address is reachable but CONNECT fails, inspect the protocol version and CONNACK Reason Code.
