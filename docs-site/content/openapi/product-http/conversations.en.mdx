## Goal and completion criteria

This page publishes six operations for the canonical Conversation projection: bounded list traversal, unresolved-key retry, clear unread, set an unread ceiling, hide, and explicit activation. The trusted product backend should continue until `done=true`, handle `deletes` and `unresolved` independently, and rebuild its local projection when required.

## List synchronization state machine

1. Call `/conversation/list` first with an empty `cursor`, a bounded `limit`, and the saved `completed_coverage`;
2. apply `conversations`, remove `deletes`, and send `unresolved` to `/conversation/retry`;
3. even when the page arrays are empty, pass the opaque `next_cursor` back unchanged while `done=false`;
4. persist this pass's `coverage` only after `done=true`;
5. when `reset_required=true`, discard the stale local Conversation projection and rebuild from an empty cursor.

`read_seq` is a monotonic badge floor, not a message-pull cursor or read receipt. `unread` also applies join, retention, deletion, and current-user-last-send visibility floors. A person Channel projects `channel_id` to the peer UID at the HTTP boundary.

`ConversationListResponse` exposes `tombstones_retained_since` for reset decisions. Each visible item can carry a nullable `ConversationLastMessage`; use its string-safe `message_idstr` as the message identity, while `payload` is a nullable base64-encoded string in JSON. Compatibility failures use `CompatibilityError` (`400 {"msg","status":400}`); restore maintenance uses `MaintenanceError` (`503 {"error":"maintenance","message":"restore maintenance is active"}`).

## Mutation semantics

- `/conversations/clearUnread` advances to the latest committed head at call time and accepts no `message_seq`;
- `/conversations/setUnread` only advances `read_seq`, so it can reduce unread to at most the target but cannot increase unread;
- `/conversations/delete` hides this user's projection through the current committed head; it deletes neither the Channel nor membership, and a later message can make it visible again;
- `/conversations/activate` records an explicit open, switch, or restore action; send, receive, delivery, and pull paths do not call it implicitly.

## Legacy synchronization deferred

`POST /conversation/sync` remains a legacy compatibility route in the runtime, but it is outside this canonical Beta contract. It uses a delimited `last_msg_seqs` string, a bare-array response, legacy message projection, and a compatibility scan of at most 1,000 candidates without completion or truncation indicators. New integrations should use `/conversation/list` and `/conversation/retry`; existing callers should remain pinned until that route receives a separate exact-version calibration.

## Errors and troubleshooting

- **An empty page ends the loop early:** only `done=true` proves traversal completion; an empty `conversations` array does not.
- **A cursor returns 400:** the cursor is a versioned base64url value; echo it unchanged instead of decoding and reconstructing it.
- **Keys remain unresolved:** retry at most 200 keys and retain failures in a bounded backoff queue; do not rewind full-list coverage.
- **reset_required=true:** saved coverage predates retained tombstones, so rebuild the local projection.
- **503 maintenance:** pause business calls and observe `/readyz`.

## Security and OpenAPI contract

The request `uid` is merely a field, not authenticated identity. Default Product HTTP has no business-authentication middleware, so the product backend must prove authority to represent that UID and access each Channel. The page is generated from the management contract's `Conversations` tag; download the [management subset contract](/contracts/product-http-management.openapi.json).
