`POST /channel/messagesync` pulls a bounded page of committed Channel messages. Realtime send and receive remain on the SDK and Gateway.

## Key points

- The sample limits `limit` to `1–100`.
- Advance the sequence cursor between pages; do not keep sending zero boundaries.
- For a person Channel, `channel_id` is the peer UID.
- Realtime RECV and sync may overlap; deduplicate with `message_idstr` first.
- An empty `messages` array is valid.

<Callout type="warn" title="A request UID is not a credential">
  `login_uid` is only a field. The trusted backend must still verify authority to represent that UID and read the Channel.
</Callout>

For an empty result, first confirm a successful SENDACK, then check direction, cursors, and membership visibility. When `more=1`, continue from the page's last sequence.
