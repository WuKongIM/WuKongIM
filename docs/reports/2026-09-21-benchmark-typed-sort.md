# 压测快照精确排序 CPU 优化 — 2026-09-21

将时延快照的 `sort.Slice` 比较回调替换为标准库 `slices.Sort`。在本地 81 万随机样本上，完整 `Collect` 耗时中位数从 75.133ms 降至 44.592ms（减少 40.6%），每次分配从 8 次降至 6 次。精确 P50/P95/P99、求和、极值、快照一致性和 SLO 判定保持不变。

基线为 `ca276ae2480741efd97d0f15a69f1440bd3a7100`。前序[锁竞争修复](2026-09-21-benchmark-snapshot-lock.md)已经释放排序期间的生产者锁，但其三节点业务 profile 中 `Collect` 仍占约 76% CPU 采样。本轮仅处理该热点的排序开销；不代表服务端或跨 ECS 业务延迟已改善。

原始数值、指令摘要、源码及二进制校验值、profile 位置见[机器可读证据](assets/benchmark-typed-sort-2026-09-21.json)。

## 假设与选择

按顺序检查：比较/交换回调是否造成可移除的 CPU 开销；复制和求和是否占用明显；保留完整排序是否仍然昂贵。用固定输入比较旧实现与仅替换排序的隔离候选，然后在实际 `Collect` 路径再次测量。这里采用性能证据路线，不在单元测试中设置依赖机器速度的时间断言，也不把统计正确性测试冒充性能故障的失败用例。

算法探针使用 30,000 和 810,000 个样本，覆盖随机、有序、逆序、全部相同、少量重复值及先升后降输入；每项 5 次汇总、重复三轮，计时包括私有切片复制。81 万样本的中位数如下：

| 输入 | 旧实现，ms | 类型化排序，ms |
|---|---:|---:|
| 随机 | 72.460 | 44.529 |
| 有序 | 1.754 | 0.815 |
| 逆序 | 2.225 | 0.976 |
| 全部相同 | 1.703 | 0.814 |
| 16 种重复值 | 16.265 | 9.249 |
| 先升后降 | 28.392 | 10.853 |

有序/相同输入包含复制与求和，耗时远低于随机输入，结合下文 profile，排序比较仍是主要成本。标准库替换已获得明显收益，本轮没有引入自定义选择算法、缓存或近似分位数。实现仍完整排序，保留标准库处理不同输入形态的路径；这些有限输入测试不是任意输入的性能保证。

## 完整快照与 CPU 验证

Apple M4，macOS arm64，Go 1.25.11，GOMAXPROCS=4。复用实际 `Registry.Collect` 并发写入微基准：固定随机历史，每项 10 次快照、三轮，另一个 goroutine 由 1ms ticker 驱动写入计数器。基线和候选顺序执行，不同时运行其他测试或微基准。

| 历史样本数 | 基线中位数，ms | 候选中位数，ms | 耗时减少 |
|---|---:|---:|---:|
| 30,000 | 1.998 | 1.602 | 19.8% |
| 270,000 | 23.023 | 13.760 | 40.2% |
| 810,000 | 75.133 | 44.592 | 40.6% |

最小规模候选三轮波动为 1.316–2.175ms，故不把其收益当作稳定精确比例。81 万样本候选为 44.447–45.541ms，基线为 73.581–75.278ms。该规模仍分配约 6.49MB/op，复制的样本量没有减少；每次少两次分配主要消除了排序适配开销。

上述六组基准的所有已观测计数器写入均低于 1ms，候选最大观测为 0.607ms。ticker 会合并事件，而且候选执行时间更短、写入观察数更少，这不是写入 P99 或最大停顿保证，也不据此声称比前一版进一步改善了锁等待。

另外针对 81 万样本各执行 100 次 `Collect` 并采 CPU profile：

| 指标 | 基线 | 候选 |
|---|---:|---:|
| 每次快照耗时，ms | 74.546 | 44.584 |
| profile 窗口，s | 7.71 | 4.71 |
| 总采样 CPU 时间，s | 6.90 | 4.15 |
| `Collect` 累计采样 CPU 时间，s | 6.67 | 4.05 |

两次 profile 是相同基准工作量，不是相同窗口长度；包括测试工具初始化/校准。旧实现中比较闭包单独占 1.44 CPU 秒，反射交换函数占 0.30 秒；候选转为 `slices` 的有序类型排序路径。CPU 总采样减少约 39.9%，与耗时变化方向一致。候选中排序仍占绝大多数采样，不能仅看其占比就认定没有改善；父子累计项也不能相加。

## 回归与复现

71 组确定性案例对照旧精确汇总，覆盖空输入、单值、分位数边界附近样本数、有序/逆序/重复值、负值、极端 int64 和既有 duration 求和溢出语义。已有并发测试继续验证快照原子捕获、私有样本归属及聚合期间生产者可写。`metrics`、`report`、`workload`、`worker` 的 integration + race 测试均通过。

```sh
GOWORK=off go test -race -tags=integration ./internal/bench/metrics \
  ./internal/bench/report ./internal/bench/workload ./internal/bench/worker -count=1
GOWORK=off go test -tags=integration ./internal/bench/metrics -run '^$' \
  -bench '^BenchmarkExactSummary$' -benchtime=5x -count=3 -cpu=4 -benchmem
GOWORK=off go test -tags=integration ./internal/bench/metrics -run '^$' \
  -bench '^BenchmarkCollectWithConcurrentWriter$' -benchtime=10x -count=3 -cpu=4 -benchmem
```

保留的算法基准直接调用产品 `summarizeDurations` 与旧参考实现，供后续复测。初始算法探针在修改产品前使用等价的临时候选函数，临时候选已经删除；最终完整快照与 profile 使用产品代码。

本次只改排序实现，已有 FLOW 的捕获、锁外聚合及串行收集说明仍准确，无需修改。没有新增云资源或业务服务进程。没有重跑 180 秒三节点业务实验或跨 ECS 测试；此前云上约 194ms P99 和发送缺口仍未在本轮验证。旧精确样本保留内存仍随运行时间增长，长时压测须继续关注这一限制。
