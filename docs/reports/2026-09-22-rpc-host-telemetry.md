# RPC 主机采样与时钟对齐：本地验证完成

已完成有界 Linux 主机/网络采集器、探针单调时钟锚点和离线关联工具。
本地 Linux 容器功能验证完成 **975,202 次 RPC，零错误**，双端样本覆盖全部6个测量秒。
这证明诊断链路可用，不能证明原生双机性能稳定，也没有确定
[上一轮重复性失败](2026-09-22-rpc-native-results.md)的根因。

本轮只修改诊断工具、相关测试和文档；没有修改产品 transport 运行时、采购云主机或调用云控制器。
实现提交：`9c8032bb56011977ba5c5db66efcab9bd1e9c97b`。

## 实现与边界

- 1 Hz 独立采集，最长900秒；限制线程、CPU行数、接口数、单次读取、记录和总输出大小。
  只读取固定的CPU/PSI、TCP、网卡、softnet、进程和线程计数；不记录命令行、环境、原始主机标识或报文。
- 采集器用PID启动时间、可执行文件inode和命名空间防止采集中途身份变化；分析器额外核对主机/
  boot摘要、PID、启动时间和可执行文件SHA256。线程身份也包含启动时间。
- 客户端使用测量起点的单调时钟区间；服务端复用已有的两个边界RPC建立时钟偏移区间。
  保留1000 ppm相对漂移假设与误差范围，拒绝时钟不一致或大于100 ms的不确定性；不假定双机UTC同步。
- 计数增量保留在采样区间，只列出可能重叠的RPC秒段，不将一次重传复制或平均分配到各秒。
  缺失指标、计数回退、线程变化、采样间断、过长读取和时钟跳变均显式保留。
- TCP/网卡统计覆盖目标网络命名空间，CPU/PSI/softnet覆盖主机；均不能直接归因于单个RPC。
  存活线程的调度计数是下界，采样间出现又消失的线程仍可能不可见。
- 客户端诊断标记 `-telemetry-tail=2s` 为最后一秒保留采样尾部，重复性验收器拒绝带此标记的报告。
  任意外部采样无法被验收器自动发现，操作流程仍必须将采样诊断与纯计时验收分开。
- 超时/中断只清理由采集器启动的子进程；附着模式不会向目标发送信号。输出独占创建且权限0600，
  截断证据不被接受。内核缺少指标时不会擅自调整内核设置。

操作命令、单位、缺失数据语义和完整限制见[工具说明](../../scripts/transport-perf/README.md)。

## 本地结果

环境为缓存的 `golang:1.25.11-bookworm` Linux arm64 容器，两个独立探针进程使用同机loopback；
网络隔离，无对外端口。GOMAXPROCS=4、64B、16调用者、单连接、预热1秒、测量6秒、保留尾部2秒。
服务端有独立生命周期，测试结束后正常SIGTERM退出；容器自动删除，并核验无本轮容器残留。

| 指标 | 客户端采集器 | 服务端采集器 |
| --- | ---: | ---: |
| 采样数 | 10 | 14 |
| 采集区间CPU时间 | 26.669 ms | 48.710 ms |
| 占单核比例 | 0.289% | 0.348% |
| 平均一次读取 | 1.035 ms | 1.853 ms |
| 最长一次读取 | 2.437 ms | 3.186 ms |
| 进程峰值RSS | 17,996 KiB | 18,040 KiB |
| 原始文件大小 | 50,468 B | 76,628 B |
| 测量秒段覆盖 | 6/6 | 6/6 |

CPU比例以采集区间为分母，包含可执行文件哈希、循环、读取和采样输出；不包含Python解释器/
模块导入启动及最终退出。它不是客户端/服务端时延受扰动幅度，也不是原生云主机的开销上界。
本轮没有以带采样和不带采样的吞吐差推导性能收益。

容器没有 `/proc/sys/kernel/sched_schedstats`，因此调度运行队列等待不可用；服务端还观察到线程变化。
分析器如实输出 `partial`，没有用0代替缺失计数，也没有宣称获得了完整调度证据。
客户端测量起点时钟区间宽291 ns；本次服务端偏移包络约为 −6.305 ms 至 +6.840 ms，
包含边界RPC耗时和所声明的漂移余量。真实跨主机的时钟偏移仅由构造测试覆盖，尚未部署双机验证。

## 验证与可复核证据

- 30项Python快速测试通过：解析字段、读取/输出上限、缺失统计、身份变化、PID/线程复用、计数回退、
  双机不同单调时钟起点、漂移/跳变、采样间断和尾部缺失、旧报告缺少锚点、诊断标记拒绝等。
- Go探针单元测试及macOS真实进程race集成测试通过；Linux容器的探针进程集成测试通过，
  包含echo计数守恒、样本耗尽和边界时钟顺序核对。
- 5项Linux采集器进程集成测试通过：正常子进程、独占证据、超时清理、附着目标存活、信号处理和上限失败清理。
  所有涉及真实进程/等待的Go测试均位于 `integration` 构建标签下。
- 从干净提交用公共构建器生成Linux amd64、Linux arm64、Darwin arm64探针；三个构建清单、
  全部探针源文件摘要和实际二进制SHA256均已逐一核对。Linux amd64只验证了交叉编译，未在原生amd64主机执行。
- 完整本地链路核对逐秒/整窗/服务端echo计数守恒，并通过CLI重新生成双端关联结果，与程序调用结果一致。

测试输出、功能验证脚本、原文件摘要和采集器开销；可离线重建关联结果。这里没有优化候选的验收结论。
