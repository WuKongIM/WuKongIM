**RPC 锁隔离实验与同步响应复制优化 — 2026-09-21**

本轮继续分析[跨 ECS 复测](2026-09-21-transport-cloud-retest.md)留下的 RPC 并发退化。保留的改动省去服务端同步响应的一次中间复制：本地 Linux 65,537B RPC 的 16 并发吞吐中位数提升约 54%，每调用分配字节下降约 33%；小包并发吞吐基本持平。取消监听移出队列锁的独立实验未显示并发收益，已撤回。没有购买服务器或重新执行跨 ECS 测试，不能据此宣布云上退化全部修复。

**验证路线与取舍**

开始前按优先级列出四个假设：取消监听注册/解绑扩大共享队列锁争用、监听器分配增加 GC 压力、队列到执行器调度增加小包开销、大包重复复制增加 CPU/分配成本。本轮先隔离锁范围，再依据明确的连续复制调用链验证大包假设；没有同时改变两项变量。

锁实验为每个请求增加局部同步，将注册/解绑移出 `Service.mu`。可控 context 注册阻塞测试在旧实现失败，实验版本通过，取消/停机/出队竞态测试在 race 下重复 10 次通过。这证明了锁耦合，但该注入场景不能代替真实 TCP 性能判据。独立 5s mutex 剖析的累计等待从约 6.47s 降到 2.67s，`Service.Enqueue` 累积等待从约 4.11s 降到 1.24s；剖析包含 benchmark 校准阶段、调用数不同，只能用于定位，不能解读为每请求等待降幅。

三轮交错、每项 3s 的无剖析 TCP 对照却得到：

| 锁实验：字节 / 并发 | 基线 ns/op 中位数 | 实验 ns/op 中位数 |
|---|---:|---:|
| 64 / 1 | 12,324 | 11,692 |
| 64 / 16 | 3,605 | 3,738 |
| 65,537 / 1 | 91,729 | 90,440 |
| 65,537 / 16 | 70,116 | 70,991 |

并发吞吐中位数分别下降约 3.6% 和 1.2%，分配仍为 46 次；因此没有保留额外同步结构。实验补丁和注入测试仅存于本地 `debug-rejected-lock` 证据目录。

**保留的修复**

原路径为 `Service.handle` 复制 handler 返回值，然后服务端同步回调中的 `EncodeRPCResponse` 再复制到自有 wire buffer。请求 payload 在回调返回后才释放，第一份临时副本没有延长必要的生命周期。

内部回调改名为 `RespondBorrowed`，明确 payload 仅在回调期间有效，接收者必须在返回前完成复制或编码。服务端同步编码成自有 wire buffer，随后沿既有发送队列执行。异步 `Reply` 通道保留原有复制语义。公共 transport API、线协议、队列预算、取消语义、执行并发及内存准入均未改变。

先运行响应交付边界微基准：64B 和 65,537B 各三轮均产生 1 次中间分配，分别为 64B 和 73,728B。修改后六个样本全部为零分配，达到“无中间响应分配”的诊断判据。此微基准不含网络和预算，其时间/带宽不能当作 RPC 性能；没有把机器敏感的吞吐阈值加入 CI。

**完整 TCP 对照**

Go 1.25.11，Apple M4 上的 Docker Desktop Linux ARM64 VM，原生静态 ARM64 测试程序，GOMAXPROCS=4、CPU 0–3、内存上限 6GiB。沿用已有 amd64 Debian rootfs，但只执行原生 ARM64 测试二进制，不调用镜像内用户态程序。仍不能替代 x86 跨 ECS 环境。

沿用 `BenchmarkTransportBudget`：16 个预热连接、请求预算开启、1/16 个调用者、服务并发 64、队列预算 5s、执行预算 30s、每调用超时 2s、Observer 关闭，逐次校验完整响应。三轮交错前/后、后/前、前/后，每项 3s；性能窗口与编译、回归测试分开执行。以下为中位数，ns/op 是吞吐倒数，并行时不是请求 RTT；分配包含客户端和服务端。

| 字节 / 并发 | ns/op：前 → 后 | 吞吐变化 | B/op：前 → 后 | allocs/op |
|---|---:|---:|---:|---:|
| 64 / 1 | 12,363 → 12,035 | +2.7% | 2,889 → 2,825 | 46 → 45 |
| 64 / 16 | 3,714 → 3,737 | −0.6% | 2,890 → 2,826 | 46 → 45 |
| 65,537 / 1 | 96,765 → 74,113 | +30.6% | 232,538 → 156,236 | 46 → 45 |
| 65,537 / 16 | 75,763 → 49,168 | +54.1% | 231,259 → 154,913 | 46 → 45 |

所有用例通过完整内容校验，无失败调用。大包分配下降约 33%，其中确定省去的单份临时分配为 73,728B，其余差额受缓冲池/GC 等影响；不要把全部差额都归为这一份数组。小包样本范围重叠，不宣称其吞吐改善或退化已确定。

**回归与限制**

- `GOWORK=off go test -race -tags=integration ./pkg/transport/... ./pkg/cluster/net -count=1` 通过，10 个包。
- 新增真实 service 执行测试：handler 返回请求数据的别名，回调复制之后释放函数立即清空原字节；检查内容、释放顺序、唯一回调、Finish 以及对 Reply 的优先级。
- 扩展 wire 编码测试，清空借用源字节后，自有响应 buffer 仍保持完整；既有异步 Reply 复制测试保留并通过。
- 既有队列超时、取消、断连、只读取消、已开始写操作继续执行、panic、背压和 typed remote error 回归通过。

本轮确认的是同步响应多余复制及本地大包收益。取消监听的分配热点和小包并发瓶颈仍未解决，云上 5.3%/8.8% 吞吐退化是否恢复仍需相同跨 ECS 场景验证。所有此前测试云资源已释放，本轮仅使用本地环境。
