# 小包 RPC 独立进程归因与队列定时器复用

本轮建立了稳定的本地小包对照：固定旧客户端，当前服务端相对旧服务端吞吐中位下降
**17.28%**，六轮同向，P99由0.160ms升至0.457ms。该ARM64 loopback结果与云上
小包回退方向一致，但不是原生x86跨主机8.24%回退的复测或等量归因。

实施一个窄优化：每个服务复用一个FIFO队列截止时间定时器，保留逐请求取消监听。
隔离分配回归从3次降至1次；旧协议小包P99中位下降15.75%，请求预算开启时下降4.66%。
吞吐提升仅约0.5%，未超出同版本对照的波动范围，**原吞吐回退仍未解决**。

[机器可读证据](assets/rpc-small-local-queue-timer-2026-09-22.json)保存全部输出、逐调用者
样本数、构建身份、候选补丁、测试日志、剖析表与清理回执。原始文件保留在

## 方法与版本

- 旧服务端：`68662c4c8`；分配优化前：`a689006cf`；当前基线：`5e159cd36`
  （产品transport与`d9d732cef`相同）。候选从当前基线修改两个RPC生产文件，补丁封存在证据中。
- 共同echo探针由前轮源码重建，补充每worker计数、截断标志、架构、客户端GC/分配计数。
  任一worker达到100万样本即失败，不再只依赖聚合数推断未截断。三个版本先做1s冒烟。
- Go1.25.11，GOWORK=off，CGO关闭，Linux ARM64静态构建，`-trimpath -buildvcs=false`。
  Apple M4的Docker Desktop VM；Debian amd64镜像仅作为rootfs，程序输出确认arm64。
- 客户端CPU0–3，服务端CPU4–7，各GOMAXPROCS=4、GOGC=100、容器上限3GiB；独立进程与GC，
  同一网络命名空间loopback，无主机端口暴露。Observer关闭，16个预热连接、16个调用者。
- 主矩阵固定旧客户端，关闭客户端预算，64B；三种服务端轮换全部六种排列，每项10s。
  服务并发64、队列4096项/64MiB、执行30s、调用2s；新服务端队列时限5s，旧版没有这项语义。
  这些版本比较定位新增行为的成本，不能用回滚旧语义作为修复。
- 纯计时不运行构建、测试或剖析。同版本A/A对照另行保留。RTT分位数沿用
  `floor((n-1)*p)`，逐次校验完整响应。延迟样本每worker预分配10万，随后按相同算法增长；
  客户端B/call不是服务端分配，不能据其差值推导服务端节省。

## 反馈环与假设

可复现驱动为证据中的`run.py`，已完成六轮版本排列及两组A/A。先检验新队列的取消监听/
分配、服务锁/执行器调度、本机噪声三个方向，再依据CPU、allocs、mutex、block和trace
选择单变量候选。没有跳过取消、超时、FIFO、共享执行器或保留字节准入。

|服务端|中位 RPC/s|P99中位 ms|相对旧版吞吐|
|---|---:|---:|---:|
|旧版|263,567.3|0.160229|—|
|分配优化前|214,995.5|0.603438|-18.43%|
|当前基线|218,029.2|0.457000|-17.28%|

两组同二进制配对吞吐变化为 -0.71%、-2.24%，明显小于主矩阵差距。
这个本地反馈环支持后续窄改动评估，但不等于正式统计显著性或一般容量保证。

## 剖析与实现选择

三种服务端分别采CPU8s与累计allocs/mutex/block，另起进程采trace3s；候选再采一组。
共8个诊断运行、20份原始性能文件及8份trace派生文件，全部可解析。诊断吞吐不参与计时表。
采集时间为请求边界，累计样本含初始化和预热，不能除以另一窗口的调用数。

当前基线 `watchQueue` 调用栈占累计分配38.34%，`Enqueue`占CPU11.83%（旧版2.79%）；
其调用栈占mutex累计等待83.01%（旧版37.37%）。这些占比有包含关系，不能相加或解释成
吞吐损失比例。它们支持先减少入队临界区内的逐请求定时器分配，不证明一个机制解释全部回退。

原实现每个需要更早队列截止时间的请求调用`time.AfterFunc`。现在服务持有一个可复用timer：
FIFO和固定服务队列时限保证队首的队列截止时间最早；队首入队、出队或取消时，按新队首的
**原始入队时间**重设timer。调用方deadline更早时仍依赖其独立取消监听。

timer不捕获某个请求对象。已开始的旧回调先在服务锁下重新检查当前队首及截止时间，
再沿用`expire`与出队/取消竞争终结所有权；不能提前过期新队首。空队列和停机停止timer。
没有新增每服务后台循环，没有池化请求或提前复用对象。执行器等待期间仍执行原有预算检查。

复用减少timer与闭包分配，但仍需Stop/Reset和原有取消上下文。候选`watchQueue`累计分配占比
为33.79%，`time.AfterFunc`从12.60%降到7.17%（执行时限等仍使用它）；这些采样占比不是精确的
每请求节省。原始云上回退及剩余服务端锁/取消开销仍需继续归因。

## 候选独立进程验收

旧协议小包4轮AB/BA；再固定当前客户端、开启预算，小包和65537B各3轮AB/BA。
每项10s，其他CPU与服务限制相同。两种当前服务端都支持预算协商，候选不更改协议。

|场景|基线 RPC/s|候选 RPC/s|吞吐变化|基线 P99 ms|候选 P99 ms|P99变化|
|---|---:|---:|---:|---:|---:|---:|
|旧客户端/64B|217,250.0|218,331.5|+0.50%|0.471187|0.396958|-15.75%|
|当前客户端+预算/64B|215,583.5|216,787.2|+0.56%|0.526750|0.502208|-4.66%|
|当前客户端+预算/65537B|57,191.6|57,065.9|-0.22%|2.012625|2.020458|+0.39%|

旧协议小包P99四轮全部下降，预算小包三轮全部下降；旧协议吞吐存在方向反转。
小于1%的吞吐变化不足以证明稳定提升。大包吞吐方向混合，P99三轮小幅上升，不能宣布
所有性能维度均改善。保留候选的依据是确定的分配下降、此本地小包尾延迟结果和语义回归，
不是宣称17.28%的主回退已经修复。未测业务SEND、十万成员群、最大容量或长时稳定性。

## 测试与交付

- 新增真实`Enqueue → pump → executor → Finish`分配回归，队列时限开启，资源与通知复用。
  实现前明确失败：3.00 objects/request；候选macOS和Linux ARM64各20次通过，最多1次。
  这是不含网络及调用方上下文创建的隔离成本；测试带`integration && !race`，不把竞态插桩
  作为产品分配。timer预热后复用，首次创建不计入稳定态节省。
- 新增队首取消后保留尾请求原始截止时间、迟到回调不提前过期新请求的回归。
- `go test ./pkg/transport/... -count=1`通过全部9个包。
- `go test -race -tags=integration ./pkg/transport/... -count=1 -timeout=4m`通过全部9个包，
  包含预算、取消、共享执行器、停机、panic、保留字节与旧节点兼容。
- 队列deadline/expiry/budget竞态回归另连续20次通过，覆盖本次重设timer的并发风险。
- 最后只修正回调说明文字；计时与最终二进制的`.text`和`.rodata`摘要一致，未更换计时代码。
- 42个纯计时窗口共 **86,087,418** 次成功RPC；8个诊断窗口共
  **25,611,815** 次，另3个冒烟窗口681,318次。全部零错误、
  零截断、16个worker计数与聚合一致；预热不计入这些数量。
