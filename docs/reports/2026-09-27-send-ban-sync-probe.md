# Linux 文件同步有界诊断

此前失败后 goroutine 只能显示 Fdatasync 栈，缺少数据库身份及操作
持续时间。本次创建独立 Pebble overlay 和诊断二进制，不修改工作树
中的产品实现、原产品二进制、同步语义或压力验收条件。

## 观测边界

在复制的 Pebble v2.1.4 Linux vfs 中包装 fdatasync、文件 fsync、目录
fsync 和 SyncTo；每次仍调用原实现一次，原样返回错误及 fullSync。
每进程保留最多 128 个进行中操作和最近 256 个耗时至少 50 ms 或报错
的已完成操作，溢出显式计数。记录固定操作类别、文件路径、开始时间及
耗时，路径和错误文本分别限制 256/128 字节。进行中操作提供采样时
已等待时间，不会因尚未返回而从观测消失。

每 250 ms 由独立 goroutine 在专用目录替换该 PID 的一个 JSON 文件；
快照复制后释放 recorder 锁，再执行文件 I/O。记录器不在同步调用路径
写日志或文件。该观测仍有计时、互斥和后台写入成本，仅供诊断，不能混入
无观测开销的性能对照。它不覆盖普通 Write、Preallocate 或非 vfs 路径，
采样也不是所有节点的原子快照。

临时开关 `WK_DIAGNOSTIC_SYNC_TRACE_DIR` 仅存在于诊断 overlay：初始化
读取后删除该键再进入产品配置验证；不改变其他 WK_ 键或产品的严格
未知配置检查，不作为产品配置交付。

## 先行验证

先写容量/复用、调用次数和错误透传、短操作排除、文本长度与旧 token
隔离契约，实际编译失败后实现。另先复现并修正采样时刻早于新操作导致
负年龄的问题。直接在上游模块单独测试最初因离线缺少其旧版测试依赖
失败，随后改用复制产品的既有依赖图，不联网下载或修改共享模块缓存。

首轮三节点正向验证在启动阶段被严格配置校验拒绝（未知诊断开关），
没有发送窗口，完整保留失败。先增加环境隔离失败契约，再修正初始化
消费开关。最终五项 recorder 契约及既有 SyncRangeSmokeTest、SyncingFile、
SyncingFileClose、SyncingFileNoSyncOnClose 通过，Linux 构建通过。

第二轮正向验证实际发送并接收 5000 条消息（25 频道、500/s、10 秒），
SENDACK P50/P95/P99 为 8/11/13 ms，RECV P99 为 13 ms，pending、
权限 busy 和 transport rejected 均为 0。三个 PID 观测文件分别记录
2818、3722、2839 个已完成同步操作，进行中为 0、overflow 为 0；该短测
没有保留到超过 50 ms 的操作，不代表完整负载没有同步停顿。

源码基准、上下文摘要、overlay、red/green、失败与成功日志、构建信息及
二进制身份见[准备清单](assets/send-ban-sync-probe-20260927/preparation-manifest.json)。
原产品 SHA-256 仍为 `2e4351d161c30925c5a19ec8eb2d1ac45c6c5e711c2075c92cb6297b7b0740a5`。
随后 `diagnostic-01` 按 5000 频道、4500 SEND/s、30 分钟目标启动；其
结果单独追加，不能以诊断构建替代 R2 或 R6 的正式资格。

## diagnostic-01 完整结果

原定 5000 频道、4500 SEND/s、30 分钟完成，进程级测试 PASS，runner
exit 0，累计 8,100,000 条消息且所有 25 个接收者各收到预期 324,000 条。
pending=0、权限 busy=0、transport rejected=0、metric sample errors=0。
SENDACK P50/P95/P99 为 9/52/163 ms，RECV P99 为 152 ms。
总运行 1988.524 秒（含冷预热和收尾）；磁盘采样最低 10.333 GiB，未触发
8 GiB 保护线，结束只剩容器 sleep，合成数据自动清理后约 20.9 GiB 可用。

三个 PID 分别完成 1,164,257 / 1,169,933 / 1,170,398 次被观测同步，
最终 active=0、overflow=0，保留慢操作 89 / 145 / 158 条，没有错误。
最大观测耗时分别 267.037 / 218.071 / 215.358 ms。最终文件更新时间
属于收尾阶段；记录环均未达到 256 条，但这仍不能覆盖未包装的 I/O，
也不能把持续时间解释为纯内核 I/O 耗时。

本次没有复现 EOF。诊断引入了时序和文件活动变化，因此不能把一次
带观测的成功解释成此前故障已修复，亦不替代无 overlay 的 R2 或 R6。
