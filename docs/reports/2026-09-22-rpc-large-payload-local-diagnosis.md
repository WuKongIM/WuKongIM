## 前轮信号与假设

前轮 102 项本地对照记录 35,041,260 次成功 RPC：65537B/16 并发的六轮中位变化，
预算开启为 −2.32%，关闭为 −2.28%，逐轮均负；再做三轮 10s 长采样，中位为 −1.12%，
逐轮同负。因此该信号需要调查，不能仅用少一次分配宣布通过。

实验前按顺序提出：

1. 合并对象改变布局或存活时间，可能增加 GC/内存访问成本；若成立，应看到可重复的
   吞吐下降以及相应剖析差异。
2. 缓冲池与 GC 波动主导差异；若成立，相关成本会随窗口改变，调整 GC 预算会显著影响基准。
3. 本机调度或构建布局导致差异；同二进制对照及机器码摘要可分别检查噪声和重建影响。

本轮未得到稳定失败的回归判据，按有界证据路线记录，未加入带噪声的吞吐阈值单元测试。

## 固定环境与重新构建

基线 `a689006cf`，候选 `d9d732cef`。在干净任务 worktree 重新构建，基线通过
仓库外明确标记为 debug 的 overlay 恢复两个生产文件；其余源文件和 benchmark 相同。
Go 1.25.11、CGO 关闭、Linux ARM64 静态程序、Apple M4 的 Docker Desktop VM。
amd64 Debian rootfs 仅承载原生 ARM64 程序，不使用 x86 模拟吞吐。

预算开启、65537B/16 调用者、16 个预热连接、Observer 关闭；服务并发64，队列4096项/
64MiB，排队/执行/调用时限分别5s/30s/2s。单进程基准固定CPU 0–3、GOMAXPROCS=4、
容器上限6GiB，四轮 AB/BA 交错，每项10s。计时与构建、剖析分开。

新构建的基线、候选分别与之前对应产物的 ELF `.text`、`.rodata` SHA-256 相同。

## pprof 结果与限制

另行按 AB/BA 运行两轮，每次固定250,000次RPC，同时采集CPU和默认采样率的内存剖析，
共4份CPU和4份内存文件。采样包含进程初始化与少量预热，不与纯计时窗口混算。
启用剖析的吞吐与不启用时明显不同，因此不使用剖析窗口给出性能验收结论。

四份 alloc_space 中，请求侧 `transport.CopyOwnedBuffer` 与响应侧
`Conn.handleRPCResponse` 的直接分配合计约95.8%–96.1%。这是**累计分配字节热点**，
不是保留堆占比，也不能直接等同于吞吐损失。现有所有权与异步取消路径需要这些复制，
本轮没有以借用可变缓冲区的方式绕过它们。

|累计CPU样本（ms）|第1轮基线|第1轮候选|第2轮基线|第2轮候选|
|---|---:|---:|---:|---:|
|mallocgc|2920|3480|3500|3330|
|scanobject|1450|1600|1910|1840|
|gcAssistAlloc|1920|2140|2410|2470|

各行包含嵌套调用，不能相加。mallocgc、扫描和执行任务开销并未稳定同向增加；
采样精度与窗口数量不足以确认对象合并改变了关键路径。载荷复制和GC压力是后续测量应控制的
因素，目前不是已证实的回退根因。

## 客户端与服务端进程隔离

复用已存档的云测 echo 探针源码，重新编译两个ARM64版本。固定候选客户端，只切换服务端，
每项10s、四轮AB/BA；客户端CPU 0–1、服务端CPU 2–3，各GOMAXPROCS=2、GOGC=100、
容器上限3GiB。两端独立进程/GC，共享本机网络命名空间的loopback，不暴露主机端口。

基线中位 **63,734.6 RPC/s**，候选中位
**64,087.0 RPC/s**，差异 **+0.55%**；
逐轮为 +3.40%、-0.29%、+0.37%、+0.53%。未复现持续回退，也不能凭这四轮宣布稳定改善。

此探针还预分配每调用者10万个延迟样本，会改变活跃堆大小；CPU划分也与单进程不同。
只能比较该场景内的版本差异，不能把其绝对吞吐与Go benchmark相比来量化进程拆分收益。
它仍不是原生x86跨主机复测，不能覆盖云上64B/16并发8.24%的回退。

## 验证与决定

- 本轮32个窗口，计入输出的成功RPC共 **11,179,019** 次，其中剖析窗口1,000,000次，
  非剖析窗口10,179,019次；不含基准自校准和预热。全部内容/错误断言通过。
- 8份pprof均可解析；原始输出、产物和剖析摘要已校验；8个独立服务端容器均正常退出并移除。
- 没有产品源码、配置、测试语义修改；前轮完整transport单元和竞态集成测试结果仍适用，
  本轮没有用重复跑无关单元测试替代性能证据。
- 保留每请求少一次分配的优化。先前的下降信号不能丢弃，但当前不足以作源码回退决定。
- 下一步若继续优化，应围绕明确的载荷所有权和复制边界构造独立进程基准，并一起测内存峰值、
  取消与超时下的释放安全性；不要直接删除复制或仅调大GC参数作为修复。
- 本轮没有稳定定位原回退根因，也未证明云上回退恢复；不新增云资源。
