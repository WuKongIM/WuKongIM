## P2 — A failed pre-claim guard can overwrite prior first-capture evidence

[watcher:91](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/watch-three-node-first-grant.proposed.py:91), [watcher:99](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/watch-three-node-first-grant.proposed.py:99), [watcher:134](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/watch-three-node-first-grant.proposed.py:134), [watcher:89](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/watch-three-node-first-grant.proposed.py:89).

Source, launcher and node guards run before claim acquisition. If an earlier invocation has already created `profile-driver.claim` and its status, a second invocation with a failing source/launcher/node guard enters the exception handler before the `already_claimed` branch. Its reason changes from `not_started`, so the `finally` condition calls `finish()` despite `claimed == False`; `finish()` replaces the original `profile-driver-status.json` with a skipped record. No duplicate sampling is required to lose the first evidence. Likewise, a failed owner/path guard can reach the same output writer, so those guards do not currently prevent artifact I/O on their rejected path.

Minimal correction: validate safe owner/output scope first; make claim ownership the sole permission to write/replace driver evidence. A caller without that claim must emit only a closed log record and preserve existing files. Re-evaluate source/binary/helper/launcher/node guards before launch inside that ownership boundary. Tests should cover a valid duplicate, a duplicate with each failing guard, and invalid owner/path inputs, asserting zero new helpers and unchanged prior status bytes/mtime. Do not mutate V1; retain it and freeze a corrected V2.

## P2 — Root-only joins do not prove cleanup of descendants after a root exits

[watcher:36](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/watch-three-node-first-grant.proposed.py:36), [watcher:46](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/watch-three-node-first-grant.proposed.py:46), [watcher:49](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/watch-three-node-first-grant.proposed.py:49), [watcher:58](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/watch-three-node-first-grant.proposed.py:58), [watcher:75](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/watch-three-node-first-grant.proposed.py:75).

`cancel()` first retains only helper roots whose `poll()` is None. After TERM grace, it again removes roots that exited and discovers descendants only under the remaining live roots. A root that exits during that grace while leaving a TERM-ignoring child is no longer traversed; after reparenting, the child's old PPID relationship is gone. A root that exited before `cancel()` is excluded from the start. Final waits and `capture_joined` cover root processes only. Thus `capture_joined=true` cannot by itself certify all owned timer/curl/descendant PIDs are absent.

The normal real helper path is stronger than this counterexample: its existing `terminate_children` TERM-signals and waits registered requests, and `join_profile_requests` waits them before normal completion ([helper:328](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/capture-three-node-first-grant-profiles.sh:328), [helper:466](/tmp/wukongim-v3-readiness-20261023/cloud/three-node-first-grant-profile-proposal-v1/capture-three-node-first-grant-profiles.sh:466)). Those normal paths were not found defective. The gap concerns abnormal root exit/orphan ownership and the broader cleanup assertion.

Minimal correction: retain an owned-descendant snapshot for all registered roots **before** TERM; within the original shared total budget, clean both that retained set and newly observed live-root descendants even if a root subsequently exits. Report root joins separately from owned-descendant absence. If a root already died before ownership could be established, mark ownership unconfirmed/partial; do not invent a complete cleanup proof or kill unrelated processes sharing the main workload PGID. The existing final whole-PGID cleanup can establish eventual zero resources, but it is a separate boundary and cannot be substituted for a proven three-second sampler cleanup. The actual-run plan must explicitly handle that unconfirmed case before review approval.

Add frozen fake scenarios for (1) root exits on TERM while its child ignores TERM, (2) root already exited with a live child, (3) ownership-snapshot failure/timeout, and (4) all helpers ignore TERM. Include the generator/test program, exact argv/environment, before/after owned PID observations and elapsed shared budget. The two existing result-only JSON receipts do not provide those reproducible programs.
