# Temporary profile-driver contract before implementation

No product process or real product profile is authorized by this preparation.
The root-approved test seam is the temporary driver CLI plus isolated fake loopback HTTP server and owned process group. Tokens stay in environment/anonymous header FD; public receipts contain only safe hashes, fixed fields and timing.

- Wrong Git revision/binary/helper/config or inherited wrong owner group: zero HTTP, typed source/ownership rejection.
- Missing/oversized/symlink/malformed/wrong-schema/stage/fence/generation or stale/future receipt: zero HTTP, never synthesize first-grant proof; bounded wait until original deadline or terminal.
- Fresh exact receipt: one CPU request seconds10 to only node2; one goroutine at CPU submission+5s, no heap/context/metrics/trace. Record receipt detection lag and actual dispatch skew; reject lag>2s.
- Receipt publication follows first grant and dataset probe; scheduling cannot recover the preceding interval. Do not label sample as covering t0 exactly.
- Duplicate receipt/invocation: immutable output claim permits no second capture.
- Terminal/stop/source group shutdown/clock confound at any point: fence later requests, cancel and join child helper/curl/timer; no delayed goroutine after cancel.
- HUP/INT/TERM during request registration, timer wait and joins: no unowned child or timer; registration guard and child ownership retained from frozen helper.
- Hard remaining budget<20s or global deadline reached: skip/cancel, never extend original570s TERM/5s KILL/600s total or delay service cleanup.
- CPU/gor network401/429/5xx, empty response, known/headerless oversized body or stall: no retry; partial result; requests bounded2s connect/15s CPU/5s gor; hard CPU8MiB/gor4MiB temporary and promoted file cap.
- Preserve original workload/exit status, including exit8 and missing final report. Profiling itself changes CPU/scheduling and cannot be used as performance acceptance.
- Output/metadata failure or unsafe paths: no overwrite of previous evidence and no secret/raw configuration publication; benchmark cleanup independent of collector success.

Fake self-checks must include matching schedule, cancellation before/after timer, wrong source, wrong/freshness receipt, deadline, repeated capture, output path safety and both headerless byte caps. They qualify only orchestration, not actual pprof validity or message-loss mechanism. Existing helper's source-level adaptation must be reviewable as an exact diff; copied tested ownership helpers must not be described as an unchanged whole helper.
