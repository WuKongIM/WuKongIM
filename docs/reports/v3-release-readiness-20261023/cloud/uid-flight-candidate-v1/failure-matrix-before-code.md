# Tests-first failure matrix for UID-flight candidate

**No candidate implementation or new test code has been written or run.** This matrix is additional to the frozen tests-only HOL experiment. Start with exported NewAuthorityRecovery(...).EndpointsByTargets, real Directory and deterministic owner-port gates. Use integration tier for concurrent/wait/deadline cases. Fake only the external owner boundary; never a private lane or flight. Each test must join every goroutine and release every gate on assertion failure. A future run uses a fixed outer timeout and preserves complete first failure. No long sleep, service build or workload is authorized by this document.

| ID | Failure mechanism and stimulus | Required observable result / control |
| --- | --- | --- |
| 1 | A spans all 32 former lanes and waits for owner I/O; B is a different cold UID under an A target, with free new quotas | B reaches its independent owner boundary and completes before A release. The frozen current-code test is already RED. Non-conflicting target and hot positive/negative proof controls distinguish a general broken fixture. |
| 2 | Partial overlap A={u1}, B={u1,u2} | B queries/installs u2 while A remains paused; a separate current-fence lookup observes u2 proof before A release. B's combined result still waits for u1. u1 is never requeried; both final routes preserve input order. |
| 3 | Owned completion wrongly delayed until joining an old dependency | Pause u1 owner (A), pause B's new u2 owner, arrange a u2 follower C before releasing u2, and require C completion before allowing u1 to finish. Owned u2 done/resource release must happen before B joins u1, allowing C→A→B to finish. Use a narrow RecoveryDirectory-port wrapper delegating to the real Directory if a public not-ready barrier is needed; no flight-state hook or merely elapsed-time inference. |
| 4 | Many identical (five-field target, UID) callers, including duplicate UIDs within a page | One owner proof/query for the in-flight key; no fabricated early result. Existing followers consume no new cohort slots even when leader quota is full. Caller/result multiplicity and route ordering remain intact; coalesced ownership does not deduplicate the public result. |
| 5 | Same UID, different distributed identity | Vary each of HashSlot, SlotID, leader node, leader term and ConfigEpoch independently. Never share proof across identities. Old authority completion returns typed failure and cannot ready the new identity. Separate local revision/AuthorityEpoch-only controls must retain existing identity semantics and forward the caller's full original target. |
| 6 | Incomplete owner evidence: one current owner fails while another returns a positive or empty snapshot | Through the actual production owner adapter with deterministic member readers, the affected group remains unknown/typed not-ready; no negative proof is installed, other valid sibling groups retain results. A complete empty response from every required current owner is the contrasting legitimate offline proof. Keep membership/boot/sequence rechecks. |
| 7 | Owner response cardinality mismatch, foreign UID/invalid route identity, stale target, or per-group error mixed with success | Reuse existing adapter/runtime error contracts; failed groups acquire no proof. Complete siblings are not discarded. No partial output slice is promoted to full evidence. |
| 8 | Follower cancellation/deadline before owner completion | The follower promptly returns its own context error and leaves no retained waiter entry; A's owner context remains live, A and other followers complete. The existing cancellation control already passes. |
| 9 | Leader cancellation/deadline while live followers exist | Owner observes cancellation; no incomplete proof is installed. Resolve/release/done exactly once. Leader returns its context error; still-live follower returns ErrRouteNotReady rather than another caller's context.Canceled, and does not start an automatic owner retry. A subsequent explicit external call can acquire fresh quota. |
| 10 | Quota full separately for keys, copied bytes and cohorts; caller needs several new keys plus existing followers | Waiting holds **zero partial new reservations**. Existing-only follower can still join. Deadline returns promptly. Release one leader; wake-up first rechecks Directory and avoids querying newly installed proof. New work never bypasses the relevant hard bound; no unbounded pending queue/map. |
| 11 | Single page's UID byte total exceeds the proposed indivisible page/global byte bound, including integer-overflow-shaped lengths and duplicates | Immediate typed not-ready, no indefinite quota wait and no owner I/O or proof publication. Count only new unique key bytes, overflow-safe, before allocating/copying. Boundary-equal values are admitted. Input order/multiplicity is still preserved. |
| 12 | Quota accounting races: simultaneous admission, cancellation, mixed completion and immediate key reuse | All three budgets stay within their independent constants and return fully to baseline, with no leaked key, double release or double close. Public owner active/peak counters verify concurrency; source/accounting checks verify key/byte ledgers. If exact retained-byte ownership cannot be proved black-box, justify a small pure private accounting test **before** writing that helper; no public test knob or flaky RSS assertion. |
| 13 | UID is a short substring of a large immutable backing string; repeated duplicate inputs; caller slice/result ownership | Retain exact owned UID bytes rather than the large backing allocation; charge each owned key once and reuse its owned string across bounded request groups. Verify cloning in source plus deterministic quota-boundary tests, not a noisy GC/heap threshold. No caller-owned UID slice or returned route cache is retained in flights. No per-UID goroutine. |
| 14 | Pages at 511/512/513/1025 UIDs and 255/256/257 targets; empty UID/page; duplicate exact-target groups | Every owner call stays <=512 UIDs / <=256 targets; existing 512/512/1 behavior remains. Correct aligned errors/routes, successful earlier pages and duplicate UID multiplicity survive. New subset processing does not turn the page into one RPC per UID/hash lane. |
| 15 | Install versus concurrent unregister tombstone/newer owner registration/boot generation | Real Directory rejects or suppresses stale owner sequence/session evidence exactly as today; no stale route resurrection, no loss of newer registration. Complete proof may correctly produce empty routes behind an unregister fence. |
| 16 | 1024-proof FIFO eviction, accelerated by simultaneous same-hash-slot cohorts, then a late flight follower | Installed proof can be evicted before the follower reads it. The follower rereads Directory and returns typed not-ready; done is not an offline marker or cached route. No implicit owner retry, no cache growth, and active newer proof remains valid. |
| 17 | LoseAuthority/BecomeAuthority or distributed identity change while owner I/O/waiters are outstanding | Completion cannot ready or overwrite the new authority. Old entries/budgets finish and release; new-identity operations use distinct keys and their own current-fence checks. Revision-only updates preserve existing Directory behavior. |
| 18 | Owner/Directory completion races a quota wake or post-reservation recheck | A proof installed by another cohort is observed before redundant owner work when possible; the admitted leader releases any now-unneeded reservations. Every success still goes through a current Directory read. A cancellation arriving before the read wins according to the caller's own context. |
| 19 | Real owner gate already full despite unrelated UID registry headroom | B is allowed to backpressure within the existing owner gate and caller context; the test must not falsely promise unlimited owner capacity. Control with an independently available owner slot separates UID admission from downstream owner/RPC pressure. |

Priority: 1–5 establish the proposed behavior; 6–9 protect evidence/cancellation semantics; 10–13 establish bounded resource ownership; 14–18 preserve existing paging/fencing/proof behavior; 19 limits the promise. Write one meaningful failing slice before implementing it, preserve existing contracts throughout, and do not turn RED green by changing workload gates, deadlines, expiry or retry. Follow with a bounded exact-candidate process E2E and repeatable artifact only after implementation is separately authorized.
