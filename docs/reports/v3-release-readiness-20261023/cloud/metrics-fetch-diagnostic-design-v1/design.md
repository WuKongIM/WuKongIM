# Bounded metrics-fetch diagnostics: proposed design

Status: **design only, awaiting root approval**. No production source, tests, PR or workload was changed. Exact source is c4954c6a638080e6a915ecec305a3381f4afd9a0, tree 98fead03ba0c727dd733f742790e7737327f3942. `source-bindings.json` freezes the governing rules, applicable FLOWs, inspected source/tests, composition and check policy.

## Evidence and scope

The c495 local run stopped with `meta_checkpoint / metrics_fetch`; its actual failing scrape round was not retained. Root's separate six-scrape in-memory parser replay passes, but those earlier/later scrapes cannot identify the missing round's cause. This proposal identifies the next real failure's fixed service-source position and broad failure class. It does not diagnose the current failure by inference, fix message loss, change report validity, or qualify Linux performance.

There are two evidence-loss boundaries. `target.Client.Metrics` delegates HTTP acquisition to `getObservationBytes`, which already collapses request, transport, non-auth status and body-read failures across configured addresses. Wrapping only the final generic error cannot recover those facts safely. Separately, `collectProductionMetaMetrics` launches three existing source calls, joins all three, checks the parent context, and turns every remaining source failure into `ErrLifecycleHarnessInvalid`. The production composition supplies exactly one API address to each of the three Metrics clients, ordered by `observation.service_nodes` (`chat_lifecycle_runner.go:124–129`). A source index is therefore a declared position, never a newly inferred node ID.

## Recommended option A

Add bounded classification at the existing target Metrics seam and carry its safe projection through the existing finalization diagnostic. Keep a single HTTP acquisition loop and the current metrics parser.

1. Extract the existing `getObservationBytes` loop behind an unexported classified helper returning bytes, a closed class, and the original error. Keep the current helper signature as a delegating wrapper that discards the class, preserving other observation endpoints' behavior. The inner loop retains address order, fallback decisions, all early returns, context checks, body drains/closes and every numeric bound. It collects only constant-size category state, never per-address error lists or response excerpts.
2. `Metrics` uses the classified helper. A failure becomes a private typed metrics error with fixed safe `Error()` text selected only from its validated closed kind (the response_limit text retains the existing word "limit"), a closed kind, and `Unwrap()` returning exactly the original error. On HTTP success, run the unchanged `parseObservationMetrics`; any error from that parser is tagged `parse`. A narrow exported classifier function accepts an error and returns only a validated kind; the concrete error and cause remain private. Typed class takes precedence over `errors.Is(context...)`, so a live-parent HTTP timeout stays `transport`, rather than being relabeled caller cancellation. Untyped port errors matching standard context cancellation/deadline may be classified as those context kinds; a custom chain matching both is `mixed`; other untyped errors are `unknown`. No classification uses error text.
3. `collectProductionMetaMetrics` stores results by source index, still joining exactly three launched calls before deciding. Preserve the pre-launch parent-context check and post-join parent-context check. If the post-join parent context failed, return that same context error and zero snapshots. Otherwise, a failed round returns a private aggregate that contains exactly three original source-error references and the fixed safe projection. Its single constant `Error()` contains no causes, and **its `Unwrap()` exposes only the original `ErrLifecycleHarnessInvalid`**. No source cause is joined into that public chain and no arbitrary-text accessor is added. This intentionally preserves the old semantic isolation.
4. Add one optional `metrics_fetch` object to `FinalizationFailure`, containing `source_mask` (uint8, only bits 0–2) and `kinds` (exactly three closed strings, in declared source order; empty means that source succeeded). Keep Stage=`meta_checkpoint` and Reason=`metrics_fetch`; no new reason combinations or log event are introduced. Populate only from the private aggregate at the existing `metaCheckpointFailure` seam. Parent-context failures retain the existing context reason and omit this object.
5. Extend `FinalizationFailure.Bounded` to project this object only for the exact metrics-fetch stage/reason. Reconstruct a fresh bounded copy: source_mask must be 1–7; each bit corresponds to one nonempty kind; successful slots must be empty; unknown supplied kinds become `unknown`; invalid mask/slot consistency clears the optional object. Other stages/reasons clear it. No arbitrary supplied string is copied out. Existing frozen observation fields, report decisions and validity remain untouched.

The fixed three-element vector preserves category-to-source association for simultaneous different failures. A single ORed category plus a node mask would lose that association. The mask is a source-position mask, not a physical node-ID mask. An optional pointer/container avoids an always-emitted zero `[3]string` array. The projection is diagnostic only and never an input to verdict, retry, accounting or deadline logic.

## Closed kinds and limits

The complete vocabulary is: `configuration`, `context_canceled`, `context_deadline`, `transport`, `auth`, `http_status`, `response_limit`, `body_read`, `parse`, `mixed`, `unknown`.

- `configuration`: no nonblank configured address, or request construction failure. No address is included.
- `context_*`: observed caller-context stop at an existing check, or causal context failure at the existing Do/body-read branch. Preserve the original error and fallback behavior even when an earlier failed address means the old helper ultimately returned its generic error. A causal context failure after an earlier different class contributes to `mixed`, rather than changing the public error chain.
- `transport`: HTTP Do failed without that causal caller-context condition. Includes client timeout, dialing, TLS and other transport failures; this proposal does not distinguish them.
- `auth`: existing immediate 401/403 stop; no numeric status or body is exported. `http_status`: other non-2xx failures when all eligible addresses fail in that class.
- `response_limit`: either existing ContentLength rejection or existing limit+1 body-length rejection. It means the existing 8 MiB Metrics HTTP body bound, not a parser bound.
- `body_read`: a successful-status body's read failed independently of causal caller cancellation. Body close/drain errors that are currently ignored remain ignored.
- `parse`: any error returned by the existing parser, including syntax/value/label/queue consistency, duplicate/overflow, line/series/scanner bounds. There is no parser rewrite, per-family classification, metric-name export or missing-family check added.
- `mixed`: different nonterminal address failure classes exhausted one Metrics client's existing address list. Maintain only a fixed category bitset for failed attempts plus any observed loop context stop; one class repeated stays that class and multiple bits become `mixed`. Classify a Do/body-read failure as context only when caller ctx.Err is nonnil and the actual error matches it, without changing the existing failures==0 return condition. A later successful address clears all prior failure state; a parser error on the selected successful body is `parse`. Existing immediate auth/limit stops report that terminal class. A loop context stop before any prior failure remains a direct context error; after a different prior failure it contributes to `mixed`.
- `unknown`: a nonnil custom port error with no known typed or standard-context classification, or an invalid supplied kind. Never guess from its text.

`Metrics` itself does not currently call `ValidateRequired`; the observer adapter does, and the meta controller receives direct target clients. Empty/partial bodies that the current parser accepts must remain successful fetches; later preview/accounting errors keep their current leaves. No new required-family validation is introduced here.

## Critical semantic boundary

Exposing all three private source errors through `errors.Join`/`Unwrap` would be wrong here. A live-parent child context error would newly match `metaCheckpointFailure`'s context precedence; a custom source `ErrLifecycleProductFailure` would newly match `Finalize`'s `metaProduct` test and become product evidence. The aggregate's harness-only Unwrap deliberately keeps both false while retaining the three original references privately. Direct `target.Client.Metrics` preserves its own original `errors.Is` behavior through its typed wrapper. Parent-context precedence remains exactly as before. Tests must explicitly distinguish these two layers.

Retention is bounded to three error references and three closed kinds, not three copies of arbitrary `Error()` strings. This does not claim to bound the heap owned by an arbitrary injected error object. No raw cause, response, token, address, UID, Channel ID or metric label is serialized. Ordinary error formatting contains only fixed safe text selected by a validated closed class; public output uses the Bounded projection exclusively.

## Alternative B, deferred

Capture one exact failed Metrics round privately outside product semantics using an injected client/transport. This could retain bounded status, transport/read result and at most three capped bodies with private permissions and an explicit finite retention plan. It requires precise round tagging, synchronous body-copy overhead, handling already-consumed bodies, and another local run before it can help; a generic proxy or extra scrape would not reproduce the original round. It also exposes much more private data and is not enabled by this proposal. Prefer A first. If A returns `parse`, root can review a separate exact-round private capture plan; A alone will not identify the offending metric line. Neither A nor B retrospectively reconstructs c495's missing round.

## Scope and validation before implementation

Expected implementation scope: a narrow target metrics-error helper plus the existing HTTP acquisition function; the meta collection aggregate; existing finalization projection/bounding; focused tests; a concise operator-facing CHANGELOG entry and knowledge/FLOW update if made inaccurate. The existing JSON controller-failure record and CoordinatorResult carry the optional object; no extra log event is added, and the existing CLI text summary can retain stage/reason. Existing client redaction, limit-text and causal-cancellation tests remain regression controls. No public final-report schema, HTTP server route, runtime delivery path, observer cadence, timeout, retry, metric parser algorithm or release gate changes.

`failure-matrix.json` and its rendered table enumerate every HTTP acquisition branch, parser family, aggregate/precedence boundary and public-projection failure before code. `proposed-validation.json` describes tests-first default-tier in-memory coverage and any later named checks. No httptest server, socket, real sleep, process, build or workload is needed for these synthetic tests. Root must approve this frozen design before any tests or implementation are written. Real workload verification remains a separate explicitly reviewed finite step.
