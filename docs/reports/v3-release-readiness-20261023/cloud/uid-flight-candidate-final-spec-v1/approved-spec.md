# Final approved local UID-flight candidate specification

This document supersedes the **budget proposal** in the earlier frozen 4 MiB design; it does not rewrite historical evidence. Scope is one local isolation candidate based on d349a7bdd2ca8f6bd4683fbccbf83010d3f9cd3e, committed as 5a8c42fa69ddc15ef341e2992148c7c7fc36eb79. No cloud-root-cause claim, release qualification, PR, push, service start or workload run is implied.

Replace I/O-spanning hash-lane ownership only with private bounded UID proof flights. The key contains UID plus HashSlot, SlotID, LeaderNodeID, LeaderTerm and ConfigEpoch. Local RouteRevision and AuthorityEpoch are excluded from equality consistently with existing distributed validation. The caller's complete original RouteTarget still reaches Directory/owner validation unchanged. Owner membership, boot/session/sequence fencing, and complete positive/negative proof semantics remain authoritative.

Fixed admission budgets are **4 leader cohorts**, **2048 retained distinct keys**, **128 MiB of registry-owned UID clones**, and **32 MiB of newly owned UID bytes per indivisible subset**. The original <=512 UID / <=256 target packing and existing production owner-read gate4 remain. The byte figures are new internal retention limits; they do not bound all input, Directory, RPC or presence heap. Copy newly retained UID bytes once after complete reservation. Do not retain large caller backing strings in registry/owner request keys.

Budget rationale: metadata identity validation permits <=65535 bytes;512×65535=33553920<32MiB, so a full page of any storable identities fits. WKProto CONNECT strings are <=32767 bytes. Presence RPC strings have variable-length prefixes and default transport frames are64MiB, while arbitrary HTTP online-status query strings lack a uniform identity-length check. Therefore an impossible-to-store/CONNECT arbitrary cold lookup subset >32MiB can newly return typed ErrRouteNotReady. This explicit boundary difference is documented; do not claim identical handling of all arbitrary strings. There is **no byte pagination or additional owner round introduced merely to meet a smaller budget**.

Proven lookups bypass admission. A page atomically reserves all newly owned keys/bytes and one cohort or reserves none while waiting. Existing-only followers take no additional cohort. Quota waiting uses the caller context and no registry-owned waiter queue. Recheck Directory after quota wake and again after reservation, before owner I/O. Oversized new subsets fail explicitly instead of waiting forever.

Execute new owned work first. For A={u1},B={u1,u2}, B queries/installs u2, then releases owned keys/bytes/cohort and signals completion **before** joining A's u1. Never delay owned completion until the entire mixed page finishes. Query current owners once for that bounded new subset; preserve aligned sibling successes, errors, UID order and duplicate multiplicity. Partial or malformed owner evidence cannot install negative proof.

Flights retain completion status only. After completion each successful caller rereads current Directory proof; authority change or1024-entry FIFO eviction can return typed unknown/not-leader, never cached routes or fabricated offline. No automatic owner requery is added. Follower cancellation does not cancel leader work. If leader cancellation aborts incomplete owner work, that leader gets its own context error and a still-live follower gets typed not-ready; already completed valid proof remains subject to the current Directory read. Existing outer retry/deadline policy remains unchanged.

No generic singleflight framework, per-UID/background goroutine, public test switch, new retry, timeout increase or owner capacity increase. Update usecase FLOW, canonical FLOW index, Unreleased and project knowledge. Tests-first public-seam RED, focused full presence/runtime regression and race, actual owner-adapter race, and frozen-policy named format/FLOW checks are required before delivery. A later exact-candidate process E2E and matching cloud incident evidence remain separate work.
