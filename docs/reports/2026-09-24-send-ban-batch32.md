总 SEND 队列、512 ordering shards、每片 256 项、Raft/持久化与门槛不变。
没有 CPU profile、并行编译、其他测试或其他压力任务。

P99=649/615ms，单节点堆峰值 370,104,504 bytes，追加路由峰值比例
0.4082，gateway batch records P99=22.60。CPU 均值 513.36%，不能用它
与前几次提前失败窗口直接计算稳定回归百分比，5% 门槛仍未验证。

该结果支持继续验证“较大批次等待放大”的假设，但不是已证明的全部
存储/调度因果链。运行命令、采样、完整指标和源码身份均保留。

## 功能配置耦合与失败保留

首次功能复验只设置 batch cap=32，保留默认 1000 gateway workers。
现有分片公式因此从 1024 片扩大到 4000 片，每片容量约 33 项。
64 条单用户多频道突发出现 EOF，私聊/群聊突发顺序测试也在 EOF 处失败。
这是与压力配置不同的真实失败，不能删除，也不能宣称单独降低默认 cap
安全。默认值保持不变；已在 PROJECT_KNOWLEDGE 记录该参数耦合。

按压力配置明确设置 128 gateway workers、131072 总队列、batch cap=32
后重新验证：
