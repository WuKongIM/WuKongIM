14: ## Core Runtime Semantics

17:   cluster**, not a standalone mode that bypasses cluster behavior.
18: - New code MUST NOT add business paths that bypass cluster semantics.

20:   deployment topology. Use "local" only for behavior within one node.
21: - Designs MUST account for high-scale workloads such as 100,000-member groups,
22:   high message rates, many channels, and many online users.
23: - Unless explicitly specified otherwise, designs MUST assume 256 hash slots.

6: # Chat Lifecycle Run Flow
7: 
8: ## Responsibility
9: 
10: This package binds four operator inputs and trusted workflow context to the
11: versioned repository Run Plan, generic Cloud Lease input, and public bootstrap
12: identities. It never calls providers, deploys hosts, runs workers, or retains
13: private credentials.
14: 
15: ## Boundaries
16: 
17: - Infrastructure quantities and workload thresholds come from a reviewed
18:   template. The direct repair controller may derive its bounded workload and
19:   Lease durations from the operator's qualification window and bind an
20:   explicitly authorized whole-CNY repair budget independently of the template.
21: - Each invocation has exactly one procurement attempt. Deployment readiness
22:   repairs reuse the exact Lease, bundle, sealed identity, and request-bound
23:   control fix. One explicit adjacent workflow may start rehearsal-2 after the
24:   original rehearsal-1 is released and its public evidence is authenticated.
25: - Runtime YAML owns workload details; this use case owns cross-stage identity,
26:   budget, duration, and transition policy.
27: 
28: ## Main Flows
29: 
30: 1. Validate source, operator, request, bundle, clock, attempt, and trusted
31:    context; materialize either the bounded direct-repair Lease or the fixed
32:    12-hour rehearsal Lease and budget ledger.
33: 2. Require a typed released rehearsal transition with exact zero inventory,
34:    matching identities, public diagnostic owner, and carried commitment.
35: 3. Materialize a fresh 96-hour formal lease bound to the same source, bundle,
36:    request, diagnostic identity, and aggregate ledger.
37: 4. For a released rehearsal continuation, strictly decode the bounded helper
38:    proof and bind its request/source/diagnostic identity and full old Quote
39:    reserve to rehearsal-2. GitHub/artifact authentication remains the protected
40:    helper's responsibility; this package performs no network verification.
41: 
42: ## Invariants and Failure Semantics
43: 
44: - The shared CNY 1,350 operational stop and CNY 1,500 hard limit cover all
45:   stages, including the original released rehearsal's conservative reserve.
46:   A reserve is not provider billing evidence.
47: - Topology is fixed at four Ubuntu x86 hosts, one EIP, and reviewed disk and
48:   port settings; rehearsal runs two hours and formal runs 72 hours after their
49:   two-hour readiness windows.
50: - Direct repair accepts a 16-minute through 72-hour-15-minute workload ceiling
51:   and derives its Lease as the larger of six hours or workload plus four hours
52:   45 minutes. Its default hard/stop limits are CNY 300/250; an exact explicit
53:   whole-CNY authorization may raise the hard limit through CNY 1,500, with a
54:   CNY 20 operational reserve, while every other quantity remains fixed.
55: - No automatic deployment retry creates a fresh Lease. The explicit released
56:   continuation requires adjacent first-attempt workflow runs, the original
57:   rehearsal-1 identity, and nonzero authenticated commitment; it cannot chain
58:   another continuation or authorize a known runtime/correctness failure.
59: - The exact release selector is derived before paid Acquire so ambiguous or
60:   artifact-losing acquisition remains cleanup-capable.
61:
