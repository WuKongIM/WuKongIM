Terminal cloud diagnostics could omit the workload’s already-produced failure examples and lose the entire Prometheus range when a response exceeded 4 MiB. The range also followed collection time instead of the actual terminal report. This change collects bounded, validated worker/status documents and eight fixed metric partitions anchored to the terminal report, preserving successful partitions and explicitly recording missing or partial evidence.

The collector binds run/generation/snapshot identity, retains the raw terminal timestamp while using Prometheus millisecond query precision, and requires a valid failed-before-capacity state before exempting missing capacity documents. Metric partitions share 24 MiB and 60 seconds; zero-loss qualification, product runtime and cloud lifecycle remain unchanged. The actual collector fixture moves into the integration tier, and its optional artifact variable uses a non-WK_ name so it cannot enter product configuration.
