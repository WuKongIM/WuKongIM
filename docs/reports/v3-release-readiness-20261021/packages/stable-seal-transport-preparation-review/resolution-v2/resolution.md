# Adopted scope resolution — before implementation

Root accepted the five-source solution: the four existing bind/seal/resolve/transport helpers plus one narrow read-only preflight helper. This resolves the generation-1 design ambiguities as an implementation contract; it is not proof that code, tests or real publication have passed. Generation-1 proposal/review evidence remains unchanged.

1. **Historical and live control identity.** Keep the original candidate control SHA and current seal control SHA distinct. Prove the historical commit is in the fresh reviewed packages-main ancestry and compare its actual Git-object bytes for all ten public controls and twelve producer files against the candidate's external anchors. Execute only reviewed checkout code; reject producer mismatch rather than add a historical executor. Candidate archive, receipt, signatures, content-derived names and internal null IDs remain unchanged.
2. **Fresh production source.** Reuse existing source numeric-ID resolver for all seven original assets and exact source Release/tag/commit facts, then the real source-attestation verifier and native metadata checks; compare immutable identities/bytes to the candidate. Local receipt booleans do not replace those operations. Reuse #72 actual candidate signature verification. Complete these before the stable sealer's first asset POST; immediately before final PATCH re-read lightweight source identity and the existing main/tag/policy fences. Do not redownload seven assets for this last fence. An intervening source change must stop publication, without retry into green.
3. **Binder remains narrow.** It binds only an exact empty draft and reserves the create-only tag. It needs the live control/ancestry/tag checks, not a redundant seven-asset download and package verification. Seal is the boundary that promotes candidate bytes into an immutable external object.
4. **Closed endpoint modes.** New stable production mode uses the existing official GitHub API/download origins, not caller-selected loopback or arbitrary hosts. TEST ONLY requires explicit opt-in plus both API/download origins loopback before requests; binder has only its API origin. TEST ONLY rejects every redirect, including the asset redirect branch at resolver lines 193–207. It remains marked TEST ONLY through seal/resolution/transport output. Legacy preview routing behavior stays unchanged.
5. **Offline transport remains observational.** It checks all descriptor/receipt/plan/hash relationships but does not authenticate who supplied JSON. A fully self-consistent local declaration does not become GitHub provenance. Plan-only, GitHub/control-commit/cloud/activation verification flags remain false; fresh production activation is later. Two current channels are required, root metadata is preview-owned, stable RPM mirrorlist maps to one immutable complete snapshot, all generated bytes are inventoried, limits are global, retention exhaustive and delete list empty.
6. **Bounded implementation.** Four existing helpers + one focused preflight module, their focused/CLI/API-fixture tests and required docs. No changes to the twelve candidate producers, manifests, certificates, live site, private-key channels, production workflows, rulesets or cloud resources. No third remote asset, signing-exchange protocol, generic registry or new historical execution mechanism.

Tests must first record red at the real CLI/API/process seams, then green: fake-but-self-consistent production history/source cannot skip fresh checks; real Git bytes and ancestry mismatch; wrong source asset/attestation/metadata; source change before PATCH; dual-mode endpoint rejection and redirect external-request sentinel; exact candidate-byte preservation; original preview regression; full actual TEST ONLY native signature chain. Mocks/loopback cannot be reported as real GitHub provenance or actual stable publication. The existing source-reader/publisher/policy identities and stable tag ruleset requirements remain deployment dependencies; no production credential/workflow wiring or external seal is performed in this slice.
