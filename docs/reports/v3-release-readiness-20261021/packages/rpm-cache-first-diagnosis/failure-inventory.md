# Complete tests-first failure inventory for the proposed cache repair

No shipping implementation is changed at this stage. Existing tests may be extended but every new check must be authored and demonstrated against old source first.

1. **Exact target coverage:** RPM mounts cover both final CLI cache/state locations and both early installroot locations. Existing mappings retained; all host subdirectory names distinct. Root-only old mapping must fail. No host absolute source, path traversal, /var/run/docker.sock, system cache or repository write mount.
2. **APT unchanged:** Existing APT cache mounts remain exact; unsupported family still fails. No production command or package-client option change.
3. **Native metadata classification:** Nonempty repodata and solver `.solv`/`.solvx` in dnf-cli-cache and existing dnf-cache can form evidence. expired_repos.json alone, dnf-state/dnf-cli-state, RPM package alone, arbitrary log and empty inventory cannot pass. Existing APT partial-list exclusion remains.
4. **Read proof:** Merely inventorying before/after cannot pass reuse. Same valid metadata content/inode plus an actual read after epoch arming passes for the new root. Changed SHA/size/inode, removed file or unchanged atime fails reuse. No-atime and rerequest/replacement without any surviving read must fail rather than silently report reuse.
5. **Bounded helper:** All four directories remain under one task cache root. Existing symlink/hardlink/unsupported-file, per-file/count/total-byte limits and root helper isolation remain; failure before or after native client preserves cleanup/error reporting. Existing tests exercise these boundaries without shipping changes.
6. **Actual mount composition:** The real download command receives four intended bind destinations and no conflicting exact tmpfs. The host paths derive only from the case's existing scratch cache, and separate distributions remain separate. Preserve complete literal native command body and family parameters.
7. **No state mixing:** Distinct client paths get distinct host children; do not collapse early state and final cache onto one host directory. Inventory and remove operate on all four children, leaving zero owned cache files.
8. **Native acceptance:** Existing Rocky/Alma cache-A-first, cache-A-repeat, cache-B-target prove actual metadata persistence, OS read signal and exact B transition. A/B switch, every negative, installed CLI and owned cleanup remain required; 49 cases unchanged. Local filesystem or configuration probes must not be reported as those native acceptance results.
