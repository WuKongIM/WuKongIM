# RPC 队列与执行器交接：单连接复用诊断及让出调度实验

本轮将后续优化重点收窄到**单连接多请求下的执行调度等待**。
固定16个调用者，复测中1条连接的吞吐比16条连接低约24%；哈希采样显示，单连接从准入到
处理函数启动约35.7～36.6µs，而16连接约3µs。短时调度trace提供了独立方向证据。
这是当前版本的拓扑对照，**没有证明它就是原始版本吞吐回退的原因**。

尝试“每提交4个任务后让出一次调度”的小候选，吞吐中位+0.99%，四对有正有负，
未达到稳定收益要求，已撤回。最终只新增共享连接基准及本文证据，运行时行为保持不变。
本次没有用户可见的产品行为变化，因此不新增产品Changelog条目。

34个纯计时窗口共59,726,676次成功RPC；12个独立诊断窗口共24,376,457次，
合计 **84,103,133次成功RPC**，零错误、零样本截断。基准自检调用另计。

[证据包](assets/rpc-queue-handoff-2026-09-22.json)包含驱动、探针、两版采样源码、补丁、
全部窗口结果、阶段明细、测试日志、原始pprof、从trace导出的调度profile、解析和清理回执。
两个原始trace合计约78MB，保留在本地证据目录，包内记录绝对路径、长度和SHA256，未重复嵌入仓库。

## 假设与测量边界

预先提出三个预测：监听注册占用主要持锁成本；队列与执行器交接等待高于锁内工作；
将16调用者从16条连接改为1条连接会改变争用分布。先测未修改的产品，再单独运行诊断版本。
源版本 `ab25df595`，根AGENTS摘要冻结，transport无适用FLOW；工作在隔离worktree内完成。

Go1.25.11、GOWORK=off、CGO=0，Apple M4上的Linux ARM64 Docker VM。
静态ARM64程序运行在已有Debian amd64 rootfs，程序输出确认arm64。
客户端CPU0–3、服务端CPU4–7，各GOMAXPROCS=4、GOGC=100、3GiB内存上限。
两进程使用同一网络命名空间的loopback，无主机端口，Observer关闭，独立GC。

固定64B写RPC、16调用者，服务并发64、队列4096项/64MiB、排队期限5s、执行期限30s、
调用期限2s、预算开启、CancelRunning=false。客户端PoolSize仍为16，仅通过固定shard映射选择
1个或16个活动连接槽，预热对应连接；没有随机路由、增加调用者或改变业务排序规则。
每窗10s，完整校验回显和每调用者计数，100万样本上限触发即失败。
构建、测试、阶段采样、CPU profile和trace均与纯计时分离。

## 未修改产品的拓扑对照

变化方向均为“1连接相对于16连接”。两批各4对交替顺序，加每个拓扑各1对A/A。

|批次|16连接 RPC/s中位|1连接 RPC/s中位|吞吐变化|P99变化|
|---|---:|---:|---:|---:|
|首批|202,181.93|164,188.56|−18.79%|+70.68%|
|交换起始顺序复测|216,759.52|164,791.62|−23.97%|+93.34%|

首批四对吞吐 +4.15%、−23.55%、−13.98%、−23.12%；16连接A/A达+14.26%，1连接+0.24%。
首批明显存在波动，完整保留，不能用删样本获得“稳定”结论。

复测四对吞吐 −26.68%、−22.09%、−24.75%、−10.95%；P99四对均升高。
复测A/A为16连接−4.21%、1连接+6.53%。方向在复测一致，幅度仍受本机波动影响。
运行前后记录的容器CPU计数未出现quota throttling，另保存Linux loadavg和CPU pressure。
这些状态没有覆盖全部宿主机干扰，不能据此证明实验环境完全无噪声。

这不是原生x86跨主机容量结果，也不是原始旧版本与新版本的对比。

## 阶段采样与独立trace

临时诊断版本给被选中的请求记录准入锁前/后、所有者分配、入队记账、监听注册、队列快照、
出队、提交、worker启动、handler启动/返回及释放锁前/后时间。记录在锁外汇总，单进程最多2万条。
请求采样对象随已有所有者跨pump和executor传递，没有延长业务截止时间或更改取消归属。

首版每1024次取一次，可能与16请求批次对齐。因此补做固定SplitMix64哈希低10位为零的采样，
保持约1/1024比例并打散选择位置。两版各2轮、每轮两个拓扑，保存全部原始记录。
两版跨协程采样各通过5轮race检查；样本ID唯一、无丢弃、阶段时间非负，
准入各子段之和与总持锁时间逐条相等。已完成计数与客户端成功数加预热数一致。

|哈希采样，两个独立窗口的中位数|16连接|1连接|
|---|---:|---:|
|准入持锁|0.541 / 0.542µs|0.417 / 0.417µs|
|其中监听注册|0.209 / 0.208µs|0.167 / 0.167µs|
|离开准入锁至开始出队|0.792 / 0.792µs|10.666 / 10.667µs|
|首次尝试提交至worker启动|0.667 / 0.667µs|21.542 / 21.167µs|
|准入锁前至handler启动，逐请求计算|2.958 / 2.958µs|36.583 / 35.667µs|
|入队前队列为空的比例|87.30% / 86.96%|10.09% / 8.62%|

单连接队列等待和交接等待的差异在打散采样后仍存在。监听是锁内成本的重要组成部分，
但典型持锁时间不足1µs，不能单独解释两种拓扑约数十微秒的生命周期差异。
16连接仍有明显的锁等待长尾；本轮没有排除其对P99的影响。

采样增加时间读取、计数、请求字段与少量分配，会扰动被测路径，尤其影响亚微秒子段。
固定哈希也不是严格统计随机试验。因此这些数值是诊断定位，不是未经扰动的精确生产时延。
表中总时延来自每条样本相加后取中位，未将各段中位数直接相加。
“worker准备”还包含inflight更新、执行前检查和上下文准备，不能单独解释成超时初始化成本。

另对未插桩产品分别取得8s CPU及alloc_space/mutex/block，共8份pprof；
再各取3s原始trace并使用Go1.25.11 `go tool trace -pprof=sched`导出调度等待profile。
工具源码确认该profile统计goroutine进入Runnable到离开该状态的等待，并归到进入状态时的栈。

|独立profile的累计采样比例|16连接|1连接|
|---|---:|---:|
|调度等待：Executor.Submit / ants.Invoke唤醒栈|47.44%|89.01%|
|mutex等待：Service.Enqueue|82.03%|74.08%|
|mutex等待：Executor.Submit|0.20%|0.04%|

Submit的调度profile比例代表其唤醒的工作等待运行，不是Invoke函数自身消耗了89%的CPU，
也不是线程在该函数里阻塞了全部时间。不同profile类型和嵌套累计比例不能相加。
这些证据支持进一步研究执行交接和连接内处理节奏，没有证明ants本身存在缺陷。

## 小候选：每4次成功提交后让出调度

候选仅在Service.pump增加局部计数器，每4次成功Submit调用一次runtime.Gosched。
保留FIFO、并发token、共享执行器容量、重试、预算与取消检查，未绕过任何准入路径。
候选先通过 `go test -race -tags=integration ./pkg/transport/... -count=1 -timeout=4m`。
然后用未插桩基线/候选执行单连接4对AB/BA和1对A/A。

|指标|基线中位|候选中位|变化|
|---|---:|---:|---:|
|吞吐 RPC/s|163,812.97|165,433.40|+0.99%|
|P99 ms|0.766146|0.739292|−3.51%|

四对吞吐 +1.58%、+0.65%、−0.55%、+3.43%；P99 −1.69%、−2.47%、+0.89%、−10.81%。
本批A/A吞吐+0.51%。中位增幅虽高于这一对A/A，但配对并非持续改善，且同轮前批单连接A/A
波动达到6.53%，不足以确认稳定收益。因此撤回，不进入多连接/大包候选验收，不宣称解决回退。
没有为微小调度技巧增加永久配置，也没有以某个有利配对作为合入依据。

## 保留的基准与交付检查

新增 `BenchmarkTransportSharedConnection`：16调用者，活动连接1/16，载荷64/65537B，预算开/关。
复用原有真实TCP基准实现，保留 `BenchmarkTransportBudget` 原有名称和场景。
shard映射在每个调用者进入循环前计算；预热和能力协商不计入计时，逐次校验全部响应字节。

两端在同一Go进程，因此分配同时包含客户端与服务端，ns/op是吞吐倒数而不是RTT。
它用于后续定位与同条件比较，不替代独立进程验收，也没有不可靠的固定吞吐单元测试门槛。

```sh
GOWORK=off GOTOOLCHAIN=go1.25.11 go test -tags=integration ./pkg/transport \
  -run '^$' -bench '^BenchmarkTransportSharedConnection$' -benchmem -count=3
```

最终基准代码对原有和新增共16个case分别完成race模式100次、普通模式1000次调用检查。
临时插桩、探针与候选代码全部移出工作树；所有实验容器正常退出并清理。
已有其他容器、工作树及无关未提交文件保留。本轮未采购云服务器。
