# 显式 batch32 配置的九轮同机对照

**状态：对照已完成，5% 性能门槛仍未验证。** 节点聚合三轮均通过；逐 Slot 聚合两轮通过、一轮权限准入 busy 后发送失败；旧基线三轮均 SENDACK 超时。所有失败保留。

## 范围与身份

固定 5000 频道、1200 SEND/s、60 秒，三节点、256 Hash Slots、10 个物理 Slots、三副本。三组均采用 128 gateway workers、131072 总队列、batch cap=32、128 Store append workers；复制参数不变。默认产品配置没有修改。此配置的结果不能用于推荐单独降低 batch cap，也不能替代 5000/4500/30m 持续资格。

顺序为 baseline/slot/node/node/baseline/slot/slot/node/baseline。所有轮次使用同一预编译 E2E 夹具；本任务在整组期间没有并行编译、其他测试、压力任务或 profile。期间只编辑了尚未编译的诊断源码，不影响运行二进制。夹具、新旧生产二进制、参考补丁和源码身份见 comparison-source.json、binaries.json 与 reference-preparation.json。主机为 Apple M4、10 个逻辑 CPU、32 GiB 内存、macOS 15.1；这是开发机同机对照，不是独占目标部署环境。

逐 Slot 参考已同步候选的 quorum cache 修复；1650 个已核对生产输入中仅 send_permission_rpc.go 的信封分组不同。fresh barrier、fence、准入与重试相同。旧基线保留已有 vcs.modified=true 限制；候选也保留实际构建时的脏工作副本身份，没有伪称二进制来自后续干净提交。

## 结论与限制

节点聚合三轮零 pending、零 permission busy。逐 Slot 第三轮在 3.99 秒、4791 次调用后收到 ReasonNodeNotMatch，同窗 permission busy=3；这不是一个完整有效的 60 秒对照。旧基线分别在约 39.47、34.32、36.24 秒超时，不能用它们较低的 CPU 或计数推导收益。

仅作描述：两个完整的配对中，节点聚合权限相关 RPC 分别减少 28.74% 和 27.01%；P99 分别变化 +7.14% 和 -18.29%，CPU 分别变化 +2.31% 和 -0.38%。第一对 P99 已超过 5% 初值，而且缺少第三个完整配对，因此不宣称性能资格通过，不用中位数覆盖失败。

此前显式 batch32 的 30 分钟目标在 238.81 秒因网关队列满关闭而失败，本轮没有修复或替代该结论。下一步用单独的 E2E 发送端时序探针区分调度/写入突发与服务端停顿；不改变负载、准入、超时、默认配置或验收门槛。
