# RPC 无调用预算请求的队列取消监听实验

本轮验证复用连接内取消入口的候选：保留标准请求context和请求表，为没有调用方时间预算的请求
增加一个可撤销的队列取消回调。带预算请求及通用context仍走context.AfterFunc。
普通64B写RPC的服务端分配减少约304B、1次/RPC（约19.3%字节）。
**保留优化**，并将实际取消回调纳入现有transport goroutine任务。单连接吞吐仍有波动，
拒绝路径增加约64B、2次分配；这是有适用负载和代价的局部优化，并非原始回退已全部解决。

## 来源和约束

基线`edcf2b746022fcb40ac4adf5ac7a567ceb9e4041`，根AGENTS摘要已冻结，transport无适用FLOW。
复用上一轮当前版及固定旧客户端二进制；基线transport与依赖文件和其构建版本`e5fe7eb74`一致。
新增候选、分配及拒绝探针都保留源码、构建命令、源码/二进制SHA256。

预先提出：复用已有取消入口可降低通用监听分配；分配下降后必须继续检查实际吞吐；
若同步或执行开销占主导，跨拓扑的吞吐收益可能不足。所有预测通过真实进程窗口验证，
不把单个有利窗口或分配下降直接等同于解决原始版本回退。

Linux ARM64 Docker VM、Apple M4、Go1.25.11、GOMAXPROCS=4、GOGC=100。
静态ARM64程序使用已有Debian amd64 rootfs，进程输出确认arm64。
客户端CPU0–3、服务端CPU4–7，各3GiB内存，独立进程使用同一网络命名空间loopback。
固定16调用者、PoolSize16、活动连接1/16、服务并发64、队列4096项/64MiB、排队5s、执行30s、
调用方2s。普通写不取消已执行的mutation，读控制设置CancelRunning=true。
纯计时每窗10s，样本上限每调用者100万，校验全部回显字节；没有profile或分配HTTP采集。

主批每拓扑4对AB/BA及基线/候选各1对A/A。单连接出现反向配对后，再以相反起始顺序
补4对及两版A/A，不删除首批或复测的不利样本。控制组各两对交换顺序。
这些结果只适用于本机负载，不能替代原生x86跨主机或完整集群容量验收。

## 机制和并发边界

原路径context.AfterFunc为排队取消注册通用子context。候选的inboundQueueContext保留底层
标准context，额外保存单个队列回调；它不改变Deadline、Done、Err、Value及context.Cause。
CancelInbound、请求Finish、连接关闭的请求表遍历均调用同一个取消入口。
连接Close先取消父context，再遍历请求表；监听注册检查当前Err，覆盖两步间的竞争。

回调注册/撤销/取消由对象互斥锁仲裁，回调在锁外异步执行；撤销失败不等待已启动回调。
同一对象的额外监听回退标准context.AfterFunc，不覆盖首个队列所有者。
对象不池化，保留已启动过期回调需要的引用；Service.mu继续决定出队、超时及停止谁取得终结权。
没有绕过FIFO、截止时间、共享执行器、准入或保留内存上限，也没有改变已运行写请求的取消策略。

候选会在准入前增加一个对象和取消方法值，因此失败准入可能增加分配。该代价通过独立
全拒绝负载测量，未仅测成功路径。

控制组没有显示明显的系统性回退，但每场景只有两对，不代表严格等效性证明。
带预算16连接两对吞吐为−1.23%、−0.12%，读16连接P99一降一升，全部保留。

全拒绝控制把MaxQueueBytes设为1，使每次64B请求在保留字节准入检查返回Busy；它测量失败准入路径，
并非模拟所有实际CPU或队列饱和情况。固定基线拒绝探针客户端，16连接，两对纯计时每窗10s，
另两对分配诊断每窗5s。拒绝响应只按预期Busy计数，不算成功执行业务。

纯计时首批吞吐中位+0.03%、P99−0.57%，两对吞吐−0.20%、+0.26%。
分配诊断发现基线632.43B/15.003次，候选696.49B/17.003次，增加64.07B/2.000次，约10.13%字节。
该诊断组吞吐两对下降约3.1%和6.5%；诊断包含额外端点及起点强制GC，不能当作纯计时结果，
但这一不利信号触发了独立的纯计时复测，而没有被忽略。

拒绝复测两对中位吞吐−0.78%、P99+2.52%；配对吞吐−0.59%、−0.97%，A/A基线−0.89%、候选−0.80%。
幅度与本批A/A接近，没有证实数个百分点的稳定处理速度回退，也不能排除小幅损失。
**额外分配已被重复证实**，不能因吞吐接近就声称拒绝路径没有成本。


正常请求的分配减少及多连接吞吐、尾延迟证据支持保留；单连接的吞吐不确定性和失败准入成本
作为明确限制保留。没有关闭取消/超时检查来消除额外分配，也不把两种不同语义路径的成本作简单抵消。
根Changelog增加了限定适用范围的操作者说明。

主测候选使用相同的监听算法。交付核查依据PROJECT_KNOWLEDGE的goroutine归属规则，将两处实际
触发回调的`go f()`改为现有`SafeGo(...TaskTransportRPCService, f)`，并补充字段注释。
普通成功请求已撤销监听，不经过这个触发分支。最终源文件和初版分别保存，避免混淆执行版本。

## 验证和复现

新增检查覆盖取消/Finish/Close、先取消再注册、父取消与表遍历之间注册、撤销与取消竞争、
额外监听及标准context子节点兼容性、带预算期限保留、阻塞handler时队列释放、
执行中读/写取消策略以及真实TCP拒绝后继续请求。
新增hook契约测试在实现前因hook不存在而失败；这不是声称旧版取消行为错误。
新增检查及现有transport全套integration均通过race，原始日志存入证据包。
没有引入依赖机器速度的固定吞吐单元测试门槛；性能回归依赖本文的受控对照。

共 **100窗、130,499,123次成功回显RPC、42,325,146次预期Busy响应**，均无意外错误或样本截断。
冒烟、分配诊断、纯计时和拒绝响应分别保存，不合并为容量结果。所有服务端正常退出、无OOM；
窗口输出、源码、二进制哈希和分配归一化公式逐项验证。测试自身的调用另计。
