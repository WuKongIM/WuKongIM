## 候选与验证方法

基线为 `5c293024c`，已包含请求/执行器对象合并分配与共享队列定时器。
候选仅修改 `Service.Enqueue`：在锁前创建 `requestEntry`，准入成功后仍在锁内设置
`queued`、原始入队时间、FIFO、保留字节与 WaitGroup，并安装取消回调。
MaxPayload 检查仍在对象分配前；未修改取消机制、执行器或背压策略。
根 AGENTS 的精确源修订及 SHA256 已冻结在证据中；目标范围没有适用 FLOW 或更深 AGENTS。

沿用前轮独立进程反馈环与已有 pprof 证据，依次检验四个预测：锁内分配造成争用；
主要成本位于其他生命周期路径；提前分配增加拒绝成本；小幅收益属于运行波动。
本轮不重新剖析：候选未达到保留条件，隔离分配测量已经给出明确拒绝代价；
不能据此次结果给取消或执行器分配确定的因果份额。

- Apple M4 Docker VM，Go 1.25.11，Linux ARM64 静态程序；Debian amd64 镜像仅提供 rootfs，
  每个网络探针结果均确认运行架构为 arm64。`GOWORK=off`，构建 `-trimpath -buildvcs=false`。
- 服务端 CPU4–7、客户端 CPU0–3，各 GOMAXPROCS=4、GOGC=100、内存限额3GiB。
  两个进程独立 GC，在同一网络命名空间使用 loopback，无主机端口发布。
- 固定旧客户端、预算关闭、64B、16调用者、16预热连接；服务并发64、队列4096项/64MiB、
  队列期限5s、执行期限30s、调用期限2s。Observer 与剖析关闭。
- 基线/候选按 AB、BA、AB、BA 共4对，之后同一基线二进制 A/A 共2对，每窗10s。
  共12窗、26,213,913次成功RPC，错误与样本截断均为0。每次完整验证响应，保留逐调用者计数。
  延迟分位沿用 `floor((n-1)*p)`；客户端分配指标不代表服务端成本。
- 纯网络计时期间没有构建、测试或剖析。基线复用前轮最终 shared-probe，候选使用相同探针源码；
  每个程序哈希已归档。驱动入口为证据中的 `run.py`。

|服务端|吞吐中位 RPC/s|P99中位 ms|

|候选|219,388.58|0.385584|
|变化|+0.30%|-3.69%|

四对吞吐变化分别为 +3.84%、−1.02%、+0.49%、+0.23%；P99变化分别为
−22.54%、+3.09%、+1.50%、−5.36%。两组 A/A 吞吐变化 +0.01%、+0.56%，
P99变化 −6.01%、−2.72%。第一对的收益没有在后续对照稳定重现，不能声称吞吐或尾延迟改善。
有限对照用于工程取舍，不构成正式统计显著性或容量保证。

## 拒绝成本

隔离基准调用真实 `Enqueue`，固定满队列/字节限额/取消/停止状态，复用调用者字节，
不运行 pump。测量拒绝分支本身，不代表完整网络拒绝吞吐或动态过载场景。
六类状态 × 串行/4核并行 × 两版本 × 四轮，共96行；版本顺序交替，200ms/子基准。
每次断言错误类型符合预期。探针与运行命令保存在 `rejection_bench_test.go`、`check.py`。

|拒绝原因|串行基线→候选 ns/op|并行基线→候选 ns/op|新增 B/op、allocs/op|
|---|---:|---:|---:|
|队列项满|8.95 → 63.16|57.10 → 104.05|160、1|
|队列字节满|9.03 → 57.81|57.31 → 101.97|160、1|
|保留字节满|8.88 → 58.13|54.41 → 104.45|160、1|
|已取消|29.22 → 80.35|65.74 → 144.35|160、1|
|已停机|7.79 → 52.66|55.69 → 90.08|160、1|
|载荷过大|9.94 → 9.97|59.89 → 56.93|0、0|

全部四轮均确认：除载荷过大外，拒绝请求从0次分配变成1次、160B。
队列项满的串行成本约7.1倍，并行成本约1.82倍。该代价会增加过载期分配压力，
当前成功路径收益不足以支持这个取舍。未扩大到预算开启、大包或付费跨主机测量。
