# GitHub Issue Agent Implementation Plan

**Date:** 2026-07-28

**Design:** `docs/superpowers/specs/2026-07-28-github-issue-agent-design.md`

## Objective

Implement the approved GitHub Issue Agent as a fail-closed, GitHub-Actions-only
system. A maintainer-authorized Bug Issue must be recoverable from signed Issue
checkpoints through version pinning, black-box E2E reproduction, early Draft
PR, root-cause diagnosis, remediation, exact PR validation, and human review.

The implementation must not deploy a server, use a self-hosted runner, create
an external business database, give a model GitHub write credentials, or
automatically merge a PR.

## Delivery Strategy

This work crosses security-sensitive Workflow, credential, Git write, model,
and code-execution boundaries. Deliver it as six separately reviewed PRs.
Never combine rollout-mode promotion with the code that introduces the mode.

| PR | Scope | Highest enabled mode |
| --- | --- | --- |
| A | Contracts, state machine, GitHub read/publish core, CLI | disabled |
| B | Tool broker, model Adapters, Worker engine, shadow Workflows | shadow |
| C | Minimal Bug Form and deterministic Intake | intake |
| D | Version pinning, E2E reproduction, Draft PR | reproduction pilot |
| E | Diagnosis, remediation, Validation Gate | remediation allowlist |
| F | Review revisions, recovery hardening, backport task, General gate | general only after pilot evidence |

Each PR must pass its focused tests and the fixed repository validation tools
selected for its exact diff. Workflow and Agent-policy changes require the
explicit protected-path review already required by
`.github/workflows/README.md`.

## Global Constraints

1. Start implementation from an up-to-date `main` in a worktree under
   `.worktrees/`, using a `codex/` branch.
2. Before reading or changing a package, read its applicable `AGENTS.md` and
   `FLOW.md`. Create a concise `FLOW.md` for each new complex package.
3. Do not use root `go test ./...`. Use the explicit roots from `AGENTS.md`.
4. Unit tests must use fake clocks, fake providers, `httptest`, and temporary
   repositories. Docker, live GitHub, and real model-provider tests use the
   `integration` build tag or a manual pilot.
5. No test may require a real GitHub token, model API key, App private key, or
   checkpoint private key.
6. Do not add a third-party GitHub client or model SDK. Use `net/http`,
   `encoding/json`, existing repository dependencies, and narrow internal
   Adapters. This keeps the publisher surface auditable and avoids an automatic
   dependency-policy exception.
7. Never interpolate Issue, PR, Review, model, or Artifact text directly into a
   shell command or GitHub Actions expression. Read `$GITHUB_EVENT_PATH` and
   bounded files as data.
8. Models may propose a `ChangeSet`; only the trusted Publisher creates Git
   objects, comments, labels, branches, or PRs.
9. `cmd/wkissueagent`, all `internal/**/issueagent*` packages,
   `.github/issue-agent/**`, Issue Agent Workflows, Issue Agent scripts/tests,
   `.agents/**`, root `AGENTS.md`, and existing `AGENTS.md` files are protected
   from automated modification.
10. A new E2E scenario's required `AGENTS.md` is generated by the trusted
    Publisher from a fixed template. Model output cannot author instruction
    files. Applicable base-revision instructions are frozen into the
    `TaskEnvelope`; an edited `FLOW.md` cannot change policy during its own run.
11. Product configuration remains `wukongim.toml`; the Issue Agent does not add
    product config keys or environment variables.
12. The Agent App is not added to any default-branch bypass list.

### Step 2: Implement typed contracts

Use structs, not unbounded maps. Keep the signed checkpoint separate from its
comment envelope:

```text
CheckpointEnvelope
  schema
  key_id
  checkpoint
  signature

Checkpoint
  repository
  issue_number
  generation
  sequence
  predecessor
  state
  frozen_input
  versions
  lease
  reproduction
  work
  diagnosis
  validation
  budget
  model
  next_action
```

Define canonical signing bytes as strict JSON encoding of the typed
`Checkpoint` with:

- no maps;
- normalized timestamps;
- sorted unique slices;
- HTML escaping disabled;
- no trailing newline.

The envelope's signature is Ed25519 over those exact bytes. Private-key
handling is not part of this package.

`TaskEnvelope` and `AgentResult` carry schema version, immutable identity,
phase, resource bounds, and digests. `AgentResult` contains a typed
`ChangeSet`, not a shell script, patch command, commit, branch write, or PR
mutation.

Lock the failure classes to `needs_info`, `already_fixed`,
`product_assertion`, `test_harness`, `worker_infrastructure`, `provider`,
`unsafe_scope`, `state_conflict`, `budget_exhausted`, and `cancelled`.

### Step 2: Publish typed file changes through `createCommitOnBranch`

4. Require the resulting commit's GitHub signature verification to be valid.

Because the mutation is expected-head fenced, an external branch advance fails
instead of being overwritten.
