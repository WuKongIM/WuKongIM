# MQTT IM 接入实施计划

状态：实施中；codec、网关接口和 session/subscription/cursor/inflight/source_binding/will 六张表的存储基础及 Slot 命令、共享回放表的副本存储与备份已建立，MQTT 产品监听及完整持久运行时尚未接通。依据：[MQTT IM 接入设计](../../specs/mqtt-im-access.md)。

本计划交付 MQTT 5.0、QoS 0/1、精确主题、持久会话、跨节点接管、受权限约束的可靠恢复和 Will。阶段完成不等于整体完成；仅在线收发的版本不能作为本次需求交付。

## 开工合同

- 从实现任务的确切 revision 冻结适用 AGENTS/FLOW；按目录读取适用 FLOW，使用 `.worktrees/` 中的任务工作区。
- 先列失败场景并写验收，再实现对应行为。E2E 使用真实 `cmd/wukongim` 进程、标准 MQTT 客户端与 WK 客户端；遵守 [E2E 规则](../../../test/e2e/AGENTS.md)，不从场景测试导入业务或存储内部包。

- 首版无需为用户、设备、IM 成员表引入 MQTT 字段；不实现 Retain、通配符、共享订阅或 QoS 2。

## 1. 冻结协议与失败验收

确定应用 topic 的 ID 编码、CONNECT 身份参数、保留属性名、稳定 `client_msg_no`、输出消息身份、能力声明和错误映射。用明确的数据 fixtures 固定旧消息缺少扩展字段时的解释。

先覆盖：报文边界和非法长度、认证失败、越权 topic、重复 ClientID、QoS 不支持、Retain 禁用、会话丢失及客户端重新同步。客户端应用仍经业务后端管理群与查询历史。

标准兼容验证需覆盖 Keep Alive、Clean Start/Session Expiry、No Local、Subscription Identifier、Receive Maximum、Message Expiry、正常 UNSUBSCRIBE 的未完成交换以及 Will Delay。无需为此增加新的业务范围。

产物：协议矩阵、失败场景清单、可运行的单节点集群和三节点集群 E2E 骨架。新增场景目录各有 AGENTS 和主要测试文件；共享协议客户端辅助能力放在 `test/e2e/suite`。

## 2. 网关接缝与普通消息闭环

目标目录：`pkg/protocol/mqtt`、`pkg/gateway`、`internal/access/mqtt`、`internal/app`。

实现独立 MQTT packet/codec，仅解耦现有网关中确实依赖 WK CONNECT/SEND/下行 frame 的接口；复用有界认证及发送工作、传输和串行写入。业务入口映射到现有 message/user 窄端口，具体依赖在 app 装配。

验证 MQTT↔WK 单聊/群聊、权限顺序、发送幂等、非持久消息的在线语义、独立 QoS 处理，以及原 WK/JSON-RPC 接入无回归。增加必要的 app 装配验证。此阶段可以证明普通闭环，不能开放未实现的持久能力。

## 3. 数据合同、复制与会话状态

实现设计中的六张元数据表，分配全新的持久 ID，注册 Slot 命令和诊断视图。会话权威、订阅/cursor/inflight 原子更新、源端反向 binding、Will 任务生命周期分别保持明确归属。

实现可恢复的 SUBSCRIBE 建立和撤销操作；先建立源保护与生效区间，再返回成功。个人收件主题保存持久 UID 级接收资格，覆盖未来新建的单聊源。

接管需要新旧 owner 的明确隔离证明；无法隔离旧连接时不激活新连接。将迟到 ACK、关闭、计时和副作用绑定 session/owner generation。

验证并发接管、Slot leader 变化、断线重启、部分投影失败、SUBACK 前后崩溃，以及相同 PacketID 在不同会话代次中的隔离。

## 4. 可恢复消息源与共享内容

目标范围：发送合同、Channel Record/复制、`pkg/db/message`、源读取/保留接口、MQTT replay 适配。

- 为原始发布语义增加有界可选元数据，贯通复制编码和身份校验，不能靠回调重建。
- 实现独立源代次、保护起点和可靠转存水位；原有 named cursor 不能被直接复用为可靠证明。
- 建立 `mqtt_replay_message` 共享内容及范围计量索引，遵循先持久内容、后推进源水位、最后释放原数据的顺序。
- 普通历史逻辑隐藏与内部受保护源读取分开；回调仅用于唤醒。
- 跨 Slot 操作使用幂等键、阶段和条件进度推进，所有发送入口均产生可恢复责任。

故障验收：提交后回调前宕机、内容持久后水位前宕机、retention 与 leader 变化并发，以及用户离线后新联系人首次发送。核验源缺口不会被当作空页跳过。

## 5. 持久投递、配额与权限

为进入投递窗口的消息先持久写 inflight，再发送；PUBACK 后原子推进安全消费状态。共享积压范围、累计计量和回收证明均可恢复，不按消息年龄满 24 小时自动删除仍有效的责任。

实现每会话窗口、条数和字节上限、订阅/源数上限、全局存储及恢复预算、公平分页。容量候选值按设计进行压测后确定，指标维度保持低基数。

当前权限优先。明确撤权与投递的排序点；如果权限策略要求终止既有未完成交换，显式结束会话并要求应用同步，而不是报告 Session Present=1 后跳过旧责任。

验证发包/ACK 的崩溃窗口、取消订阅与撤权差异、退群重入、解散、会话过期、条数/字节超限、断线同步和全局容量背压。
