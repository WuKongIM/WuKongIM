# MQTT Access Mapping Flow

## Responsibility

This package maps wire-validated MQTT 5 packets to IM identities and immutable
publication content. Product listener/session orchestration is not yet wired.

## Boundaries

- `pkg/protocol/mqtt` owns packet syntax and wire limits.
- Authentication, current permissions, session ownership and Will scheduling
  belong to use cases; parsed credentials are not authenticated identities.
- Publication metadata imports no packet or gateway types.

## Main Flows

1. Parse canonical base64url application topics and CONNECT device credentials.
2. Extract the required client message number and reject reserved-property
   forgery before constructing owned publication content.
3. Map original QoS, publisher identity and ordered content properties to the
   bounded durable format. Separate Will Delay from forwarded properties.

## Invariants and Failure Semantics

- QoS 0 does not imply NoPersist. Retain, QoS 2, aliases and client-supplied
  subscription identifiers are rejected for publications.
- Namespace, ClientID and ingress time come from the accepted connection.
- Reserved output properties are regenerated by the server, not copied back
  from client attributes. Unreserved duplicate keys retain their order.
- Will client message numbers cannot substitute for server idempotency identity.
- Will setup reserves the 79-byte server identity before accepting its template;
  ordinary publications retain the full metadata bound.
- Errors contain fixed diagnostics without credential or content values.
